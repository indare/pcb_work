初号 PCB の立ち上げ作業ログ。切り分けの経緯を残す。**いま何が動いているか／次に何をするか**は STATUS を見る。

## 現在の結論（2026-08-14 時点の到達点）— **PCM1804 稼働。Y701 も復活**

（その後: アナログ FE 通電・LCD／タッチ・10 バンド UI まで到達。詳細は STATUS。）

**Y701 が SCKI を供給し、ADC は設計どおりマスタ・シングルレート・48kHz で動作している。**

| 信号 | 実測 | 理論値 |
|---|---|---|
| SCKI（Y701） | 12,288,337 Hz | 12,288,000 Hz |
| LRCK | **48,000.0 Hz** | 48,000 Hz |
| BCK | 3,072,018 Hz | 3,072,000 Hz |
| SCKI / LRCK | **256.000** | 256 |
| BCK / LRCK | **64.000** | 64 |
| DATA | 約 550 kHz で変化 | データ出力中 |

Y701 は死んでいなかった。VDD と OUT の飛ばし配線が繋がっていなかっただけ。

### ⚠ GP9 は駆動禁止

`GP9 → CN3F-1` の飛ばし配線は**測定プローブとして残置**しているが、
**Pico から出力してはいけない。** Y701 と R718(33Ω) を挟んで衝突し SCKI が化ける。
実際に衝突させたときは SCKI が壊れて BCK 5.26MHz / LRCK 83.7kHz
（SCKI/LRCK = 149.2 という無意味な比）になった。
**標準にない分周比が出たら、まず 2 つのドライバの衝突を疑うこと。**

### 原因は「番号をどちらの端から数えるか」の取り違え 2 件

長時間ハマった原因は 2 つが重なっていたこと。どちらも同種の間違い。

**1. Pico の物理ピン番号（SCKI が一度も届いていなかった）**

Pico は基板上で横向きに寝ている。**南の列が西から東へ 1〜20、北の列が東から西へ 21〜40。**
物理12番(GP9) は「南の列を USB 側から 12 個目」。
当初これを「左側の上から12個目」と説明したため、実際には北の列の左から12個目
＝物理29番(GP22) に配線されていた。

**2. JP1F の番号（スレーブモードになっていた）**

**JP1F の番号は左から 7,6,5,4,3,2,1。「JP1F」のシルクがある側の端が 7番(FMT0)、
反対の端が 1番(BYPAS)。** 左端を 1 と数えると設定が全て左右反転する。
意図した「3,4,7 をショート」は実際には「1,4,5 をショート」になり、
**5番 = S/_M がショート = H = スレーブモード**だった。

### 見落としていた決め手

**DATA が L に「能動駆動」されていた**こと。
チップが本当にリセット中なら出力ドライバは働かず DATA も高インピーダンスになる。
駆動しているのにクロックを出さない、は「リセット中」ではなく
「**スレーブモードで BCK/LRCK が入力になっている**」と読むべきだった。

### 2.36V の正体（誤診の訂正）

配線が別ピンだった時期に CN3F-1 が 2.36V を示したのを
「SCKI ノードから GND へ直流が流れている＝入力破壊」と読んだが**誤り**。
テスターの入力抵抗 10MΩ と高抵抗経路の分圧にすぎない。
中途半端な電圧は「負荷がある」ではなく「繋がっていない」のサインでありうる。

### 次にやること（当時）

1. PIO で I2S スレーブ受信 ← **済**
2. サンプル値の確認 → FFT → LCD ← **済**（タッチメニューまで）
3. アナログ入力側（OPA 電源・VCOM）の立ち上げ ← **済**（J703 ±15V）

**いまの次作業**は `MeasurementADC_STATUS.md`（次号ジャンパ解消 → 端子台／ケース）。

### いまの応急構成（残置）— **このまま維持で確定（2026-08-14）**

| 箇所 | 状態 |
|---|---|
| U710 1番（RESET） | **浮かせたまま**（出力 L 固定のため） |
| U710 CT–VDD | 100kΩ 残置（ピン1が浮いているので今は無害な置物） |
| U709 CT–VDD | 100kΩ 追加・残置。**外すな**（下記） |
| U709 1番 | パッドに戻済み（正常） |
| Y701 | 初号 FP 誤りのため空中配線。**発振確認済み**（部品2→右下GND、部品4→左上+3.3V） |
| **GP9 → CN3F-1** | 飛ばし配線。**入力専用の測定プローブ。駆動禁止** |
| **GP15 → `ADC_nRST`** | 飛ばし配線。Pico から RST を制御 |

飛ばし先の GPIO は Pico 側で電気的に確定させた。`ADC_nRST` は R719 の 10kΩ でプルアップ
されているので、候補ピンを一瞬 Low に駆動してから入力へ戻し、即座に H へ復帰するかを見れば
判別できる（未接続ピンは L のまま残る）。この方法で GP15 のみが反応した。

#### なぜ戻さないのか（蒸し返さないこと）

**U710 の 1番**: 戻せば再発する。リフトの根拠は「U709 の1番を浮かせてもネットは 0V のまま、
続けて U710 を浮かせた瞬間に 3.26V」という直接測定で、引いていたのは U710 だけ。
しかもこれはホットエアで載せ替えた**新品のほう**。失うのは +5V_A の監視だけで、
+3.3V の監視は U709 が生きており、両レールは同じ電源モジュールから同時に立ち上がる。
リセットは GP15 から任意にかけられるので実害は小さい。

なお **U710 が「出力段の故障」なのか「本当にアサートしている」のかは未確定**。
当時 CT が 2.86V（解除側）だったので前者と読んだが、これは我々が付けた 100kΩ で
5.12V から吊った結果であり、差分 2.26V ÷ 100kΩ = 22.6µA が CT に流れ込んでいる、
つまり内部放電が効いている（＝アサート中）とも読める。**100kΩ が診断を壊していた。**
確定させるならピン1を浮かせたまま CT の 100kΩ を外して CT を測る。
5V 近くまで上がれば出力段故障、0V のままならアサート中で MR（3番・北東、未接続）と
汚れが容疑者。MR は実測 4.69V で GND へ約 1.1MΩ のリークがあるが閾値は割っていない。

**U709 の 100kΩ**: これは応急処置ではなく**データシート規定の使い方**（CT を 40k〜200kΩ で
VDD に吊ると 300ms 固定遅延モード）。かつ load-bearing で、付ける前の U709 は CT が
0.00〜0.01V に張り付いて永久アサートだった。CT オープン運用は 220nA の微小電流なので
基板の汚れや寄生リークに勝てない。**今は U709 が唯一の監視 IC なので、外すと ADC が止まる。**

**GP9 → CN3F-1**: 12.288MHz にスタブがぶら下がる形なので信号品質としては褒められないが、
SCKI を直接見られる唯一の点。無いと「SCKI が来ていない」と「ADC が死んでいる」を区別できない
（正常時は BCK/LRCK の比 256・64 から逆算できるので不要、異常時の切り分けには有用）。
アナログ側の立ち上げが済むまでは残す。

**GP15 → `ADC_nRST`**: もう調査用ではなく機能の一部。U710 が外れている今、ソフトから
リセットをかける唯一の手段で `I2SReceiver.reset()` が使う。Low に駆動してから入力へ戻すだけで
High は駆動しないので、オープンドレインの監視 IC と R719 にきれいにワイヤ AND される。
次改版の方針「`ADC_nRST` を Pico からオープンドレインでワイヤ AND」そのものなので先取りになる。

## アナログ front-end 立ち上げ（2026-08-14）— **解決**

### 症状

I2S 受信と FFT が動いたあと、**両チャンネルとも約 1196Hz の倍音列が −15dBFS** で出ていた。
16 倍音まで揃い、時間波形は 0 / −2.0M / +2.3M の 3 値をカクカク行き来する非正弦波。

### まず取り込み側を潰した

デシメーションフィルタを通ったにしては角が立ちすぎていたので、I2S のビット位置を疑った。
**LRCK 遷移直後の 32BCK をそのまま取り込み、24bit 窓の位置を 9 通り総当たり**した結果、

- shift=7（I2S の 1BCK 遅れ）が他より 2 倍以上滑らかで最良
- 32bit 枠の**末尾 7 ビットが常にゼロ**

つまり「1BCK 遅れ + 24bit 有効」で寸分違わず取れている。取り込みは無罪。

### 原因: OPA の両電源が未接続で front-end 全体がクランプされていた

`AMP_V+_IN` / `AMP_V-_IN` は **J703** から入る **±15V**
（`+15_IN` → F1(1A) → U1 = MCW03-12D15 → L1/L2）。ここが未接続だった。

未通電の OPA1656 は出力が高インピーダンスにはならない。レールが 0V だと
**出力段も入力段も ESD 構造で 0V へクランプ**する。通電前の実測（ADC_GND 基準）は

| 点 | 実測 | 本来 |
|---|---|---|
| VIN±（CN1F/CN2F の両端） | 0.76V | VCOM と同電位 |
| VCOM（CN1F/CN2F の中央） | **0.92V** | **2.5V** |

VCOM は U702/U703 の + 入力 4 本にぶら下がっており、0.92V はほぼダイオード 1 個分。
**VCOM は PCM1804 の内部基準の出力**なので、これが引きずり降ろされていた＝
変換器の基準そのものが壊されていた。入力の同相ずれより、こちらのほうが重い。

### 結果

J703 に ±15V を入れたら**ノイズフロアが約 70dB 下がった**。

| | 通電前 | 通電後 |
|---|---|---|
| L ピーク | −15.3 dBFS | **−84.2 dBFS** |
| R ピーク | −25.2 dBFS | **−70.0 dBFS** |
| バンドフロア | −35〜−50 dBFS | **−115〜−126 dBFS** |

固定小数点 FFT の演算ノイズはピークから約 65dB 下（今回なら −135dBFS 相当）なので、
測れているのは ADC の実ノイズであって丸め誤差ではない。

### 混入スペクトルの実測（2026-09-03、`capture_raw.py` の無信号キャプチャ）

生サンプルを PC 側 float64 で FFT した。**10 バンド表示では見えなかった系列が出た。**

| 系列 | 実測（L） | 性質 |
|---|---|---|
| **750 Hz = `fs/64` の倍音列** | 750:−80.4 / 1500:−84.4 / 2250:−91.6 / **3000:−90.1** / 3750:−91.7 dBFS | **クロック同期**（BCK = 64×LRCK）。ドリフトしない |
| 1205.7 Hz（既知の自走源） | −77.8 dBFS。倍音 2411:−80.5 | 非同期。**上記の 1174.8 から約 31 Hz 動いている**。**⚠ USB グラウンドループ仮説あり**（下記） |
| DC | L −76.0 / R −71.8 dBFS | |
| 中央値の床（ビン当たり） | **L −123.9 / R −117.6 dBFS** | R が 6.3 dB 悪いのは既知の傾向と整合 |

> **⚠ 試験周波数に 1 kHz を使ってはいけない。**
> `750 × 4 = 3000 Hz` が **1 kHz 音の H3 と正確に衝突**し、そこに −90.1 dBFS が乗る
> （局所の床 −115.4 dBFS より **25 dB 上**）。H3 の測定が壊れる。

**試験周波数は 1320 Hz を使う**（H2=2640 / H3=3960 / H5=6600）。
無信号での実測が H2 −118.7 / H3 −116.6 / H5 −119.2 dBFS と床に近く、
**ドリフトする 1205.7 Hz 系のどの倍音からも 139 Hz 以上離れている**
（実績ドリフト 31 Hz に対し十分な余裕）。選定は 900〜2000 Hz を 5 Hz 刻みで走査して決めた。

**分解能を縛るのは雑音床ではなくこのスプリアス。** 中央値床 −123.9 dBFS に対し
H2/H3/H5 位置の実測は −117〜−119 dBFS で、**約 6 dB を妨害に食われている**。
スプリアスは離散トーンなので **N を増やしても平均化しても下がらない**
（下がるのはランダム雑音だけ。issue #33 で3回間違えた論点と同じ構造）。

### 1320Hz 通電測定の結果（2026-09-03、OPA2134PA / G8 最大出力）

**結論: この構成ではオペアンプの歪みは測れない。** 測定系自体は正常だった。

| 量 | 5回連続キャプチャの結果 |
|---|---|
| 基本波 | **−16.31〜−16.34 dBFS（0.03 dB 幅）**、f0 ドリフト **3 ppm** |
| ビン当たりの床 | −122.0〜−123.6 dBFS |
| H2 振幅 | −84.1〜−89.7 dBc（**1σ = 2.4 dB**） |
| H3 振幅 | −92.7〜−110.3 dBc（**1σ = 6.5 dB**） |

**基本波は極めて安定なのに高調波だけが数 dB 振れる。** 原因は相対位相で判明した。

#### 決め手: 相対位相がランダム＝それは信号の高調波ではない

`analyze_thd.py` の相対位相 `θh − h·θ1` は時間シフト不変（自己検証で 0.04° まで確認済み）。
**本物の高調波なら5回とも同じ値になる。**

| 次数 | 5回の相対位相 | 平均ベクトル長 R |
|---|---|---:|
| H2 | 104.4 / −89.2 / 15.3 / 113.1 / −117.6 | **0.059** |
| H3 | −100.5 / 115.3 / −88.5 / 130.0 / 120.6 | 0.364 |
| H5 | −148.6 / −86.2 / 106.1 / 92.9 / 84.0 | 0.351 |

`R ≈ 0` は一様ランダム。**H2/H3/H5 の位置にあるのは信号と無相関な混入**で、
オペアンプの歪みではない。振幅のばらつきもこれで説明が付く。

#### レベルが 21dB 以上足りない

`PCM1804` のフルスケールは **5 Vp-p 差動 = 1.77 Vrms**。`AdcBuffer` はゲイン1
（`README.md`「Rf=0Ω なのでゲインは 1」）なので減衰は無い。
**−16.3 dBFS は AdcBuffer 出力で約 0.27 Vrms**（前段の差動変換のゲイン次第でさらに小さい）。
一方 DUT のデータシート条件は **3〜3.5 Vrms**。

局所床（H2 位置 −110.6 / H3 −116.5 / H5 −121.3 dBFS）から逆算した必要レベル:

| 石 | THD+N | 必要な基本波 | 現状 −16.3 dBFS で |
|---|---:|---:|---|
| NJM5532 | −94.0 | −6.6 dBFS | 10dB 不足 |
| MUSES02 | −100.0 | −0.6 dBFS | 16dB 不足 |
| NJM4580 | −106.0 | +5.4 dBFS | **ADC FS 超え。不可** |
| OPA2134 | −122.0 | +21.4 dBFS | **不可** |
| OPA2140 | −126.0 | +25.4 dBFS | **不可** |

**G8 は最大出力。これ以上レベルを上げられないので、この構成では梯子のどの段も測れない。**

#### ⚠⚠ 回路図と実基板が違う（2026-09-03、発注記録で確定）

**`AmpModule` の Rf と Rg は実装では両方 10.0 kΩ。** 回路図の
`R405/R408 = 47kΩ`（Rf）は**実装と一致しない**（`R403/R407 = 10kΩ` の方は合っている）。

    PART: RG32P10.0KBCT-ND
    MFG : SUSUMU / RG3216P-1002-B-T1
    DESC: RES SMD 10K OHM 0.1% 1/4W 1206

**部品番号の `-1002-` がそのまま 10.0k を意味する**ので、マーキング読みより確実。
（`2001`=2.00k と `1002`=10.0k は 180° 回転で入れ替わる典型的な誤読ペアで、
 一度 2.00k と誤認した。**発注記録が正。**）

トポロジはネットリストで確認済みで**非反転**（信号は `C405/C406`・`C408` 経由で + 入力へ、
`R401/R410` 10k は + 入力の GND バイアス、`R403/R407` が Rg、`R405/R408` が Rf）。

| | Rf | Rg | ゲイン | ノイズゲイン | Rf∥Rg | 帰還ゼロ(Cs=5pF) |
|---|---|---|---|---|---|---|
| 回路図 | 47 kΩ | 10 kΩ | 5.7 | 5.7 | 8.24 kΩ | 3.9 MHz |
| **実装** | **10.0 kΩ** | **10.0 kΩ** | **2.0** | **2.0** | **5.0 kΩ** | **6.4 MHz** |

**ゲイン 2.0 は AudioV2 の `AmpChannel`（20k/20k）と同じ**なのは好都合。

> **⚠ ただし `REFINE` §4.2 の発振判定は「実装の方が 1.73 倍きびしい」方向へずれる。**
> ゼロは 3.9→6.4 MHz と 1.65 倍上がるが、**ノイズゲインが 5.7→2.0 に下がるぶん
> 交差周波数が 2.85 倍上がる**ので、差し引き悪化する。
>
> | 石 | GBW | 交差(÷2) | ゼロ 6.4M との比 | 判定 | REFINE の判定 |
> |---|---:|---:|---:|---|---|
> | OPA2134 | 8 M | 4.0 M | 1.59× | **OK** | OK |
> | NE5532 | 11 M | 5.5 M | 1.16× | ぎりぎり | OK |
> | OPA2140 | 11 M | 5.5 M | 1.16× | ぎりぎり | OK |
> | MUSES01/02/03 | 12 M | 6.0 M | 1.06× | ぎりぎり | OK |
> | NJM4580 | 15 M | 7.5 M | **0.85×** | **NG** | OK |
> | OPA1652 | 18 M | 9.0 M | 0.71× | **NG** | ぎりぎりOK |
> | OPA2604 | 20 M | 10.0 M | 0.64× | **NG** | ぎりぎりOK |
> | OPA1612 / LME49860 / OPA1656 / OPA828 / LT1364 | 40〜70 M | 20〜35 M | 0.18〜0.32× | **NG** | 要注意 |
>
> **安全に使えるのは `OPA2134` / `NE5532`(`NJM5532`) / `OPA2140` / `MUSES01・02・03` だけ。**
> `NJM4580` / `OPA1652` / `OPA2604` は `REFINE` では OK 側だったが、実装値では NG 側に入る。
>
> ただし `Cs = 5 pF` は `REFINE` の仮定値で、実際の DIP ソケット＋1206 の浮遊容量は
> 未確認。**これは一次スクリーニングであって判定ではない**（比が 1.0 前後の石は実測で確認）。
> `REFINE` §4.3 のデカップリング不足も別問題として残る。

**教訓: 実装値を回路図から推定しない。発注記録か実測が正。**
この件では ①座標から「10k/10k で G=2」→ ②回路図値から「47k/10k で G=−4.7」→
③マーキング誤読から「2k/2k で OPA1612 も使える」と**3回間違え**、
発注記録でようやく確定した。**推定を重ねず、一次資料に当たること。**

> **⚠ 以下の測定はすべて仮配線・ケーシング未了の状態で行った。**
> ベースラインや混入の**絶対値は仮組みの性質**であって設計の性能ではない。
> **原因は配線とケーシングと分かっているので、この数字で部品を選ばないこと。**
> 正規の配線・筐体ができてから同じ手順で取り直す。
> **手法（複素ベクトル・抜き差し対照・位相）と罠の記録は配線が変わっても有効。**

### 分解能の実測（2026-09-03、OPA2134PA / 専用試験音 / 8回連続）

**信号源を YouTube から専用 WAV（`make_tone.py`）へ替えたら、本物の高調波が測れた。**
条件: 1320Hz、ADC-L −3.4 dBFS、連続再生、何も触らず8回。

| 量 | 平均 | ばらつき(1σ) | 位相の 1σ | 判定 |
|---|---:|---:|---:|---|
| **H3** | **−76.17 dBc** | **0.115 dB** | **0.63°** | **位相ロック＝本物** |
| H5 | −81.03 dBc | 0.403 dB | 0.88° | 位相ロック＝本物 |
| H2 | −96.5 dBc | 1.77 dB | 12.9° | 床に近く不安定 |

**YouTube のときは H2 の相対位相が ±180° 全域に散っていた（平均ベクトル長 0.059）。
今回は H3 が8回とも −174.8° ± 0.63° に収まる。** 位相を測る設計にしておいたのが効いた。

#### 「どこまでの THD 差を比較できるか」への答え

ベースライン H3 = −76.17 dBc、再現性 1σ = 0.115 dB。
DUT の寄与 `x` がベースライン `B` に複素加算されるときの振幅変化は
`20log10(1 + 10^((x−B)/20))`。

| 検出基準 | 必要な変化 | DUT の H3 |
|---|---:|---:|
| 1σ | 0.115 dB | −113.7 dBc |
| 2σ | 0.230 dB | −107.6 dBc |
| **3σ** | **0.345 dB** | **−104.0 dBc** |

**→ この測定系は DUT の H3 を約 −104 dBc まで分解できる。**

| 石 | THD+N(DS) | 総量の変化 | 検出 |
|---|---:|---:|---|
| NJM5532 | −94.0 | 1.049 dB (9.1σ) | **見える** |
| MUSES02 | −100.0 | 0.542 dB (4.7σ) | **見える** |
| OPA2134 | −122.0 | 0.044 dB (0.4σ) | 床以下 |
| OPA2140 | −126.0 | 0.028 dB (0.2σ) | 床以下 |
| MUSE03 | −130.5 | 0.017 dB (0.1σ) | 床以下 |

#### ⚠ ベースライン −76 dBc は DUT の歪みではない

`OPA2134` の DS 値は −122 dB で、実測の −76.17 dBc より **46 dB 良い**。
つまりこの −76 dBc は **DUT 以外（G8 の出力段、`AdcBuffer`、ADC のいずれか）**が作っている。
**それを下げれば分解能はそのぶん伸びる。** いまの限界は測定系であって DUT ではない。

#### 未解明: `f0` 推定が 5.4 Hz 振れる

8回で 1317.3〜1322.7 Hz（4106 ppm）と出る。水晶誤差にしては大きすぎる。
ただし**振幅は 0.02 dB、H3 は 0.115 dB で安定**しており、もし `f0` が本当に 5.4 Hz
動いていれば `3f0` は 16 Hz（5.5 ビン）動いて H3 が大きく振れるはずなので、
**`f0` 自体は安定していて推定器がノイズを拾っている**と見るのが自然。
基本波が −3.4 dBFS と強く、近接側波帯が放物線補間を引っ張っている可能性。
測定結果には影響していないが、原因は未確認。

### 石の差し替えを実際に検出（2026-09-03、OPA2134PA vs NJM5532DD）

**振幅だけでは見落とす。複素ベクトルで扱うと出る。**

#### 分解能の最終値

| 手法 | 3σ 検出限界 |

#### 差ベクトル −104 dBc の解釈

データシート上は `NJM5532` −94 / `OPA2134` −122 なので、差は `NJM5532` が支配して
−94 dBc になるはず。実測は −104 dBc で 10 dB 小さい。ただし
**`NJM5532` の −94 dBc は TI DS に規定が無い通説値**なので、
この動作点での実値がもっと良い可能性が高い（JRC DS には THD vs Vout グラフがある）。
部分的な相殺の可能性も残る。**「どちらが良いか」の判定にはまだ使えない。**

別途決める必要がある**。それには DUT を通さない経路（G8 → AdcBuffer 直結など）の

### 【決着】USB グラウンドループ仮説は「抜けば良くなる」形では否定（2026-09-03）

**実測した。USB を抜くと逆に悪くなる。**

`capture_hold.py` で USB を抜いたまま捕まえて、挿してから読み出した（同ファイルの docstring）。

| | 基本波 | 床 | 自走源 | H3 |
|---|---:|---:|---|---:|
| **USB 接続** | −3.41 dBFS | **−117.7 dBFS** | 1204.1 Hz / −73.6 dBc | −76.6 dBc |
| **USB 抜き** | −4.74 dBFS | **−94.8 dBFS** | 1262.7 Hz / −38.7 dBc | −76.2 dBc |

- 基本波は 1.3 dB 差なのに **床が 23 dB 悪化**、**スパーは消えるどころか 35 dB 増**
- **H3 は 3 本とも −76 dBc で一致**。歪み測定自体は壊れておらず、**変わったのは雑音側だけ**

**読み方:** USB ケーブルが**グランドの基準**を与えていた。音声接続はシングルエンドで
`A_GND` 基準なので、USB を抜くと装置と G8 のグランドを結ぶのが**音声ケーブルの
細いグランド線だけ**になり、同相成分が差動として現れる。
つまり主因は「ループを流れる電流」ではなく **「基準が弱いこと」**の可能性が高い。

**結論:**

- **USB は挿したまま使う。** `ADUM3160`（¥1,951）を買う根拠は無い。むしろ逆効果の可能性
- 有望なのは**シャーシアース1点**。PC に頼らず基準が立ち、ループも増やさず、部品代ほぼゼロ。
  **詰めるのは筐体設計（C1）の段階で**
- `ISO7741`（¥448）で絶縁を本物にする価値は残るが、**分解能のためではない**（B5 で判断）

### スパーは律速ではない（2026-09-03）

「この妨害はどれだけ悪さをするか」を数字で置く。

```
−76 dBc    いまのベースライン H3（仮配線由来）        ← 実際に効いているのはこれ
−106 dBc   抜き差し再現性（ソケットの機械的ばらつき）  ← 実用上の分解能
−111 dBc   測定雑音（スパー込み、8回複素平均）
−117 dBc   スパーを消せた場合の測定雑音              ← ここを直しても上3つは動かない
```

- **絶対値には効かない。** H3 −76.6 dBc は床（−117.7 dBFS）より **38 dB 上**
- **差の検出限界を約 6 dB 押し上げている**（中央値床 −123.9 に対し H2/H3/H5 位置は −117〜−119）
- **しかし実用の律速は抜き差しの −106 dBc。** スパーを消しても実用分解能は変わらない
- 実害として残るのは**試験周波数を縛ること**（1 kHz が使えず 1320 Hz）

**優先順位は §1 の順序どおり: 配線とケーシング → ベースライン取り直し → 素子の検証。**

### ⚠ 1205〜1212 Hz 自走源の有力仮説: USB グラウンドループ（2026-09-03）

**測定時、G8 と計測用 Pico は同じ PC の USB に繋がっている。**
つまり **PC → G8 → アナログ経路 → ADC → Pico → PC** というループが閉じている。

この混入の性質（**非同期・ゆっくりドリフト・自走**、1174.8 → 1205.7 → 1212.4 Hz と
セッション中も動く）は、PC 側の電源やクロックに由来すると考えると自然に説明できる。

**検証方法（どれも簡単）:**

1. **USB アイソレータ**を計測用 Pico に入れて混入が変わるか見る
2. G8 と Pico を**別の PC / 別のハブ**に分ける
3. Pico を電池駆動にして USB を切る（`capture_raw.py` は使えないので LCD スペアナで見る）

**これが当たりなら、基板レイアウトをどう工夫しても消えない種類の混入。**
配線・ケーシングの作業に入る前に切り分ける価値がある。

### 残っている混入（未解決・実用上は許容範囲）

**1174.8Hz の倍音列。L −84.4dBFS / R −70.0dBFS。**

- 両ch で基本波が 0.1Hz まで一致 → 独立した拾いではなく**共通源**（電源か VCOM 経由）
- 測定ごとに 1172.2 → 1174.8Hz と動く → こちらのクロックに同期していない**自走のアナログ源**
- 倍音の減り方が 4 倍音まで 1/n、以降急落 → **帯域制限された鋸歯状波**。
  スイッチング電源のインダクタ電流リプルの形。ただし 1.17kHz はスイッチング周波数としては低い
- **R が L より全倍音で一貫して 14dB 悪い。** R は基板北側（R713/R714 が y=142〜147、CN2F も北）で、
  ±15V が入る J703（y=114.75）に近い。位置関係とは整合する

### 測定点（実データで確認済み）

**J703**（北を上にして西→東）: **3番 AMP_V+ (x=380.05) / 2番 GND (385.13) / 1番 AMP_V− (390.21)**。
**ADC モジュールから遠いほうが +、近いほうが −。**

**ADC モジュール上のヘッダが一番測りやすい。** シルクで確認済み。

| コネクタ | 位置 | 北のピン | 中央 | 南のピン |
|---|---|---|---|---|
| CN2F | 北側 | VINR− | **VCOMR** | VINR+ |
| CN1F | 南側 | VINL− | **VCOML** | VINL+ |

親基板側は 47Ω の Takman が北から R713(VINR−) / R714(VINR+) / R715(VINL−) / R716(VINL+) の順に
東西に寝ており、**4 本とも 1番パッド＝東端（ADC 側）**。
VCOM のデカップは **C719(VCOMR) は北のパッド、C720(VCOML) は南のパッド**が VCOM 側で向きが逆。

## SCKI（MCLK）系の切り分け

### 回路上の経路と配線先

```
Y701 pin3 (OUT) ── Net-(Y701-OUT) ── R718 pin1
R718 (33Ω) 
R718 pin2 ── ADC_MCLK ── A701 pin7 (SCKI) = モジュール CN3F-1
```

- **R718 = 33Ω**（MCLK ダンピング抵抗）。Y701 と ADC の間に入っている
- `ADC_MCLK` に乗っているのは **R718 pin2 と A701 pin7 だけ**。Pico からは未配線
- Y701 は空中配線なので OUT リードを物理的に浮かせやすい

### A702（Pico2）の空き GPIO

| ピン | GPIO | 備考 |
|---|---|---|
| 12 | **GP9** | GP0/1/2 と同じ左側で最短。第一候補 |
| 19–22 | GP14–17 | |
| 24–27 | GP18–21 | |
| 29 | GP22 | |
| 31/32/34 | GP26/27/28 | ADC 兼用 |

使用済み: GP0=DATA / GP1=BCK / GP2=LRCK / GP3–7=LCD / GP8=LCD_EN / GP10–13=タッチ。

### STEP 1: Y701 の生死判定（非破壊・まずこれ）

Y701 も R718 も外さず、**聞くだけ**。テスターの平均電圧では振幅を保証できないので、エッジを数える。

- 測定点: **CN3F-1（= A701 pin7、R718 の ADC 側）**。ADC が実際に受けている点なので、R718 のはんだ付けまで込みで検証できる
- 接続: CN3F-1 → **GP9**。GND 共通を確認すること
- 判定: 12.288MHz が数えられれば Y701 は生きている → STEP 2 は不要で、疑いはモジュール側へ移る

> **注意**: カウントは必ず **PIO** で行う。Python の IRQ ハンドラでは 12.288MHz は取りこぼす。
> 既存の GP1/GP2 エッジカウントを流用する場合、PIO の `wait` ループは 2 命令＝ sysclk/2 まで追えるので 12.288MHz は余裕。

### STEP 2: Pico で SCKI を代用（STEP 1 で死んでいた場合）

1. **Y701 の OUT リードを浮かせる**（空中配線なので容易。両方が駆動すると争う）
2. **GP9 → R718 pin1**（Y701 側）に注入する。33Ω のダンピングが飛ばし配線にも効くので、CN3F-1 に直接入れるより素性が良い
3. GND は共通のまま、リターンは最短で

正確な 12.288MHz でなくてよい。マスタ 256fs なので fs = SCKI/256 になるだけ。

```python
from machine import Pin
import rp2

@rp2.asm_pio(set_init=rp2.PIO.OUT_LOW)
def clk():
    set(pins, 1)
    set(pins, 0)

# 2命令/周期なので出力は freq/2。24.576MHz 指定で 12.288MHz が出る
sm = rp2.StateMachine(0, clk, freq=24_576_000, set_base=Pin(9))
sm.active(1)
```

### ⚠ 順序制約（これを外すと誤判定する）

PCM1804 のリセット回路は **SCKI をクロック源にしている**。データシートに「VDD > 2V、VCC > 4V、RST = High より前に最低3クロックが必要」と明記されている。

**クロックを走らせてから RST を入れ直すこと。** 逆順だと SCKI が正常でもリセット状態から抜けられず、BCK/LRCK は 0V のまま。「代用クロックを入れたのに出ない＝モジュール不良」という誤判定になる。

1. PIO を起動して SCKI を出す
2. その状態で **CN6F を一瞬短絡**して RST を L→H
3. BCK/LRCK を確認

電源投入からやり直せるならそのほうが確実。

### 判定

| 結果 | 意味 |
|---|---|
| CN3F 2/3 または GP1/GP2 にクロック | ADC は生きている → Y701／振幅／配線側 |
| 依然 0Hz | モジュール／PCM1804 側 → 載せ替え優先 |

## ジャンパ設定の根拠（確定済み・蒸し返さないこと）

出典: 共立キット説明書 `https://www.kyohritsu.com/eclib/DIGIT/KIT/adc1804f.pdf` および TI PCM1804 データシート。

- **ショートピンを差すと H(1)、開放にすると L(0)**（説明書に本文と巻末の2箇所で明記）
- JP1F ピン割当: **1=BYPAS / 2=OSR2 / 3=OSR1 / 4=OSR0 / 5=S/_M / 6=FMT1 / 7=FMT0**
- S/_M 開放 = L = **マスタモード**（説明書・TI Table 4 とも一致）
- TI Table 1（マスタモード）: **OSR2=L / OSR1=H / OSR0=H → Single rate・256fS**。12.288MHz ÷ 256 = 48kHz で設計どおり
- 実機は開放状態で背面はんだの目視と回路側の導通検査を実施済み。**製造不良による短絡はなし**

補足として、仮にジャンパに不具合があっても今の症状を説明できるのは S/_M だけである。OSR1/OSR0 が H のはずが L に転んでいればサンプリング周波数が変わるだけ、FMT0 が転べばフォーマットが変わるだけで、いずれもクロックは出る。

> 「開放=L/ショート=H という理解で6項目とも仕様に一致した」という論法は**根拠にならない**。同じ規則で設定したものを同じ規則で読み返しているだけで、規則が逆なら6項目とも逆に転ぶ。上記は説明書という独立した出典による確定。

## TPS3808 / PCM1804 メモ

- CT オープンは 220nA 充電。リークに弱い → **100kΩ で VDD へ**が実機でも有効
- CT 電圧: ほぼ 0V = アサート中 / 2–3V = 解除済み
- PCM1804: SCKI の High は 2V 以上（VIH = 2V、TTL 互換）。テスター平均 1.4V は振幅保証にならない
- **SCKI はリセット回路のクロック源**。VDD > 2V / VCC > 4V / RST = High より前に最低3クロックが必要。SCKI が来ていなければリセット状態から抜けられず、デジタル出力はゼロに固定される。**現象「BCK/LRCK = 0V」はこれで説明がつく**
- RST（pin19）には内部 51kΩ プルダウンがある。R719 の 10kΩ と分圧して 2.8–3.0V。実測 3.01V は正常（VIH 2V に対し余裕あり）
- OSR2/OSR1/OSR0 を変更するときは RST = Low が必要（説明書にも「ジャンパ変更後はリセットをかけること」とある）
- RST を 65536/fS より長く Low に保つとパワーダウンに入る。その間もクロック供給が必要

## 次改版への反映事項

- ASFL FP は `ef9d6d4` の修正版を使う（初号実基板は旧 FP）
- **LCD SCK/MOSI をハード SPI 正規ピンへ**（初号は GP18/19 へ飛ばし。基板ヘッダの GP3/4 は SPI ペアではない）
- MADCTL `0xE8` とタッチ座標（`x=479-ty`, `y=tx`）は実機確認済み。次号でも向きを変えないこと
- **監視 IC は大きいフットプリント**を検討（SOT-23-6 のリワークが切り分けを阻害）
- U709/U710 の CT を最初から 100kΩ で VDD へ
- SENSE に 1–10nF
- **`ADC_nRST` を Pico からオープンドレインでワイヤAND**（監視 IC は残す。置換は非推奨）
- Y701 の銅箔配線を正す／MCLK テストポイント
- U710 相当の部品は初号で出力不良があったので、実装・調達に注意
- JP1F・Pico 物理ピンの数え方をシルク／ドキュメントで明示（初号で長期ハマり）
