## 0. 判定の要約と統合した推奨

### 0.1 主張ごとの判定

| # | [A1P] の主張 | 判定 | 理由（1 行） |
|---|---|---|---|
| 1 | Pico の今の使い方と空き（デジタル 5・ADC1/2、RUN は `3V3` 直結）、ヘッダの GPIO 26 本 | **支持** | [SF pin A1602] とシンボルのピン名（GP0〜22・GP26〜28）で一致 |
| 2 | M の Pico 直の残りはタッチありで 0（MIRROR で 1）／なしで 4、ADC 3/3、制御 MCP 15/16 | **支持** | 5 −（`RAIL_OK`・RESET・検知 3）−（I2C1 の 2）＝ 0。GP14＝I2C1 SDA・GP3＝I2C1 SCL〔RP2350 DS p19 Table 3〕 |

| 4 | P1 の空き: Pico-A 0〜3／4〜7、Pico-B 4〜8 | **修正** | Pico-A は ADC の 3 本（`DEST_ADC`・LM4040 が抜ける）もデジタルに使えるので **3〜6／7〜10**。Pico-B は DIRECT 2 を固定すると 4〜6（ミュート 2 あり）／6（なし） |

| 10 | 利点②: 制御に I²C が無いので書きかけ OLAT の故障形が無い | **支持（差は小さい）** | 本当の差は「I²C には誤り検出が無く、化けたバイトがそのまま出力になる」こと。M は I²C の分割（A1 で必須）と書いたあとの読み返しでほぼ閉じる。P1 の UART は CRC と冪等な要求で「正しい手順の別の要求」にしか化けない（§3.2） |
| 11 | 利点③: UI 側のハング・書き込み・デバッガ停止がスタックに届かない | **支持（安全ではなく可用性と故障の封じ込め）** | M では UI のハングは WDT で安全側（無音）に倒れる。P1 の本当の強みは、UI のコードの誤り（間違った番地・レジスタへの書き込み）が物理的にスタックの線へ届かないこと。Pico-B のハングは Pico-B の WDT＋Pico-A の心拍（RUN の FET は「任意」でなく推奨に）（§3.3） |
| 12 | 音: Pico-B を親のデジタル区画に置けば同等、クロックの塊が 1 個増える | **修正（補足）** | 増えるのはクロックだけではない: RP2350 は**コアの電源に on-chip のスイッチング電源**を持つ〔p14〕。基板の 3V3 もスイッチングの見込み〔推論〕。静的な線を常時動く MCU の pad が駆動する点も M と違う。未測で「小さい」は推論のまま（§4.4） |
| 13 | 2 本の USB を同じ PC に挿しても「隣り合う 2 個の間なのでループは小さい」 | **棄却（理由）** | 閉路は PC → ケーブル A → Pico-A → `D_GND` → Pico-B → ケーブル B → PC で、面積は 2 本のケーブルの取り回しで決まる。聴く・測る間は USB を 1 本にする運用が要る（§4.3） |
| 14 | 規則①②③は「そのまま Pico-B に置く」 | **修正（見落とし）** | 規則①には PT2314E の初期化が入り、PT2314E は Pico-A のバス。±15 V の復帰（[DER] B8 #7）を知るのも Pico-B だけ。**2 石をまたぐ依存**を取り決め（電源の世代番号）か Pico-A 側の検知で埋める必要がある（§4.1） |
| 15 | 部品・面積・費用は M、ファーム・デバッグは M | **支持（面積は弱い）** | 価格・Pico 2 の寸法はリポジトリに無い（確かめられず）。親のラフ外形は (5,5)–(455,455) mm（NOW）で、面積が決め手になる見込みは低い（§4.5） |
| 16 | P2 は P1 に劣り、P3 は本数が入らず棄却 | **支持** | P3 はミュート 0 本（B7＝(B)）でも 9 または 13 本に対し 17 本要る |
| 17 | 推奨 P1、「安全は M と同等以上」 | **修正** | 根拠から言えるのは「**安全は同等**」。「以上」の 3 理由は、①は M の必須の分割で小さくなり、②は M も 1 ゲートで得て P1 は USB で失い、③は安全ではなく可用性。「僅差」は妥当だが、符号はユーザーの重み（ファーム 2 本を受け入れるか）で決まる（§5） |
| 18 | M が勝つ条件（ファーム 2 本・Pico-B の USB の置き場・面積・Pico 2 の事実） | **修正（足りない）** | 足すべき条件: UI の故障の封じ込めを重く見ない／親に常時動くスイッチング源を増やしたくない（測るまで）／聴く間も Pico-B の USB を挿したままにする使い方。面積は外してよい（§5.3） |

### 0.2 統合した推奨 — **条件つき**（安全は同等。決め手はユーザーの重み）

- **安全の差は無い**。どちらも「駆動する石がリセットされたら出力を放し、外付けプルダウンで 0」という同じ形で、娘の側の守り（§5-8 の排他・B1/B2・EN ≤ IN）も同じ。両案に共通の穴（ハング・デバッガ停止・起動前にパルスが残る窓、ハードの最大パルス幅が無い）も同じ
- **P1 を選ぶ理由は可用性と故障の封じ込め**（UI・USB・FFT・LCD のコードの誤り・ハング・書き込み・デバッグがスタックの線に物理的に届かない。Pico-B を小さく変えないファームにできる）。代わりにファーム 2 本・取り決め・2 石をまたぐ依存・新しい電気の経路を持ち込む
- **M を選ぶ理由は簡単さ**（ファーム 1 本、親に常時動く源を増やさない、E9 の pad が 2〜3 本）。代わりに UI の不具合は WDT で無音に倒れ、UI のコードが制御 MCP を書けてしまう
- **既定を 1 つ置くなら P1**。理由は安全ではなく、M では UI の誤った I²C 書き込みがスタックの線を動かせる（同じ実行環境・同じドライバ）経路を、P1 は配線で断てること。**ただし下の P1 の修正を入れない P1 は、M に無い穴（Pico-B の 3V3 への逆給電、2 本の USB の閉路、PT2314E の再初期化の取りこぼし、E9 の線が 13〜17 本）を持ち込む**
- ユーザーが「ファームを 2 本持ちたくない」なら M。[A1P] の分かれ目の置き方は正しい

**P1 を採るなら必須（[A1P] に無いか弱いもの）**
1. UART の各線のプルアップは**送り側の 3V3** に置く（受け側に置くと、主電源 OFF・Pico-A だけ USB のとき Pico-A の TX から死んだ Pico-B の 3V3 へ流れ込む）。§3.1
2. Pico-B が駆動するスタックの線（13〜17 本）のプルダウンは**すべて ≤ 8.2 kΩ**（石が A2 のとき。A3 以降なら不要だが安い）。出力を High のまま入力に戻す書き方をファームで禁止。§2.3
3. **電源の世代番号**（`PD_12V_SW` の立ち上がり・±15 V の復帰のたびに増やす）を Pico-B の心拍に入れ、Pico-A は世代が変わったら 50 ms 待って PT2314E を全レジスタ書き直す。または Pico-A も `VCC_TONE` か検知線を直接読む。§4.1
4. 聴く・測る間は **USB は Pico-A の 1 本だけ**。Pico-B の USB は書き込み・デバッグのときだけ（その間の音・測定は比較に使わない）。§4.3
5. Pico-A から Pico-B の RUN を落とす FET は**推奨**（Pico-B の WDT を有効にする前のハングの後ろ盾）。デバッグ中に撃たない切り替えを付ける。**今の図の RUN の `3V3` 直結を Pico-B に写さない**（FET が 3V3 を短絡する）。§3.3・§4.6
6. コイルの 20 ms は **PIO でハードに作る**（CPU のハング・デバッガ停止・Ctrl-C でもパルスが終わる）。P1 だけが取れる手当て。§2.4

**M を採るなら足すもの（[DER] A1 に無いもの）**
1. 制御 MCP の RESET（と `RAIL_OK`）を「Pico の GPIO ∧ 電源検知あり」の 1 ゲート（Pico の 3V3 で動く 2 入力 AND、入力にプルダウン）で作る → 規則②が P1 と同じく配線で守られ、Pico に USB を挿しても崩れない。§3.1
2. 制御 MCP は**専用のバス**（I2C1）に 1 個だけ置き、UI の MCP は PT2314E と同じ元のバスに残す（[DER] A1 は UI と制御を同じ新しいバスへ移す案。UI の読み書きと制御の書き込みが同じバスを取り合う）。代わりに UI の MCP は ±15 V が無い間は読めない（[DER] §1.10 を UI だけで受ける）。書いたら読み返す。§3.2・§3.3
3. IOCON.MIRROR で `ENC_INTB` を空ける（タッチありでも Pico 直に 1 本の余り）。§1.3
4. 3V3 の浅い瞬断に備え、IODIR・OLAT を定期的に読み返して食い違えば RESET から初期化し直す（MCP の POR は 0 V 起点しか保証されない）。§2.2

**B7 ＝ (B)（ミュートを切替に使わない）で結論は変わらない**。ミュートの 2 本は M では元から MCP 側（Pico 直の本数に効かない）、P1 では Pico-B の余りの中。ミュート 0／1／2 本のどれでも両案とも入る（§1.4）。

## 1. ピン数の算術

### 1.1 図の事実（支持）

- Pico（`A1602`、シンボル `MCU_Module:RaspberryPi_Pico` の Pico2）のピン名は 1＝GPIO0 … 29＝GPIO22、31/32/34＝GPIO26_ADC0/GPIO27_ADC1/GPIO28_ADC2、30＝RUN、33＝AGND、35＝ADC_VREF、36＝3V3、37＝3V3_EN、39＝VSYS、40＝VBUS（`MeasureControl.kicad_sch` の lib_symbols から抜いた）。ヘッダの GPIO は 26 本（GP0〜22 の 23 本＋GP26〜28 の 3 本）— [A1P] §1 **支持**
- 今の使用: I²S 3（GP0〜2）、LCD 6（GP5〜8・GP18/19）、タッチ 4（GP10〜13）、`ADC_nMR` 1（GP15）、`ENC_INTA/B` 2（GP16/17）、I²C 2（GP20/21）＝ 18 本。空きは GP3・GP4・GP9・GP14・GP22 の 5 本、ADC0＝`DEST_ADC`、ADC1・ADC2 は未接続、RUN（30）は `3V3` [SF pin A1602] — **支持**
- UI の MCP（`U1610`）は GPB3〜7（4〜8 番）が空き、GPB1/2 は DEST の LED、RESET（18 番）は `3V3` 直結 [SF pin U1610]。DEST の LED を外せば（[DER] B10）空きは 7 本。**安全に関わらない線**の逃げ場として両案に効く（[制] §1.5 のとおり制御線は混ぜない）

### 1.3 数え直し〔計算〕

**M（Pico 1 個＋制御 MCP）**

| | タッチあり | タッチなし |
|---|---:|---:|
| Pico のデジタルの空き（今） | 5 | 9 |
| −（`RAIL_OK`・MCP の RESET・検知） | 3 | 3 |
| −（I2C1: GP14＝SDA・GP3＝SCL、または GP22＝SDA。I2C1 の SCL は空きの中では GP3 だけ〔p19 Table 3〕） | 2 | 2 |
| **残り** | **0** | **4** |
| ＋ MIRROR（`ENC_INTB` を空ける） | 1 | 5 |
| ADC | 3/3（余り 0） | 3/3 |
| 制御 MCP: 出力 10＋DIRECT 2＋ミュート m＋入力 `PG_N` 1 | 13＋m /16 | 同 |

- [A1P] の M の数えは**支持**
- [A1P] が挙げていない逃げ道: `RAIL_OK` を制御 MCP の 16 本目に移す。MCP の RESET を Pico から取るので Pico のリセットで 0 に戻る向きは変わらず、[DER] B8 #10 が反応時間の目標を 10 ms 級に下げたので I²C 1 回（0.29 ms、[DEC] §5-2 却下案 (b)）でも足りる。ただし §5-3 の「Pico の GPIO から直接」（いったんの決め）を動かすのでユーザー判断が要る。**本数の上で M が詰まるのはタッチありの Pico 直だけで、それも 1〜2 本は逃がせる**

**P1**

| | Pico-A タッチあり | Pico-A タッチなし | Pico-B |
|---|---:|---:|---:|
| デジタルに使える本数 | 5＋**3**（ADC の 3 本。`DEST_ADC` と LM4040 が Pico-A から抜ける） | 9＋3 | 26 − ADC 3 ＝ 23 |
| − UART | 2 | 2 | 2 |
| − RUN の FET（任意） | 0〜1 | 0〜1 | — |
| − I²C の分割（P1 では任意） | 0〜2 | 0〜2 | — |

### 1.4 B7 ＝ (B)（ミュートを切替に使わない）での数え直し

| | ミュート 2 本（ラッチを残す） | 1 本（電源断のためだけに常閉の非ラッチ） | 0 本（外す・手動） |
|---|---:|---:|---:|
| M の Pico 直の残り（タッチあり／なし） | 0／4（MIRROR で 1／5） | 同じ | 同じ |
| M の制御 MCP | 15/16（余り 1） | 14/16（余り 2） | 13/16（余り 3） |
| P1 の Pico-A | 3〜6／7〜10 | 同じ | 同じ |
| P1 の Pico-B | 4 | 5 | 6 |
| P3（Pico-A＝UI＋制御） | 9／13 に 19 | 9／13 に 18 | 9／13 に 17 → **入らない** |

- **結論は変わらない**: M のミュートは元から制御 MCP の線で、Pico 直の本数（M の唯一の詰まり）に効かない。P1 は余りが 2 本増えるだけ
- 手順の中身も A1 の比較の向きを変えない: B7＝(B) では切替の手順がすべてスタックの線（`ARST`・`PRST`・`PSETk`・`CH_SEL`・`CH_EN`・`RAIL_OK`・音声 SET）の上で閉じる。M では Pico＋制御 MCP、P1 では Pico-B の中で閉じる。親の側で手順に入るのは DIRECT だけ（上の §1.3）
- ミュートを電源断のためだけに残す場合、ラッチは電源断で動かせない（保持の容量 0.4〜1.5 mF、[DER] B6）。常閉の非ラッチなら**コイルの電源が落ちれば自分でミュートに戻る**ので制御線の速さは要らない。つまり [A1P] §5 の「P1 の GPIO 直なら電源断の予告に µs で反応できる」は、この形でも効き所が無い〔推論〕。ただし常閉の非ラッチは聴取中ずっとコイル電流が流れる（[DEC] §2-1 のユーザーの好みに反する。[direct_bypass_review] の素子の表の非ラッチの行と同じ理由）

### 2.2 「同等」の判定

- **リセットの形は同等 — 支持**。どちらも「出力を放す」で、0 を作るのは外付けのプルダウン。M の 2 段目（Pico の pad → MCP の RESET → 出力 Hi-Z）は TIOZ ≤ 1 µs〔MCP p5〕と RESET の線のプルダウンの RC だけで、20 ms のパルスに対して差は無い〔計算〕
- 違いは段の数そのものより**故障点の数**: M は RESET の線のプルダウンの開放（"Must be externally biased" の破り）で MCP の RESET が浮く点が 1 つ増える。P1 は線ごとのプルダウンの開放が各線の故障点（M でも MCP の出力ごとに同じだけある）〔推論〕
- **M だけの小さな穴**: MCP の POR は VDD が 0 V から立つときしか保証されない〔p4 D002〕。RP2350 の BOR はコアの電源（DVDD）を見る〔p498〕ので、Pico の 3V3 が浅く落ちて RP2350 は生きたまま MCP だけが動作範囲（1.8 V〔p4 D001〕）を割ると、MCP の中身が不定のまま残りうる〔推論〕。起きやすさは DS に無い。手当ては IODIR・OLAT の定期的な読み返し（食い違えば RESET から初期化し直す）
- **E9 は同等ではない — 修正**（§2.3）

### 2.3 E9 の露出は P1 の方が大きい

- 条件 3（出力無効）と 2（IE 有効）がそろうのは、ファームがその pad を入力にしたとき・NULL の機能にしたとき。初期化の順（値 0 → 出力）なら、pad は 0 V にあり p1369 の 1 文のとおり E9 は起きない（[A1P] §3.2 は支持）
- 危ないのは **High を出していた線を、IE を有効のまま入力（または NULL）に戻す**書き方: pad が未定義の帯を通って落ちるので、弱いプルダウンだと約 2.2 V に居座る〔p1368〕。娘のコイル側の論理は `+5V_COIL` で動く TTL しきい値の石（[DEC] §2-15）で、VIH は 2.0 V 級〔推論、AHCT の DS は未収集〕→ **2.2 V は High に読まれ、コイル線が High のまま残る**
- M では、この形がありうるのは Pico の `RAIL_OK`・MCP の RESET（と検知線）だけで、MCP の出力 10〜15 本には E9 が無い。P1 では Pico-B の 13〜17 本すべて
- したがって P1 の要件は「**Pico-B のスタックの線のプルダウンはすべて ≤ 8.2 kΩ**」（3.3 V で 1 本 0.4 mA〔計算〕、High のまま居る線は `CH_SEL`・`CH_EN`・`RAIL_OK` の最大 4 本で 1.6 mA、IOVDD の総ソース 100 mA〔p1341〕の内）＋「出力を入力に戻さない（0 を出す）」。[A1P] §7 は「プルダウン 13〜17 本」と書くだけで値が無い — **修正**。石が A3 以降なら不要（`CHIP_ID.REVISION`、[DER] C4）

### 2.4 パルスの途中で止まったとき、コイルが通電したまま残る窓

コイルのパルスは 20 ms（[DEC] §6-2）。「窓」は、止まってから線が 0 に戻るまでの間。

| 止まり方 | M（Pico → I²C → 制御 MCP） | P1（Pico-B の GPIO） | 差 |
|---|---|---|---|
| POR・BOR・SWD のリセット（RUN は `3V3` 直結で今は使えない [SF pin A1602]） | pad Hi-Z → RESET Low → ≤ 1 µs で出力 Hi-Z〔MCP p5〕→ プルダウンで 0 | pad Hi-Z → 0 | 同等（µs） |
| WDT（SDK の WDSEL） | WDT の時間だけ残り、リセットで閉じる〔p506・p1195 からの推論〕 | 同じ | 同等 |
| ハング（WDT を有効にする前・餌やりの位置の誤り） | 残る | 残る（Pico-A の RUN の FET があれば心拍の途切れ 0.5 s で閉じる） | P1 は後ろ盾を 1 段足せる |
| デバッガで停止 | 残る。WDT も既定で止まる〔p1197–1198〕 | Pico-B を止めたときだけ残る | P1（UI のデバッグでは起きない） |
| MicroPython の Ctrl-C（KeyboardInterrupt）・Ctrl-D | 残る（MCP は OLAT を保つ）。**UI の開発中の Ctrl-C でも起きる** | 残る（Pico-B の開発中だけ） | P1 が露出が小さい |
| パルスを閉じる I²C の書き込みの失敗（NACK・バスの固着・化け） | 残る（再試行か、RESET を下げるまで） | 形が無い | P1 |
| 3V3 の浅い瞬断で MCP だけ不定 | 形がありうる（§2.2） | 無い | P1（小） |
| BOOTSEL（ボタン＝電源の入れ直し） | 閉じる | 閉じる | 同等 |
| BOOTSEL（ソフト）・UF2 の後の再起動 | bootrom は WDT 経由〔p397〕、WDSEL は DS に無い | 同じ | 同等（確かめられず） |

- **両案に共通の穴**: ハング・デバッガ停止・Ctrl-C・起動前の窓は、どちらも WDT かファームの後始末（`try/finally`）頼みで、**ハードの最大パルス幅は無い**。§5-8 の排他ゲート（音声 SET ∧ ¬(ARST ∨ Q)、PSETk ∧ ¬PRST）があるので「同じリレーの両コイル」は両案とも起きない。残る害は熱: `ARST` が固まると 8 コイル 373 mA（[DER] §1.1）で L7805C に (12 − 5) V × 0.373 A ≈ 2.6 W〔計算〕が続き、熱保護（"Thermal overload protection"〔ST L78 DS p1〕）か上流の PPTC（0.4 A 保持、[DEC] §3-8）で止まる見込み〔推論〕。壊れはしないが、そのあいだコイルの電源が当てにならない。両案に同じ
- **P1 だけが取れる手当て（[A1P] に無い）**: 20 ms のパルスを PIO のステートマシンで作る（「1 を出す → 20 ms 待つ → 0」を FIFO への 1 回の書き込みで起動）。CPU のハング・Ctrl-C でもパルスは PIO が終わらせる。WDT（PAUSE_DBG0/1 の既定 1〔p1197–1198〕）と TIMER（DBGPAUSE の DBG0/DBG1 の既定 1〔p1192 Table 1239〕）は既定でデバッグ停止中に止まるので、`sleep_ms` やタイマの割り込みで作るパルスはデバッガ停止で終わらない。PIO の章にその設定は見当たらない → PIO は止まらないと読む〔推論〕。M ではパルスの終わりに CPU の I²C 書き込みが要るので、この手当ては取れない
- **両案に効くハードの手当て**（採るかは別の判断）: 娘の上で SET/RESET の入力を単安定で最大幅に切る（固まった High でもコイルは最大 30 ms 程度で切れる）〔推論〕。[DEC] §5-8 のゲートと同じ石の中で作れる見込み

## 3. P1 の 3 つの利点の裏

### 3.1 利点① 主電源 OFF・USB だけで Pico-B は無電源 → 規則②が配線で守られる — **修正**

**`+5V_D` の出どころ — 支持**
- `PD_12V`（PD モジュールの出力 `J202`）→ `SW402`（主電源スイッチ）→ `PD_12V_SW` → `F1602`（PPTC 0.5 A）→ `PD_12V_MEAS` → `U1607`（BP5293-50）→ `+5V_D` → `D1601`（RB160M-30）→ Pico の VSYS [SF pin SW402・F1602・U1607・D1601、nets PD_12V・PD_12V_SW・PD_12V_MEAS・+5V_D]。**`+5V_D` は主電源スイッチの後ろ**
- BP5293-50 の推奨入力は 7〜26 V、UVLO は 6.4 V typ（下降、6.0〜6.8 V）〔ROHM BP5293 DS p4〕、起動は 6.6 V typ〔同 p6〕→ PD の交渉前の 5 V の窓でも Pico-B は動かない。12 V の無い充電器で 9 V に落ち着くと動く（[A1P] §5 (i)、支持）
- `+5V_D` には LCD の負荷スイッチ（`U1609` XC8107 → `LCD_VCC`）とパネルへの渡りも載る [SF nets +5V_D]。BP5293-50 は 1 A max〔ROHM p1〕、今の見積もり 0.25〜0.3 A（[電] §1.3）に Pico 1 個を足しても余る見込み〔推論、Pico 2 の消費は DS が無く確かめられず〕

**「配線で守られる」の範囲 — 修正**
1. **Pico-B に USB を挿すと消える**。Pico-B は VBUS で生き、規則②はファームに戻る（[A1P] §5 (ii) 自身が書いている）。開発中はこの状態が普通になる
2. **受け側の 3V3 へのプルアップが逆給電の経路になる（[A1P] §4.1 の見落とし）**: 主電源 OFF・Pico-A だけ USB のとき、Pico-A の TX はアイドルで High を出し続ける。Pico-B の RX を「10 kΩ → Pico-B 自身の 3V3」で引いていると、**Pico-A の TX → 10 kΩ → 死んだ Pico-B の 3V3 の網**へ最大 3.3 V / 10 kΩ ＝ 0.33 mA〔計算〕が流れ続ける（PC に挿したままなら何時間でも）。[A1P] の「相手が無電源でも pad は failsafe なので流れ込まない」は pad については正しい（FT は "very little current"〔p1336〕、IOVDD＝0 V で 3.63 V まで〔p1339–1340〕）が、**プルアップ抵抗は pad を通らない**。死んだ 3V3 がどこまで持ち上がるかは Pico 2 の基板の DS が無く確かめられず。直し方: **プルアップは送り側の 3V3 に置く**。送り側が死ねば線は 0 V（受け側は break を読む。0 V は VIL の下なので E9 は起きない〔p1368〕）、受け側が死ねば送り側の High は FT の pad に「ごく小さい電流」だけ
3. **M も 1 ゲートで同じ性質になる（[A1P] が比べていない）**: 制御 MCP の RESET（と `RAIL_OK`）を「Pico の GPIO ∧ 電源検知あり」の 2 入力 AND で作る（AND は Pico の 3V3 で動き、入力にプルダウン）。電源検知が無い間は Pico のファームが何をしても MCP は RESET のまま、出力は Hi-Z → 0。Pico のリセットでも入力のプルダウンで 0。**Pico に USB を挿しても崩れない**ので、この点は P1（Pico-B の USB で崩れる）より強い〔推論〕。P1 でも Pico-B の RUN を「電源検知あり」で放す FET にすれば同じになる（代わりに主電源 OFF では Pico-B を USB だけで動かせない）
4. 守られる害の大きさ: 規則②が破れたときの害は「`+5V_COIL` の無い娘の TTL 入力へ 3.3 V」（[DEC] §2-15 前提の Ioff か直列 R）で、コイルは電源が無いので動かない。**リレーが動く害ではない**ので、①の利点はもともと小さい

**ADC のピンの注入 — 両案に共通（[A1P]・[電] が故障のときだけに限っている点を修正）**
- ADC のピンは Standard の pad で、無電源なら 0.5 V を超えると絶対最大の外〔p1339–1340〕。[A1P] §5 と [電] §2.3 の表は「Pico の電源の枝だけの故障」のときだけとしている
- しかし**ふだんの電源断のたび**に起きる: 主電源を切ると Pico の 3V3 は約 2 ms で失われ、娘のレールは 17〜29 ms 残る（[DER] §1.1、選んだ娘の電源リレーはセットのまま）〔計算は [DER]〕。その間 `MON_P`/`MON_N` の分圧が無電源の ADC ピンに掛かる。M の Pico も同じ（USB が無ければ）なので**差ではない**が、分圧の上側の抵抗で注入を制限する要件は「故障のとき」ではなく「毎回」として置く。RP2350 の DS に注入電流の規定は見当たらない（確かめられず）

### 3.2 利点② I²C が無いので書きかけ OLAT の故障形が無い — **支持（差は小さい）**

- 「書きかけ」は言い方が不正確。I²C では途中で切れたバイトは書き込まれず、OLAT は完全なバイトごとに更新される（"Writing to the OLATn register forces the associated output drivers to drive to the level in OLATn"〔MCP p16〕）。本当に残る形は 2 つ〔推論〕:
  - **化けたバイトがそのまま出力になる**（I²C に誤り検出が無い）。例: 余計な PSETk が立つと 2 枚目の娘に電源が入る（音声 SET は §5-8 と `RAIL_OK` でゲートされるのでバスには出ないが、「1 枚だけ ON」はファームだけの約束 [DEC] §2-9 前提）
  - **連続書き込みでアドレスが進む**（SEQOP の既定は自動加算〔MCP p21〕）。バイトの取りこぼし・ファームの誤りで次のレジスタ（IODIR など）へ書きうる → 1 レジスタずつ書く
  - どちらも「書いたら読み返す」で ms の内に検出・修正できる。**I²C の High の低下で PRST を書けない形（[制] #8）は、M でも A1 の必須の分割で消える**
- **P1 の UART の化け・フレーミングの誤りは代わりにどうなるか**: UART は要求だけを運び、コイルの出力は Pico-B が自分の状態から決める。取り決めに要るもの: (1) フレームごとの CRC、(2) 連番と**冪等な要求**（「次の ch へ」ではなく「ch k へ」。応答が失われて再送しても手順を 2 回走らせない）、(3) break・タイムアウトを「相手が死んだ・リセット中」として扱う（§3.1 の送り側プルアップなら、相手が死ぬと break になる）。CRC をすり抜けた化けは「正しい手順の、別の ch への要求」にしかならず、手順の規則（全リセットから、音声 SET は 1 か所）は守られる〔推論〕。表示との食い違いは状態の返送で分かる
- したがって**向きは P1 が正しいが、M の必須の手当て（分割・読み返し）の後に残る差は小さい**

### 3.3 利点③ UI 側のハングがスタックに届かない — **支持（ただし安全ではなく可用性と故障の封じ込め）**

- M で UI（LCD・FFT・USB・エンコーダ）がハングすると、WDT が全体をリセットし全リセット（無音）になる。**安全側に倒れるので、これは安全の差ではない**。差は「音が止まる」かどうか（可用性）と、デバッガ停止・Ctrl-C で監視も止まること
- [A1P] が書いていない**より強い点**: M では UI のコードと制御のコードが同じ実行環境・同じ I²C ドライバにいる。UI の誤り（番地・レジスタの取り違え、LED の read-modify-write）で制御 MCP を書ける経路がある。[DER] A1 は UI の MCP と制御 MCP を**同じ新しいバス**へ移す案なので、なおさら近い。P1 は Pico-A からスタックの線を書く手段が配線に無く、要求は Pico-B が検める → **故障の封じ込め**。M でこれを近づけるなら、制御 MCP だけを専用のバス（I2C1）に置き、UI の MCP は PT2314E の元のバスに残す（UI の MCP は ±15 V が無いと読めなくなるが、そのとき UI は要らない）
- **逆に Pico-B のハングは誰が拾うか**: [A1P] §4.2 の (1) Pico-B 自身の WDT（安全に効く唯一の WDT）と (2) Pico-A の心拍の監視（表示＋任意で RUN の FET）で**支持**。ただし:
  - WDT を有効にする前のハング・餌やりの位置の誤りを拾えるのは (2) の RUN の FET だけ → **「任意」ではなく推奨**にすべき
  - Pico-B をデバッガで止めると WDT も止まる〔p1197–1198〕。RUN の FET が 0.5 s でリセットを撃つと、デバッグにならない → 心拍の監視を止める切り替え（Pico-A 側の設定）が要る
  - RUN の FET の誤動作（Pico-A のバグ）は Pico-B のリセット＝無音で、安全側。P1 の「UI の不具合がスタックに届かない」を 1 本だけ破るが、向きは安全〔推論〕
  - RUN のプルアップは RP2350 の中にある〔p1338 Table 1430〕ので、FET で Low に引く形は基板の外付けの有無に依らず成り立つ

## 4. 見落とし

### 4.1 2 石をまたぐ依存 — 規則①と PT2314E

- [A1P] §5 は「§5-7 の検知線と規則①②③はそのまま Pico-B に置く」。しかし規則①は「全リセット**と PT2314E の初期化（50 ms 待ち）**」で、PT2314E は Pico-A のバス。加えて「±15 V が戻るたびに PT2314E を 50 ms 待って全レジスタを書き直す」（[DER] B8 #7、RS6 のヒカップからの復帰など）のきっかけを見られるのは `MON`・検知線を持つ Pico-B だけ
- Pico-B がリセット中・ハング中に ±15 V が落ちて戻ると、Pico-A は PT2314E の書き直しを取りこぼす。PT2314E の POR 直後の状態は未確認（[DEC] §10-1）なので、**LCD の Bass/Treble と現物が食い違い、音量側の既定しだいで聴こえる**〔推論〕
- 埋め方（どれか）: (a) Pico-B の心拍に**電源の世代番号**（検知の立ち上がり・±15 V の復帰ごとに増やす）を入れ、Pico-A は世代が変わったら 50 ms 後に全レジスタを書く。Pico-B が再起動したら、世代の比較ができないので Pico-A は書き直す、(b) Pico-A も `VCC_TONE` か検知線を読む（1 本の検知線を 2 つの pad で読むなら、E9 の漏れが 2 つ分になるのでテブナンは ≤ 8.2 kΩ の半分程度が目安〔推論: DS の 8.2 kΩ は 1 pad の値〕）、(c) Pico-A が PT2314E を一定の間隔で書き直す（依存は消えるが聴取中に I²C のエッジが出る）
- 同じ種類の依存: [制] F8 の「切替のたびに PT2314E の減衰器でミュート」を手順に入れると 2 石をまたぐ。[DEC] §2-10 の理由（過渡はバスより下流に出るので PT2314E のミュートでは消えない）と B7＝(B)（娘は音声リレーでバスから切れている）により、この手順は P1 では**入れない**のが素直〔推論〕

### 4.2 起動の順・片方だけの書き換え・版の食い違い

- 主電源 ON（USB なし）では 2 個が同時に起動する。Pico-A は Pico-B の心拍が来るまで「制御待ち」を表示し、要求を出さない。Pico-B は起動のたびに全リセット（規則①と重なる、[A1P] §5 は支持）
- **Pico-A だけを書き換える**: スタックはそのまま（支持）。書き換えの後、Pico-A は状態を問い合わせ、自分から全リセットを要求しない（[A1P] §4.1、支持）。PT2314E は §4.1 の世代で扱う
- **Pico-B だけを書き換える**: 全リセット（無音）→ 起動 → 全リセット。M の書き換えと同じ
- **版の食い違い**: [A1P] は「心拍に版番号 → LCD に出せる」まで。取り決めの版が合わないとき Pico-A は**要求を出さない（表示だけ）**と決め、取り決めを変えるときは Pico-B（後方互換）→ Pico-A の順に書く、を手順として置く必要がある
- 試験の組み合わせが増える: リセットの種類（§2.4 の表）× 2 石、加えて「A 生・B 再起動中」「A 再起動中・B 生」「A だけ USB・B 死」「B だけ USB・主電源 OFF」

### 4.3 グランド・USB 2 口

- **[A1P] §5 の「2 本の USB を同じ PC に挿してもループは小さい」は棄却（理由の誤り）**: 閉路は PC → ケーブル A → Pico-A → `D_GND` → Pico-B → ケーブル B → PC。面積を決めるのは 2 本のケーブルの取り回しで、2 個の Pico の間隔ではない。USB のグランドが床に効くことはリポジトリにも記録がある（[DEC] §4-10 の USB アイソレータの行: USB を抜いた A/B で 2.9 dB、n＝1。V21-継-28）。**聴く・測る間は USB を Pico-A の 1 本だけ**にする運用として置く
- `D_GND` の中に 2 か所のデジタルの塊: 隣に置けば UART と戻りは短い（支持）。スタックの `D_GND` のピン（Pico からの線の基準、[DEC] §2-5）は Pico-B の足元で取る〔推論〕
- デバッグ: PC にシリアルが 2 つ出る（どちらかを取り違えない仕掛けが要る）。Pico-B の REPL・ログは Pico-B の USB を挿さないと見えない → Pico-A 経由の中継を取り決めに入れるか。[A1P] が挙げていない選択肢: Pico-A を Pico-B の SWD の書き込み器にする（Pico-A の 2 本と Pico-B の SWD の端子。Pico 2 の SWD はシンボルの 40 ピンに無い）と、USB 1 本で両方を書ける〔推論、手間は大きい〕

### 4.4 置き場とクロック・電源の塊

- Pico-B が親に持ち込むのは CPU・フラッシュのクロックと 12 MHz の水晶だけではない: RP2350 には**コアの電源を作る on-chip のスイッチング電源**がある（"On-chip switched-mode power supply to generate core voltage"〔p14〕）。Pico 2 の基板の 3V3 もスイッチングの見込み（[制] 新-7〔推論〕）。つまり**スイッチングの源が DS で 1 個・推論で 1 個増える**。MCP23017 は待機 1 µA max〔MCP p4 D005〕で源にならない
- 静的な線の High の揺れ: M でも P1 でも駆動する石の電源（Pico の 3V3）の揺れは乗る（[A1P] §6、支持）。加えて P1 では、同じ石の中で他の pad が動く（UART の心拍）ので、pad の電源・グランドの跳ねがスタックの静的な線に乗る〔推論〕。聴取中は心拍の間隔を長くするか、状態が変わったときだけにできる
- 大きさは誰も測っていない。「小さい」は [A1P] の推論のまま。コネクタの手前の直列 R＋小さな C（[A1P] §6）は両案に同じだけ効く

### 4.5 費用・面積

- 価格・Pico 2 の寸法はリポジトリに無い — [A1P] のとおり**確かめられず**
- 親の外形はラフ配置で (5,5)–(455,455) mm（NOW「PCB」）。最終の大きさは未定だが、Pico モジュール 1 枚分が決め手になる見込みは低い → [A1P] の外れる条件「面積が足りない」は弱い〔推論〕

### 4.6 その他の小さな点

- DIRECT は Pico-B に置く（§1.3）。[A1P] の置き方は支持、理由を B7＝(B) で補った
- **今の Pico の周りをそのまま写すと壊れる所**（図にするときの注意）: (1) 今の Pico は 3V3（36 番）・ADC_VREF（35 番）・RUN（30 番）が `3V3` 網に繋がっている [SF pin A1602]。Pico-B の 3V3 を同じ `3V3` 網に繋ぐと **2 つの 3V3 の出力が並列**になる → Pico-B の 3V3 は別の網（ADC_VREF もそちらへ。`MON` の比率校正の基準になる）。(2) RUN の `3V3` 直結を写すと、§3.3 の RUN の FET が 3V3 を GND へ短絡する → Pico-B の RUN は石の中のプルアップ〔p1338〕に任せ、FET のドレインだけを付ける
- ESD: スタックのコネクタの線は P1 では RP2350 の pad に直に来る（FT の pad は HBM 4 kV〔p1340 Table 1434〕）。M では MCP23017（ソケットの DIP で安い）が受ける。直列 R（§4.4）は ESD にも効く〔推論〕

## 5. 結論の妥当性

### 5.1 両案に共通のもの（差し引く）

外付けプルダウン（Pico が駆動する線は ≤ 8.2 kΩ）／E9 の扱い（IE・初期化の順）／WDT の設定（SDK の WDSEL で PADS まで戻す）／規則①②③と `PD_12V_SW` の検知線（しきい値素子・テブナン ≤ 8.2 kΩ）／`MON` の注入の制限（毎回の電源断で要る）／娘の Ioff・§5-8 の排他・B1/B2・EN ≤ IN／`RAIL_OK` の意味（能動 High の間だけ良）／**ハードの最大パルス幅が無いこと**／リセットの形（放す → プルダウン）

### 5.2 差し引いた後に残る差

| | P1 の得 | P1 の損 |
|---|---|---|
| 安全 | 無し（同等）。細かくは: パルスを閉じる I²C の失敗が無い、3V3 の浅い瞬断の MCP の不定が無い、PIO でパルス幅をハードに持てる | E9 の線が 13〜17 本（値の制約）。直さなければ UART の逆給電 |
| 故障の封じ込め | **UI のコードの誤り・ハング・Ctrl-C・デバッガ停止・書き込みがスタックの線に届かない**（最大の得） | RUN の FET を入れると Pico-A から Pico-B を落とせる（安全側） |
| 可用性 | UI を書き換え・止めても音が続く | Pico-B の書き換えは M と同じく無音 |
| 本数 | 余りが多い、Pico-A の ADC 3 本が空く | — |
| ファーム | Pico-B を小さく変えない専用に（C でも） | 2 本＋取り決め（CRC・冪等・版・電源の世代）、2 石をまたぐ依存、試験の組み合わせ |
| 電気・音 | 規則②が Pico-B の USB を挿さない限り配線で守られる（M も 1 ゲートで同じ） | 常時動く MCU＋on-chip のスイッチング電源（＋基板の 3V3）が親に 1 組増える（未測）。USB 2 本の閉路（運用で避ける） |
| 部品・費用 | — | Pico モジュール 1 枚（価格は確かめられず） |

### 5.3 判定

- **「安全は M と同等以上」→「安全は同等」に直す**。「以上」の 3 理由のうち、①（I²C が無い）は M の必須の分割と読み返しで小さくなり、②（主電源 OFF で死ぬ）は M も 1 ゲートで得られて P1 は Pico-B の USB で失い、③（UI が届かない）は安全ではなく可用性と故障の封じ込め
- **「僅差」は妥当**。ただし符号は根拠からは決まらず、**ユーザーがファーム 2 本と取り決めを受け入れて、UI の故障の封じ込めを買うか**で決まる。[A1P] が「最も現実的な分かれ目」としたところ（ファームを 2 本持ちたくないなら M）は正しい
- **M が勝つ条件の書き方 — 修正**。[A1P] の 4 つに足す:
  - UI の故障の封じ込め・可用性を重く見ない（UI のハングは WDT で無音に倒れればよい）
  - 親に常時動くスイッチングの源（RP2350 のコアの電源・基板の 3V3）を、測るまで増やしたくない
  - 聴く間も Pico-B の USB を挿したままにする使い方（P1 の②が消え、USB の閉路ができる）
  - 外してよい: 「面積が足りない」（§4.5）
- **P1 が勝つ条件**（[A1P] に明示が無い）: UI・FFT・LCD のファームを聴きながら何度も書き換える開発の形が続く／監視と手順のファームを MicroPython の UI と別の実行環境に置きたい（[制] F4 の「LCD・I²S・FFT と同じ流れで回さない」を石で満たす）
- 統合した推奨は §0.2（条件つき、既定を置くなら P1、ただし P1 の修正 6 点を前提に）
