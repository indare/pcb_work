## 1. 指摘詳細

### [要確認] ⑦-1 初回 bring-up と単体試験の切り方が文書に無い

**何が** — NOW の「次にやること」は否定側査読のあと、娘（電源／音声リレー・ゲート・デコーダ・B1/B2・排他）と親（RS6・ADC・検知・制御 MCP・NJW1194…）の実装へ進む。DECISIONS §5・§6・§10 にも、段階（例: 親だけの PD／`+5V_D` → RS6 無負荷 → 娘 0 枚で全リセットと `MON` 空 → 娘 1 枚で PSET のみ → 音声 SET → ch EN）の手順が無い。  
**なぜ効くか** — ラッチング・縦積み・共通音声 SET・OR の `MON` は、一括配線してからだと「誰が生きているか」が最初から曖昧になる。単体で親と娘を切れないと、初回短絡・溶着・ジャンパ重複をファーム手順の奥まで持ち込む。  
**確度** — 文書事実（NOW L22、§6-2 は運用手順のみ）。  
**外れる条件** — 別文書に bring-up 手順がある／実装担当が口頭で同じ段階を守る、と明示される場合。

### [要確認] ⑦-2 `MON`/`PG_N` だけでは故障分離できず、TP も未定義

**何が** — §5-2: 各娘の生レールをダイオード OR → 親で分圧 → Pico ADC。`PG_N` は「どれかの娘に両レールあり」のワイヤード OR。規則③（§5-7）は全リセット後に `MON` が約 10 V を割ることで「戻らないリレー」を見る。DECISIONS 全体に、親の `PD_12V_SW`／±15 V／`+5V_COIL`／分圧後 `MON`／娘ローカル ±15 V（22 Ω 後）／ch LDO ±12 V／`AMP_SEL` などの**測点（TP）一覧が無い**。§4-14 の外出し端子は聴取用で、電源・制御の bring-up 用ではない。  
**なぜ効くか** — OR は「どれかがある」しか言わない。溶着・ジャンパ重複・片レール落ち・ch LDO 短絡をオシロ／DMM で切り分けるとき、どこに当てるかがレイアウト後まで決まらない。`MON` は生の ±15 V 側で、ch LDO 出力の短絡は間接（レール落ち込み）にしか見えない。  
**確度** — 文書事実（§5-2・§5-7・§2-5）＋推論（観測点の欠落が切り分けを阻害する）。  
**外れる条件** — スタック 24 本のピン配置で各娘ローカルレールや段 ID を探針できると決める／PCB で TP をネット名付きで置く、と実装前に書く場合。

### [要確認] ⑦-3 ファーム無しの「箱としての安全」は厚いが、「試験切り」とデバッガ経路が穴

**何が** — §6-1: B1/B2、`RAIL_OK` 能動 High、電源検知∧MCP RESET、排他ゲート、EN≤IN、デコーダ既定 OFF は、ファームが止まっても「つながない・両コイル同時通電しない」向き。一方 §5-3 前提: BOOTSEL・デバッガ停止・起動中は WDT も助けない／High 出しっぱなしのハングは B1/B2 頼み。design_eval B11 の「差し替えモード（全リセット→放電確認→LCD）」は §6-2 に無い。娘だけ／親だけでコイルを手で叩く手順も無い。  
**なぜ効くか** — 初回はほぼ必ず SWD／REPL で止める。その間 `RAIL_OK` と MCP の状態は「完成品の安全証明」の外。差し替えモードがファーム責務に無いと、運用約束（電源切って抜き挿し、§6-2）以外の安全な差し替え観測点が無い。  
**確度** — 文書事実（§5-3・§6-1・§6-2、design_eval B11）。  
**外れる条件** — デバッガ使用時は電源 SW OFF を必須にする／差し替えモードを §6-2 に入れる／制御線を外して娘単体治具で試す、と書く場合。

### [要確認] ⑦-4 DNP／0 Ω 足場の「使い方」が bring-up 手順になっていない

**何が** — 足場はある: CMC 0 Ω（§3-9）、−15 V プリロード DNP（§3-10）、HP 電源 RC（§3-11）、親 +100 µF 任意（§3-6）、Q1 戻し／GND ヘッダ（§4-3・§4-4）、RCOM 0 Ω（§4-8）、VCOM・I²S 0 Ω（§4-11）、電源断 GND 落としは R=0 Ω・リレー類 DNP（§2-10）、NJW1194 まわりの 0 Ω／置き場（§1-6）。どれも「実装するかは実測後」で、**どの段階でどの足場を載せて何を切り分けるか**が無い。§4-9 の予備 12 V は SW 迂回で bring-up に使えるが、同時給電の並列と検知「有り」固定の副作用だけの注記。  
**なぜ効くか** — 足場は「後で直せる」ためのもので、初回切り分けの手順書ではない。0 Ω のまま音を出してから CMC／プリロード／RC を載せる順序を間違えると、原因が電源・制御・音声のどこか分からない。予備入口は「SW 無しで動く」試験に便利な一方、§5-7 の検知を常時「有り」にしうる。  
**確度** — 文書事実。  
**外れる条件** — 足場ごとに「未実装で測る項目／実装して測る項目」の表を §10 か NOW に足す場合。

### [要確認] ⑦-5 §10 の抜け — C 項目との突合せと実測-02 の手順矛盾

**何が**  
1. design_eval **C1**（使う充電器で PDO・主 SW 突入・再交渉・12 V 不出時に 5 V 窓が続くか）は §3-13 で「C1 の実測」と参照されるが、§10-1 に **V21-実測 ID が無い**。V21-実測-03 は充電器↔リニア／電池の**音の A-B-A**で、C1 の起動・損傷側とは別。  
2. **C4**（`CHIP_ID.REVISION`／MicroPython ADC の IE／WDT の pad 復帰）は §10 に無い。§5-2・B9 の E9・比率校正・`RAIL_OK` の信頼に直結。  
3. **C3**（縦積みの手の届き）は V21-未決-20 のまま。観測・差し替えの物理アクセス。  
4. V21-実測-02 の表は「1 ch・無音・軽い石」、§3-13 は「待機（娘すべて OFF）で測る」— **同じ ID で手順が食い違う**。  
5. NOW が挙げた NJW1194 実物確認（本物か、スルー段、雑音、電源断時入力電流）も §10 に ID が無い。  
6. 評価 B1 の「整定後 ≈13 V」しきい値・ソケット短絡の必須規則は §6-2 に未反映（⑦-7）。  
**なぜ効くか** — NOW は「基板前に要るのは実測-01」とだけ言い、C1 を基板前必須に格上げしていない。PD 突入でヒューズ／交渉失敗すると bring-up 自体が始まらない。C4 未測のまましきい値とプルダウンを固めると、監視が誤「良／不良」になる。実測-02 の負荷条件が二つあると、プリロード DNP 判断が再現できない。  
**確度** — 文書事実。  
**外れる条件** — C1/C4 を §10 に採番して順序を書く／実測-02 を一方に直す／NJW 実測を §10 に載せる場合。

### [要確認] ⑦-6 実装順で戻れない決定 — ピン配置・コネクタ・観測幾何

**何が** — §2-5: 24 本内訳はいったんの決め、**ピン配置は未確定**。§5-2: `MON` を論理線の隣に置かない。V21-実測-01 は基板前必須と書いてあるが、NOW の実装列挙はそれをゲートにしていない。娘 MCP 廃止（§2-12）で段ごとの I²C デバッグは消えた。B7 毎回全リセットは寿命・音・所要をロック済み。  
**なぜ効くか** — 親・娘同時に 2×12 を切ると、ピン間違い・MON 隣接・探針不能は両方の再版になる。段ジャンパの重複は §2-6 前提で残る弱点で、OR の `MON` では「2 枚同時給電」の切り分けが弱い。実装を図から始めると、観測点を後付けする銅が無い。  
**確度** — 文書事実＋推論（コネクタ／ピンは一発ロック）。  
**外れる条件** — ピン配置＋TP 表を図の前に閉じる／実測-01・C1 を NOW の着手条件に明示する／片方だけ先に治具ピンで試す場合。

### [軽微] ⑦-7 ソケット短絡の観測がファーム案のまま

**何が** — design_eval B1: 立ち下がり 10.5 V ではソケット短絡後の娘レール 10.2〜11.1 V を取り逃しうる → 整定後 ≈13 V を必須に。§6-2 にその行が無く、「迷惑トリップを無限再試行しない」は未決（推奨）。  
**なぜ効くか** — 石差し替えが目的の装置で、初回・運用ともいちばん起きる故障の分離が、ハードの `MON` 帯とファーム未決の間に落ちる。  
**確度** — 文書事実（評価 B1 vs §6-2）。  
**外れる条件** — B1 を §6-2 に必須で書き、しきい値 2 段を bring-up チェックリストに入れる場合。

## 2. 問題なし

- §6-1 のハード保証一覧（B1/B2、電源検知 AND、排他、EN≤IN、デコーダ既定 OFF、NC／バスの DC 基準）は、**完成後・ファーム無し／停止時にバスへつながない**方向として文書上つながっている。  
- §5-7 規則①（起動時すでに検知あり）は、Pico が `PD_12V_SW` 系から来る前提と整合し、USB 先挿しでも主 SW 後に全リセットが走る筋がある。  
- 規則③（全リセット後 `MON` 下降確認）は、OR の弱点（古い娘のレールを「良」と見せる）に対する、ハード追加無しの検出手順として評価 A2 と一致。  
- `PG_N` で `MON_N` 上側開放の誤「良」を別ビットで見る（§5-2／A5）は、監視の妥当性チェックとして足りる最小限。  
- LM4040 を ADC0（旧 `DEST_ADC`）で比率校正する割り当ては、監視の再現に必要で、DEST 位置センス廃止と矛盾しない。  
- V21-実測-01 を「基板を起こす前」と明示している点は、電源系の不可逆（+100 µF・22 Ω 電力）に対して順序が正しい。  
- Q1 戻しヘッダ、RCOM／VCOM／I²S／CMC／プリロード／HP RC など、**音・電源の後追い変更用足場**自体は、テスト可能性の「後から直す」側としては揃っている。
