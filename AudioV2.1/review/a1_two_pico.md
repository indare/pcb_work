# A1 の別案「Pico を 2 個」— 親の制御 MCP23017 案との比較

- 作成: 2026-09-25（評価エージェント、読み取り専用）。書いたのはこのファイルだけ
- 対象: [DER]（`review/design_eval_review.md`）A1 の推奨（親に制御専用 MCP23017）と、ユーザーの「Pico を 2 個使う手もありそう」（V21-未決-26）を並べて評価する

## 0. 結論

| 観点 | M: Pico 1＋制御 MCP23017（A1 の推奨） | P1: Pico-A（UI・トーン・計測・USB）＋Pico-B（スタックの制御専用） | 勝ち |
|---|---|---|---|
| Pico の空き（タッチあり／なし） | 0（MIRROR で 1）／4 | A: 0〜3／4〜7、B: 4〜8。ADC は A の 3 本が空く | P1 |
| リセットで全コイル線と `RAIL_OK` が 0 | Pico → MCP の RESET → 全ピン入力、2 段 | pad のリセット状態（Hi-Z・入力無効・プルダウン）で 1 段〔RP2350 DS p589–590〕 | 同等 |
| WDT・ソフトリセット・E9 の条件 | 同じ条件に乗る（[DER] C4） | 同じ | 同等 |
| 主電源 OFF・USB だけ | 制御側が生きていて、線を 0 に保つのはファーム（§5-7 規則②） | Pico-B は無電源で線はプルダウンの 0（配線で守られる） | P1 |
| 制御の経路の I²C | あり（書きかけ・High の低下）→ I²C の分割が必須 | 無い → 分割は任意 | P1 |
| UI のハング・書き込み・デバッガ停止 | スタックの監視・手順も止まる | スタックは生きている | P1 |
| 音（[DEC] §2-12） | 静的な線だけ | 同じ（Pico-B は親のデジタル区画に置く）。親に動き続けるクロックの塊が 1 個増える | 同等（P1 に小さな未測の増分） |
| 部品・面積・費用 | 小・安（価格は確かめられず） | Pico モジュール 1 枚分、高（同） | M |
| ファーム・デバッグ | 1 本 | 2 本＋取り決め（UART・心拍・版番号）、状態の食い違いの追跡 | M |

**推奨: P1**。安全は M と同等以上（根拠は同じ pad／POR の事実で、加えて主電源 OFF で制御側が死ぬ・制御に I²C が無い・UI の不具合が届かない）、本数は両方に余りがある。M が勝つのはファームの本数・部品・費用。
**外れる条件**: ファームを 2 本持ちたくない、Pico-B の USB に手が届く置き場が無い、面積が無い → M（そのときはタッチを捨てるか MIRROR で余りを作る）。P2（M＋監視用 Pico）は P1 に劣り、P3（計測を別の Pico へ）は本数が入らず棄却（§2・§8）。

## 1. 前提（読んだもの・数え方）

- 入口: `AudioV2.1/CLAUDE.md`・`NOW.md`・`DECISIONS.md`（以下 [DEC] §n）。統合リスト `review/design_eval_review.md`（[DER]）、`review/design_eval_control.md`（[制]）、`review/design_eval_electrical.md`（[電]）
- `AudioV2/`・`Audio/` の文書は読んでいない
- 凡例: 〔DS p.xx〕は DS の PDF ページ（`pdftotext -layout` の頁、PDF の通し番号）／〔計算〕／〔推論〕／〔仮定〕／[SF …] は `python3 AudioV2.1/scripts/sch_facts.py …`（図は v2 の回路なので「今ある物」だけ）
- 今の Pico（`A1602`、Pico 2）の使い方は [SF pin A1602] とシンボルのピン名で確かめた: I²S 3（GP0〜2）、LCD 6（GP5〜8・GP18/19）、タッチ 4（GP10〜13）、`ADC_nMR` 1（GP15）、`ENC_INTA/B` 2（GP16/17）、I²C 2（GP20/21）、ADC0＝`DEST_ADC`。**空きはデジタル 5 本（GP3・GP4・GP9・GP14・GP22）＋ADC1・ADC2**、RUN（30）は `3V3` 直結。[DER] §1.8 と一致
- Pico 2 の基板で外に出ている GPIO は 26 本（GP0〜22 と GP26〜28。うち ADC に使えるのは GP26〜28 の 3 本）— **シンボルのピン名からの数え**。Pico 2 基板の DS はリポジトリに無いので、基板の内部で使っているピン（GP23〜25・GP29）の用途・3V3 の取れる電流・起動時間・RUN のプルアップの有無は**確かめられず**
- 要る線（[DEC] §2-5 の 24 本の内訳、§2-10、§5-2、§5-3、§5-7 から）:
  - スタックへの出力 10 本: `PSET1`〜`4`（4）・音声 SET（1）・`ARST`・`PRST`（2）・`CH_SEL0/1`（2）・`CH_EN`（1）
  - `RAIL_OK`（出力 1、Pico の GPIO 直 §5-3）・`PG_N`（入力 1、§5-2）・`MON_P`/`MON_N`（ADC 2）・LM4040（ADC 1、比率校正 §5-2）・`PD_12V_SW` の検知（入力 1、§5-7）
  - 親の中: ミュート 0〜2（§2-10。推奨のラッチなら SET/RESET の 2 本、手動スイッチなら 0）、DIRECT 0〜2（V21-未決-14、評価中）
  - これらは**切替の手順の中で順序を守って動く一組**（[DEC] §6-2）。どこで切っても、手順の原子性（途中で別の手が入らない）を 1 個の石の中に置けるかが割り方の良し悪しを決める〔推論〕

## 2. 割り方の候補と本数（課題 1・6）

### 2.1 候補

| 記号 | 形 | 一言 |
|---|---|---|
| **M** | Pico 1 個＋親に制御専用 MCP23017（RESET は Pico の GPIO、プルダウン付き）。I²C を分けて MCP を 3.3 V だけのバスへ（[DER] A1 の推奨） | 比較の基準 |
| **P1** | **Pico-A**＝UI（LCD・タッチ・ENC の MCP）・トーン（PT2314E）・計測（I²S・`ADC_nMR`）・USB。**Pico-B**＝スタックの制御専用（コイル線 10・`RAIL_OK`・`PG_N`・`MON_P`/`MON_N`・LM4040・`PD_12V_SW` の検知・ミュート・DIRECT）。2 個の間は UART | ユーザーの案の素直な形 |
| **P2** | M に監視専用の Pico-B を足す（Pico-B＝`MON`・LM4040・`RAIL_OK`・`PD_12V_SW`・`PG_N`、制御 MCP の RESET も Pico-B から）。手順とコイル線は Pico-A＋制御 MCP | 監視だけ切り離す |
| **P3** | Pico-B＝計測（I²S・`ADC_nMR`・FFT・USB）、Pico-A＝UI＋スタックの制御 | 重い計算を追い出す |

### 2.2 本数〔計算〕

デジタルの「空き」は、その Pico の外に出ている 26 本から ADC に使う本数と今の用途を引いた数。

**M（Pico 1 個）**

| | タッチあり | タッチなし |
|---|---:|---:|
| 空き（今） | 5 | 9（GP10〜13 が空く） |
| 使う: `RAIL_OK`・MCP の RESET・`PD_12V_SW` | 3 | 3 |
| 使う: I²C を分ける 2 本（I2C1。GP14＝I2C1 SDA・GP3＝I2C1 SCL、タッチなしなら GP10/GP11＝I2C1 SDA/SCL）〔DS p19 Table 3〕 | 2 | 2 |
| **残り** | **0** | **4** |
| ADC（LM4040・`MON_P`・`MON_N`） | 3/3 | 3/3 |
| 制御 MCP（出力 10＋ミュート 2＋DIRECT 2、入力 `PG_N`） | 15/16 | 15/16 |

- タッチありの M は**ぴったり 0 本**。V21-未決-14（DIRECT）やミュートの読み返しなど、Pico 直の線が 1 本でも増えると入らない（MCP に載る線なら 1 本まで入る）
- **小さな救い（両案に効く）**: UI の MCP の `INTA`/`INTB` は IOCON.MIRROR＝1 で内部で OR できる（"1 = The INT pins are internally connected"〔MCP23017 DS p21 Register 3-6〕）。`ENC_INTB`（GP17）が空き、タッチありの M でも残り 1 本になる。ファームの読み方（どちらのポートの割り込みか）は INTF を読めば分かる〔推論〕

**P1（Pico 2 個）**

| | Pico-A タッチあり | Pico-A タッチなし | Pico-B |
|---|---:|---:|---:|
| 使える（空き） | 5 | 9 | 23（26 − ADC 3） |
| スタックへの出力 10・`RAIL_OK`・`PG_N`・`PD_12V_SW` | — | — | 13 |
| ミュート・DIRECT | — | — | 0〜4 |
| 2 個の間の UART（Pico-A は GP4＝UART1 TX・GP9＝UART1 RX〔DS p19 Table 3〕） | 2 | 2 | 2 |
| Pico-B の RUN を Pico-A から落とす線（任意、オープンドレイン、§4） | 0〜1 | 0〜1 | — |
| I²C を分ける（P1 では**任意**、§3.4） | 0〜2 | 0〜2 | — |
| **残り** | **0〜3** | **4〜7** | **4〜8** |
| ADC | 0/3（`DEST_ADC` も不要） | 0/3 | 3/3（`MON_P`・`MON_N`・LM4040） |

- P1 は**どちらの Pico にも余りがある**。制御 MCP は要らない

**P2**: Pico-A は I²C を分ける 2＋UART 2 ＝ 4 本（タッチありで残り 1）、Pico-B は `MON`×2・LM4040（ADC 3）＋`RAIL_OK`・`PD_12V_SW`・`PG_N`・MCP の RESET・UART 2 ＝ デジタル 6 本。入るが、**MCP と Pico の両方を足す**ので部品が最も多い

**P3**: Pico-A から I²S 3・`ADC_nMR` 1 が抜けて空きは 9（タッチなし 13）。要るのは 13＋ミュート・DIRECT 0〜4＋UART 2 ＝ 15〜19 → **タッチなしでも入らない**。制御 MCP が結局要るので A1 の答えにならない → **棄却**

**ADC の空き**: 1 個の Pico では LM4040・`MON_P`・`MON_N` でちょうど 3/3（[DER] §1.8）。P1 では Pico-A の ADC 3 本がまるごと空き、計測・保守に使える（例: `PD_12V_SW` をアナログでも読む、など〔推論〕）

## 3. 安全の向き（課題 2）— リセット・ハング・BOOTSEL・USB だけ・片方だけ電源

### 3.1 DS で確かめた RP2350 の事実

| 事実 | 出典 |
|---|---|
| 最初の電源投入で Bank 0 の IO は「出力バッファ Hi-Z・入力バッファ無効・プルダウン・分離ラッチはラッチ状態」 | 〔RP2350 DS PDF p589 §9.3〕 |
| pad がこの状態に戻るのは「ブラウンアウト・RUN を Low・SW-DP CDBGRSTREQ・RP-AP rescue reset」。分離ラッチがラッチ状態なら PADS/IO のレジスタのリセットでは物理的に戻らない | 〔PDF p590 §9.3〕 |
| 分離ラッチ自体は POR・BOR・RUN・CDBGRSTREQ・rescue でリセットされ、IE は 0（入力無効）に戻る。ISO ビットは RESETS による PADS のリセットでは戻らないが、「PADS のリセットは分離していない pad をリセット状態に戻す」 | 〔PDF p597–598 §9.7〕 |
| ウォッチドッグは PSM を WDSEL で選んだ段から再実行する。PSM の段に RESETS（WDSEL bit 4）があり、PSM の手順の 5 番は「master subsystem reset を外すが個々のサブシステムのリセットは外さない」。サブシステムのリセット対象に PADS_BANK0・IO_BANK0 がある | 〔PDF p499–500 §7.4.1・§7.4.3、p502 Table 532、p504 §7.5〕 |
| pico-sdk の `_watchdog_enable()` は PSM_WDSEL を「ROSC と XOSC 以外すべて」に設定する（DS に SDK の抜粋が載っている） | 〔PDF p1195 §12.9.6.1〕 |
| RP2350-E9: 入力有効・出力無効で pad が VIL〜VIH の間にあると約 120 µA が湧き約 2.2 V に居座る。内部プルダウンは負ける、外付け 8.2 kΩ 以下なら勝つ、**プルアップは効く**。「PoR・RUN のリセット直後は IE がクリアなので影響しない」。A2 で起き、A3 で直った | 〔PDF p1367–1369、p1368 は画像で確認〕 |
| VIL max 0.8 V・VIH min 2.0 V（IOVDD 3.3 V）、内部プルダウン 36〜113 kΩ、プルアップ 32〜86 kΩ、IOVDD からの総ソース 100 mA | 〔PDF p1340–1341 Table 1436〕— [DEC] §5-7 前提の「VIL/VIH のページは未照合」はこれで照合できる |
| "GPIOs are 5 V-tolerant (powered) and 3.3 V-failsafe (unpowered)"。FT の VIH 上限 5.5 V は「IOVDD must be powered to tolerate input voltages above 3.63V」 | 〔PDF p14、p1341〕 |
| BOOTSEL の USB ドライブの「活動表示」の GPIO は、再起動の呼び出しの引数で有効にしたときだけ | 〔PDF p397〕 |

**読み**: RP2350 の pad の「リセット状態」（Hi-Z・入力無効・プルダウン）は、MCP23017 の POR 状態（全ピン入力 IODIR＝1111 1111・OLAT＝0〔MCP23017 DS p16–17、[sw] §4〕）と**同じ形**。どちらも「出力を放す」で、線の 0 は**外付けのプルダウン**が作る。内部プルダウン（36〜113 kΩ）は E9 と無関係でもノイズには弱いので、どちらの案でも外付けは要る〔推論〕。

### 3.2 起こる形ごとの比較

凡例: 「0」＝全コイル線と `RAIL_OK` が外付けプルダウンで 0 に戻る（娘の側では `RAIL_OK` の立ち下がりで単安定 → 音声 RESET、[DEC] §5-3・§5-4。ただし `+5V_COIL` があるとき）。

| 形 | M（Pico＋制御 MCP） | P1 の Pico-B（制御） | P1 の Pico-A（UI） |
|---|---|---|---|
| 電源投入・BOR・RUN・SWD のリセット | Pico の pad が Hi-Z → MCP の RESET がプルダウンで Low → MCP が全ピン入力 → **0**。段は 2 つ | pad が Hi-Z → **0**。段は 1 つ | スタックに触れない。UART の受け側（Pico-B）は無音の線を見る |
| ウォッチドッグ | SDK の既定なら RESETS の段まで戻り PADS がリセット → MCP の RESET が落ちる → **0**〔DS p1195・p499・p502・p504 からの推論〕 | 同じ条件で **0** | 同じ。スタックはそのまま |
| MicroPython のソフトリセット（Ctrl-D） | pad も MCP もそのまま〔推論、どちらのリセットの一覧にも無い〕→ 起動の最初で出力を 0 に | 同じ | スタックに影響なし |
| ハング | Pico の出力も MCP の出力も固まる（パルスの途中なら通電のまま）。WDT が上の行に変える | 同じ（Pico-B の WDT） | **スタックは止まらない**。Pico-B の監視（`MON` → `RAIL_OK`）は動き続ける |
| BOOTSEL（書き込み） | リセットから入るので **0**。書いている間、音は全リセットのまま | 同じ（Pico-B を書くときだけ） | **Pico-A を書き換えても音は止まらない**（PT2314E はレジスタを保つ〔推論〕） |
| デバッガで停止 | 出力が固まる。B1/B2 だけが守る（[DEC] §5-3 前提） | 同じ（Pico-B を止めたとき） | UI を止めてもスタックは生きている |
| I²C の途中の失敗（書きかけ・バスの固着・High の低下 [DER] §1.10） | 起こりうる。**MCP の出力が意図しない値になる形**がある（書きかけの OLAT）。I²C を分けて減らす | **形が無い**（GPIO 直） | UI の MCP だけの話 |
| 主電源 OFF・USB だけ | Pico と MCP は USB で生きる。**線を 0 に保つのはファームの規則②**（[DEC] §5-7）。ファームが間違えれば、電源の無い娘の論理へ 3.3 V が入る（Ioff が要る、[DEC] §2-15 前提） | Pico-B を `+5V_D` から給電すれば（§5）**Pico-B は死んでいる → 線はプルダウンで 0**。規則②は構造で守られる | Pico-A だけ生きる。LCD は「主電源 OFF」（Pico-B の応答が無い） |
| 片方だけ電源（Pico-B の電源の枝だけ故障） | — | 線は 0、`MON` は電源の無い ADC ピンへ（上側の抵抗で制限。M で Pico の電源が落ちたときと同じ、[電] 行 170） | 心拍が途切れて LCD に故障表示 |

- **結論: P1 の Pico-B は M と同等以上**。同等の根拠は §3.1 の「pad のリセット状態＝MCP の POR 状態」で、どちらも外付けプルダウンで 0 に倒れる。**以上**の根拠は 3 つ:
  1. 途中に I²C と MCP が無いので、「書きかけの OLAT」「I²C の High の低下で PRST を書けない」（[制] #8）という形そのものが無い
  2. 主電源 OFF・USB だけのとき、Pico-B を主電源の後ろから給電すれば制御側の石が**生きていない**。§5-7 の規則②（線を 0 に保つ）と §2-15 前提の「電源の無い石の入力へ 3.3 V」が、ファームではなく電源の配線で守られる
  3. UI・USB・LCD・FFT のコードのハング・例外・書き込み・デバッガ停止が、監視と手順を止めない
- **M が負けない点**: リセットの種類ごとの戻り方（WDT で PADS が戻るか、ソフトリセットで戻らない）は両案で同じ条件に乗る（[DER] C4 のまま）。E9 の扱いも同じ（出力のピンは起きない、入力は ≤ 8.2 kΩ）
- **P1 で新しく増える形**: 2 個の Pico の状態が食い違う（LCD の表示と現物が違う）。これは安全ではなく**表示の正しさ**の問題で、§4 の握手で扱う
- **出力を初期化する順**: M は「OLAT＝0 → IODIR」（[DER] A1）。P1 は「出力の値を 0 に書いてから出力を有効」（SDK の `gpio_init()` は値 0・入力で初期化する〔推論、SDK はリポジトリに無い〕）。そのあいだ pad は入力・IE 有効になりうるが、外付けプルダウンで 0 V にあるので E9 の条件 1（未定義の帯）に入らない〔DS p1368 の条件 1〜4 からの推論〕

## 4. 2 個の間の通信と、片方の死の知り方（課題 3）

### 4.1 何で繋ぐか

| 手段 | 本数 | 良い点 | 悪い点 | 判定 |
|---|---:|---|---|---|
| **UART** | 2 | 全二重、主従が無い、両方向の心拍と状態をそのまま流せる。Pico-A は GP4＝UART1 TX・GP9＝UART1 RX で今の空きに乗る〔DS p19 Table 3〕 | フレームと CRC を自分で決める | **採る** |
| I²C（Pico-B を従） | 2 | 既存のバスに載る | Pico-B を I²C の従にするのが MicroPython で標準かは**確かめられず**。UI・PT2314E のバスと共有すると、[DER] §1.10 の High の低下と誤書き込みが制御に戻ってくる | 採らない |
| SPI | 3〜4 | 速い | 本数が多く、従側の実装が面倒〔推論〕 | 採らない |
| GPIO の並列の握手（番号 4 本＋ストローブ） | 5〜6 | ファーム無しに近い | 本数が多い、状態を返せない | 採らない |

- **向き**: 「スタックの状態の正は Pico-B」。Pico-A は要求（「段 k・ch c へ」「ミュート」「DIRECT」）を送り、Pico-B は結果と状態（手順のどこか、故障の番号、`MON` の読み）を返す。**手順（全リセット → 電源 SET → … → 音声 SET、[DEC] §6-2）は Pico-B の中で完結**し、途中で Pico-A が落ちても最後まで走るか、安全側で止まる〔推論〕。M と同じく手順の原子性は 1 個の石の中にある
- **Pico-A が起動したら**、まず Pico-B に状態を問い合わせる。自分から全リセットを要求しない（Pico-A の書き込み・例外で音が切れないように）〔推論〕
- **受け側のピンにプルアップ**（例 10 kΩ → 自分の 3V3）: 相手がリセット・無電源のとき TX は Hi-Z（§3.1）になり、受け側は入力有効なので E9 の帯に居座りうる〔DS p1368〕。E9 は「プルアップは効く」ので、アイドル＝High の UART と向きが合う。相手が無電源でも pad は 3.3 V-failsafe〔DS p14〕なので、プルアップから相手へは流れ込まない〔推論〕

### 4.2 片方が死んだことを知る・ウォッチドッグの位置づけ

| 誰が | 何で | 見つけたら |
|---|---|---|
| Pico-B 自身 | **ハードの WDT**。餌やりは監視の周回（`MON` を読み `RAIL_OK` を決めた後）の 1 か所だけ | リセット → §3.2 の「0」。これが安全に効く唯一の WDT |
| Pico-A 自身 | ハードの WDT（UI の可用性のため） | Pico-A だけ再起動。スタックはそのまま |
| Pico-A が Pico-B を | Pico-B の状態の報告（心拍、例 100 ms ごと、連番と版番号つき）が例 0.5 s 途切れる | LCD に「制御が応答しない」。任意で **Pico-B の RUN を Low**（オープンドレインの N-FET 1 個。Pico-A のリセット中は pad がプルダウンなので FET は OFF で RUN を放す〔DS p589 からの推論〕）。Pico-B の WDT が効かない形（WDT を有効にする前のハング、餌やりの位置の誤り）の後ろ盾になる |
| Pico-B が Pico-A を | 要求・心拍が途切れる | **何もしない**（今の状態を保つ）。新しい手順を始めないだけ。Pico-A が落ちても音声経路は変わらない（PT2314E はレジスタを保つ〔推論〕） |

- RUN の直結（Pico-A の GPIO → Pico-B の RUN）は**しない**: Pico-A のリセット中の pad はプルダウンなので、Pico-A を書き換えるたびに Pico-B もリセットされ、音が全リセットになる〔推論〕。Pico 2 基板の RUN に内部プルアップがあるかは Pico 2 の DS がリポジトリに無く**確かめられず** → FET の案でも RUN のプルアップを自分で置くかを実装時に確かめる
- 心拍に**版番号**を入れる: 2 個のファームの食い違い（片方だけ書き換えた）を LCD に出せる
- M との比較: M では WDT は 1 個で、UI のハングも監視のハングも同じ WDT がリセットに変える（そのたびに全リセット＝無音）。P1 では UI の不具合が音を止めない

## 5. 電源とグランド（課題 4）

- **Pico-B の電源は `+5V_D` から、自分専用のショットキー越しに VSYS へ**（今の Pico と同じ形 [SF pin D1601・U1607]）。`+5V_D` は `PD_12V_SW` → PPTC 0.5 A → BP5293-50 [電] 行 86、BP5293-50 の出力は最大 1 A〔ROHM_BP5293 DS p1「Maximum Output Current: 1A」〕、今の `+5V_D` の負荷は 0.25〜0.3 A [電] 行 92。Pico-B の消費は Pico 2 の DS が無く**確かめられず**（MCU 1 個分の数十 mA 級と置けば余る〔仮定〕）
- **`+5V_COIL` からは取らない**: Pico の基板の 3V3 はスイッチングと見られ（[制] 新-7〔推論〕）、`+5V_COIL` は全娘へ配られる。[DEC] §3-8 がコイルの 5 V を BP5293 から L7805C へ替えた理由（全娘へ配る線からスイッチングを外す）に反する〔推論〕
- **スタックからは取らない**: スタックに 3.3 V は無い（[DEC] §2-15）。娘の中に Pico-B を置く理由も無い（§6）
- **グランド**: Pico-A・Pico-B とも `D_GND`。スタックの `D_GND` は「Pico からの線の基準」（[DEC] §2-5）で、その Pico が Pico-B になるだけ。2 個を隣に置き UART を短く〔推論〕
- **USB を挿すのは Pico-A**（UI・計測のデータ・ファームの主）。Pico-B の USB は書き込み・デバッグのときだけ（蓋を開けて届く位置に置く）。ショットキーがそれぞれにあるので、どちらの USB も `+5V_D` ともう片方の Pico も給電しない（[電] 行 129 の今の形の読み）〔推論〕。2 本の USB を同じ PC に挿すと PC のグランドを 2 か所で `D_GND` に繋ぐが、隣り合う 2 個の間なのでループは小さい〔推論〕
- **主電源 OFF・USB だけ（Pico-A）**: Pico-B は無電源 → 全制御線はプルダウンで 0、`+5V_COIL` も ±15 V も無い。§5-7 の規則②（線を 0 に保つ）は配線で守られる。Pico-A の UART の TX は無電源の Pico-B の pad へ入るが 3.3 V-failsafe〔DS p14〕
- **主電源 ON**: BP5293 が入力 7 V 以上で立ち〔[電] 行 129、ROHM DS p4〕Pico-B が起動する。起動の数百 ms（**確かめられず**）の間、線はプルダウンで 0、ラッチは前の状態のまま（M と同じ）。**規則①（検知の立ち上がりで全リセット）はふだん「Pico-B の起動」と重なる**
- **それでも検知線は要る**: (i) 12 V の無い充電器で PD が 9 V に落ち着くと（CH224K 説明書 p1「12V のみ対応していないものがあります」、[DER] §1.7）BP5293 は動き Pico-B は起動するので、`PD_12V_SW` の約 10 V のしきい値で「無し」と判断する必要がある（規則②）。(ii) Pico-B に USB を挿して開発するときは M と同じ状況になる。(iii) 電源断の予告。したがって **§5-7 の検知線と規則①②③はそのまま Pico-B に置く**
- **電源断の予告の窓**: `PD_12V_SW` が 10 V を割ってから RS6・L7805C が止まるまで約 0.5〜1 ms（[DER] A2〔計算〕）。M ではこの間に I²C の書き込みは 1〜2 回（1 回 0.29 ms [DEC] §5-2 却下案 (b)）。P1 の GPIO 直なら µs で ミュート・`CH_EN`＝0・`RAIL_OK`＝0 まで出せる〔推論〕。ただし [DER] B6 は「電源断で音声リレーは戻さない」に決めているので、効くのは EN・`RAIL_OK` を先に落とす分だけ
- **片方だけ電源（Pico-B の枝だけの故障、主電源あり）**: 線は 0、`RAIL_OK` の立ち下がりで娘は音声 RESET（`+5V_COIL` はある）→ 無音。Pico-A は心拍の途切れで表示。`MON` は電源の無い Pico-B の ADC ピン（FT ではない〔DS p1336–1337、[DER] §1.8〕）へ入るので、分圧の上側で電流を制限する（M で Pico の電源だけ落ちたときと同じ条件、[電] 行 170）

## 6. 音への影響と置き場所（課題 5）

- [DEC] §2-12 が言っているのは「**聴取中の娘**にクロックのある信号を持ち込まない」。Pico-B を**親のデジタルの区画**（`D_GND` の島、Pico-A の隣）に置き、スタックへ出すのが静的なレベル線だけなら、娘から見て M と区別がつかない〔推論〕
- 静的な線の High の値には駆動する石の電源の揺れが乗る。M の MCP の VDD は Pico の 3V3（今の UI の MCP の VDD＝9 番は `3V3` [SF pin U1610]。制御 MCP も同じ作りなら）なので、**どちらも Pico の 3V3 の揺れ**が乗る〔推論〕。聴取中に High のまま居るのは `CH_SEL`（番号しだい）・`CH_EN`・`RAIL_OK`。気にするならスタックのコネクタの手前に直列 R＋小さな C を置く — **両案に同じだけ効く**足場〔推論〕
- **違うのは親の上**: MCP23017 は I²C が止まっていれば静かな石（DS に発振器の記述が無く、待機電流は max 1 µA〔MCP23017 DS p4 D005〕→ 内部で動き続けるクロックは無いと読む〔推論〕）、Pico-B はいつも動くクロック（水晶・CPU・フラッシュ・基板の電源）を持つ。親のデジタル区画に**動き続けるクロックの塊がもう 1 個**増える。Pico-A がすでに同じものを持っているので、増分は「同じ区画にもう 1 個」〔推論、測っていない〕
- **置いてはいけない場所**: 娘の上、スタックのコネクタのすぐ脇で音声コネクタ（2×5）に近い所、ルートの音声区画（NOW「ゾーン」: 左上＝ルート音声）。UART（1 Mbit/s 級でなくてよい、例 115.2 kbit/s）は親の中だけで閉じ、スタックへ出さない
- `MON_P`/`MON_N` は生のレール（約 ±14 V）の線で、分圧は親（[DEC] §5-2）。Pico-B をスタックのコネクタ寄りのデジタル区画に置けば、この線と LM4040 の線が短くなる〔推論〕。ADC のサンプリングの蹴り返しは M と同じ

## 8. 結論（課題 8）

**推奨: P1（Pico-A＝UI・トーン・計測・USB、Pico-B＝スタックの制御専用、間は UART）。M に対して安全は同等以上、本数は両方に余りがあり、負けるのはファームの本数・部品・費用だけ。**

いちばん強い理由（順に）:
1. **リセットで 0 に倒れる形は M と同じ根拠で成り立つ**: RP2350 の pad のリセット状態（Hi-Z・入力無効・プルダウン）〔DS p589–590〕は MCP23017 の POR 状態（全ピン入力・OLAT 0）と同じ「放す」形で、どちらも外付けプルダウンが 0 を作る。M は Pico → MCP の RESET → MCP の 2 段、P1 は 1 段
2. **主電源 OFF で制御側の石が死ぬ**: Pico-B を `+5V_D` から給電すれば、USB だけのとき制御線はプルダウンで 0。§5-7 の規則②と §2-15 前提の「電源の無い娘の入力へ 3.3 V」が、ファームではなく電源の配線で守られる。M では Pico と MCP が USB で生きたまま、ファームが 0 を保つ
3. **制御の経路に I²C が無い**: 「書きかけの OLAT」「±15 V が無いと I²C の High が落ちて PRST を書けない」（[制] #8、[DER] §1.10）という形そのものが消え、**I²C の分割が必須でなくなる**
4. **本数の余り**: M はタッチありで Pico の空きが**ちょうど 0**（MIRROR で 1）。P1 は Pico-A に 0〜3（タッチなし 4〜7）、Pico-B に 4〜8、ADC も Pico-A の 3 本が空く。DIRECT（V21-未決-14）・ミュートの形が決まる前に本数で詰まらない
5. **UI の不具合・書き込み・デバッガ停止がスタックに届かない**

外れる条件（M を選ぶ方がよいとき）:
- **ファームを 2 本持ちたくない**（書き込み 2 か所、2 個の間の取り決め、状態の食い違いの追跡）。安全の上での M の損は小さい（1 の根拠は同じ）ので、これが最も現実的な分かれ目。M を選ぶなら**タッチを捨てるか IOCON.MIRROR で余りを作る**こと（タッチありで 0 本のままにしない）
- Pico-B の USB に手が届く置き場が親に取れない（書き込みのたびに分解が要るなら P1 の利点がデバッグで相殺される）
- 基板の面積が足りない（Pico モジュール 1 枚分）
- Pico 2 基板の事実（3V3 の取れる電流、RUN のプルアップ、起動時間、基板の電源の方式）が悪い方に出る — リポジトリに Pico 2 の DS が無く**確かめられず**

P2（M＋監視用の Pico）は MCP と Pico の両方を足して、手順は依然 I²C 越し — **P1 に劣る**。P3（計測を Pico-B へ）は本数が入らず制御 MCP が残る — **棄却**。

P1 を採るなら DECISIONS で主語が変わる所（**ここでは書き換えていない**）: §2-12 前提（出どころ＝Pico-B の GPIO）、§5-2・§5-3・§5-7（Pico → Pico-B）、§6（ファームの分担と 2 個の間の取り決め、Pico-B の WDT が安全の WDT）、[DER] A1 の「I²C の分割」（任意へ）、V21-未決-26、PARTS（Pico 2 を 2 個）。

## 9. 確かめられなかったこと

- **Pico 2 基板の DS がリポジトリに無い**: 外に出ていない GPIO の用途、3V3 の取れる電流と方式、RUN のプルアップの有無、起動時間、VSYS の扱い。本書の「26 本」はシンボルのピン名の数え
- MicroPython の `machine.WDT` が pico-sdk の `watchdog_enable()`（PSM_WDSEL を ROSC・XOSC 以外すべて〔DS p1195〕）を使うか。使わなければ WDT で PADS が戻らない形がありうる — **M と P1 に同じだけ効く**（[DER] C4）
- MicroPython で RP2350 を I²C の従にできるか（§4.1 で I²C を採らない理由の一つ。UART を採るので結論には効かない）
- 価格（リポジトリに記録が無い）
- Pico-B の常時動くクロックが親の上で聴こえるか（測っていない。Pico-A で同じものがすでにある）
- 手元の Pico 2 の石の版（A2 なら E9 あり、`CHIP_ID.REVISION` で読める〔DS p1355–1356、[DER] §1.2〕）
