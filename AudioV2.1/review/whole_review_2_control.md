## 2. 指摘の本文

### C-01（損傷／まれ・実装の誤り）UI の MCP で 3 線を「続けて書く」と、番地の自動加算でレジスタ表を一周する

- **種類**: 決定の穴。**場所**: §1-6 の 2・4（3 線は UI の MCP から、16 ビットに約 4 ms）。§2-16 の足すもの 2（1 レジスタずつ書く）は制御 MCP だけ
- **何が起きるか**: 速さのために 1 回の I²C 転送で OLATB に 35 バイトを続けて送ると、SEQOP の既定（0＝自動加算）では 2 バイト目から番地が進み、BANK=0 の最後の番地 OLATB（15h）の次は 00h（IODIRA）に戻る。35 バイトで 22 本のレジスタを一周し、IODIRA/B・IOCON（0Ah/0Bh）・GPPU・OLATA/B に 3 線のビット列が入る。ポート A（エンコーダ）の一部が出力になり、OLATA の 1 のビットで High を出す。エンコーダの A/B は MCP に直結で接点の相手は `D_GND` なので、閉じている接点が出力を GND へ短絡する。IOCON に BANK=1 が入れば以後の番地の意味が変わり、3 線に化けた値が出てラッチされうる（C-04 の +31.5 dB にも届く）
- **根拠**: 自動加算と 00h への巻き戻し、BANK=0 の Byte mode は A/B の組を交互に指す〔MCP23017 Rev C p13 §3.2.1・§3.2.2.3〕。BANK=0 の番地表（OLATB＝15h が最後）〔p16〜17 Table 3-3・3-5〕。SEQOP の既定 0〔p20〜21〕。出力の絶対最大 25 mA／ピン〔p3〕。エンコーダの B 相 → UI の MCP、共通 → `D_GND`〔SF pin ENC1603、nets ENC1_A〕。前の査読は「Byte mode（BANK の設定に注意）で 1 語 約 1 ms」を勧めた〔[TCBR] 44 行・121 行〕。短絡のときの電流は DS に無い〔確かめられず〕
- **外れる条件**: ファームが 1 回の転送で 1 レジスタしか書かない（400 kHz で約 4 ms／語で足りる）か、流す前に SEQOP=1 を書く
- **直し方**: UI の MCP の初期化で IOCON.SEQOP=1。BANK=0 のままなら OLATB・OLATA を交互に送る（OLATA には GPA7 など出力の値を入れる）。BANK=1 にするなら UI のコードの番地をすべてそちらに揃える。流したあと IOCON・IODIRA/B を読み返す。安い保険にエンコーダの A/B/SW へ直列 330 Ω〜1 kΩ（`FrontPanel` は手で直してよい）
- **ユーザー判断**: 不要

### C-02（聴こえる／ふつう）DIRECT の「チップの音量を MUTE → TSW を書く」は DS の注と逆

- **種類**: 決定の誤り（DS の読み）。**場所**: §1-6 の状態の欄（DIRECT は NJW1194 のスルー）・前提、§2-10 前提
- **何が起きるか**: 聴取中（音声リレーは閉じたまま）に DIRECT を倒すと、音量段より後ろにある切替点の段と切替の雑音が、そのまま `TONE` バス → 娘（利得 2 程度）→ `AMP_SEL` → HP/LINE に出る。チップの MUTE はこの点を覆わない。DIRECT を倒すたびに起きる。大きさは不明
- **根拠**: 日本語版 DS p8「注：TONE 設定の ON/OFF 切換時は、IC 後段で MUTE をかけて使用されますことを推奨いたします。」（Ver.11.3、テキスト層で読んだ）。英語版 p8 の "use MUTE on the set"（Ver.7.4）も機器の側と読める〔推論〕。英語版 p11 はチップのミュートを "MUTE setting" と書き分けている。切替点が音量段より後ろなのは §1-6 前提自身の読み
- **外れる条件**: 実物で、チップの MUTE だけで TSW を倒しても出口で段も雑音も聴こえないと測る（C-14 の 2）
- **直し方**: 既定を「全リセットの中（音声リレーが開いている間、S2 の直後）で TSW を書く」にし、今の形は実測で問題が無かったときの近道にする。そのとき DIRECT の切替は切替 1 回＋TSW の段の整定（§1.3）。別の形はポットの前の GND 落とし（§2-10 の足場）を DIRECT の間にも使う（実装が要る）。§1-6 の「DS の『TSW を切り替えるときはミュートを使う』（p8）に従い」の理由も直す
- **ユーザー判断**: 要（DIRECT の切替の時間とクリックの兼ね合い、GND 落としを実装するか）

### C-03（聴こえる／まれ）±15 V だけが落ちて戻ると NJW1194 が黙って初期値に戻り、ファームは知らない

- **種類**: 決定の穴。**場所**: §1-6 の 4（規則①で全レジスタを書き直す）、§5-7 規則①、§6-2
- **何が起きるか**: ±7 V は ±15 V からの LDO で、±15 V は `PD_12V_SW` が残っていても RS6 の保護で落ちうる。例: 石の逆挿し・ソケット短絡で ch の LDO が電流制限に入ると、+15 V の常時の負荷（約 90 mA）と足して 310〜590 mA で、RS6 の過負荷保護（150 %＝300 mA）を越える。保護がヒカップ型か深く垂れる形なら NJW1194 は動作範囲（±4.5 V）を割り、初期値（音量 MUTE・入力 MUTE・TSW＝0）に戻る〔推論〕。規則①は検知の立ち上がりと Pico の起動でしか走らず、どちらも起きないので、ファームの持つ状態は古いまま。次の書き込みが音量だけなら入力 MUTE のまま無音、全部を書けば段階の戻しなしで一気に鳴る（無音の間にポットを上げていれば大きく出る）。§1-6 の 7 の整定待ちも飛ぶ。LCD の Bass/Treble/DIRECT は実際と違う
- **根拠**: 電源投入で MUTE・初期値〔NJW1194 p11、画像で確認〕、動作電圧 ±4.5 V min〔p3〕、書き込み専用〔ds_facts/njw1194.md §2〕。TPS7A49 の電流制限 220/309/500 mA〔pow、TPS7A49 p6〕、RS6 の OLP "150% load, continuous, automatic recovery"〔pow、RS6 p5〕、常時の負荷〔DER §1.4〕〔計算〕。OLP の形は未測（V21-実測-01）。前回の要件「±15 V が戻るたびにトーンチップを書き直す」（[DER] §3 B8 #7）は PT2314E の形のまま DECISIONS に入らず、§1-6 の 4 は規則①だけ
- **外れる条件**: RS6 の保護が定電流で、NJW1194 の電源が動作範囲に残る（内部の論理は V− から作る〔p6〕ので、+15 V だけの崩れなら設定を保つ見込みもある〔推論〕）
- **直し方**: ファームの規則に「`MON` の崩れ（レールの異常）を見たら、トーンチップを『状態不明』にし、次の音声 SET の前に MUTE から全語を書き、§1-6 の 7 の整定待ちからやり直す」を足す。切替の窓（どの娘もつながっていない間）の崩れは `MON` に見えないので、切替のたびに S11 の前に全語を書く。任意でハード: UI の MCP の空きの入力で ±7 V の有無を読む（抵抗 2 本）
- **ユーザー判断**: ハードの任意の 1 本だけ（小）

### C-04（聴こえる／まれ・ファームの誤りか化けた語）音量の符号は MUTE の隣が +31.5 dB

### C-05（聴こえる／まれ）3 線の待機の電位・プル・LATCH の扱いが決まっていない。UI の MCP は Pico のリセットに追従しない

- **何が起きるか**:
  - (a) 主電源を入れると NJW1194 は約 20 ms で立つが、UI の MCP は Pico が設定するまで全ピン Hi-Z（P3）。3 線（AHCT を載せればその入力）が浮く。NJW1194 の論理入力にプルは無い

- **外れる条件**: —（どの形でも待機の電位は決める必要がある）
- **直し方**:
  - ハード: LATCH・DATA はプルダウン（LATCH が要）。CLOCK はプルアップ（3.3 V 直結なら 3V3 へ。USB だけで MCP が Hi-Z の間は電源の無いチップに 3.3 V が掛かるが、V+ へのダイオードが無いので受ける〔推論〕。AHCT を載せるなら入力側と出力側の両方にプル、AHCT の電源の Ioff は DS 未収集）
  - ファーム: LATCH は 16 ビットを新しく送った直後にしか上げない／検知が無い間は 3 本とも Low、±7 V が立ってから CLOCK を High／OLATB の書き手は 1 つ（影を持つ。DEST の LED を同じポートに残すなら同じ書き手）／各書き込みの ACK を見て、誤りなら語の頭から送り直す／語の前に UI の MCP の IODIRB・IOCON を読み返す
  - 任意: UI の MCP の RESET を制御 MCP と同じ AND の出力へ。USB だけのときは UI の MCP も止まるが、そのとき LCD はもともと点かない（C-12）
- **ユーザー判断**: 不要（RESET の配線は任意、小）

### C-06（聴こえる／まれ）制御 MCP の読み返しで食い違ったときの戻し方が無い

- **種類**: 決定の穴。**場所**: §2-16 の足すもの 2・4（書いたら読み返す、食い違えば RESET から初期化し直す）
- **何が起きるか**: 食い違いの原因は (1) 3V3 の浅い瞬断で MCP が状態を失った、(2) 検知が短く切れ、AND が MCP を RESET した、(3) I²C の誤り。(2) では AND が同時に `RAIL_OK` を落とし、全娘の単安定が音声リレーを戻している（無音）が、ファームは読み返しの周期の間それを知らない。「RESET から初期化し直す」で OLAT をそのまま戻す（`CH_EN`=1）と、音声リレーが SET の娘で ch の LDO と TMUX が生きたバスの上で立つ（§2-10 が避けたい過渡）。(3) で ASET を 0 に戻す書き込みが失敗したまま、後で `RAIL_OK` を上げると、その瞬間に音声 SET が出る（§2-6 の「手順の中でだけ」が破れる。S8 の前で整定が済んでいない）
- **根拠**: RESET・POR で IODIR＝FFh・OLAT＝00h〔MCP Rev C p16〜17〕。音声 SET ＝ ASET ∧ `RAIL_OK` ∧ ¬(ARST ∨ Q)〔DEC §5-8〕。`RAIL_OK` の立ち下がりで単安定〔§6-1〕。AND の形〔§2-16 足すもの 1〕。PD の再交渉で 12 V が一瞬切れるかは確かめられず〔§3-13〕
- **外れる条件**: 検知の短い切れも I²C の誤りも起きない
- **直し方**: 規則にする: 「食い違い・I2C1 の誤りを見たら、Pico の GPIO で制御 MCP を RESET（全線 0）→ `RAIL_OK`=0 → §6-2 を頭から」。`RAIL_OK` を上げる前にパルスの線が 0 であることを読み返す（S8）。読み返しの周期がこの無音の長さの上限になるので周期を決める。検知のピンに端でラッチされる割り込みを付け、短い切れを直接拾う（しきい値の揃えは C-08）
- **ユーザー判断**: 不要

### C-08（無害〜聴こえる／ふつう）規則①の「余裕」の長さ、検知の安定の確かめ、ヒステリシスが無い

- **種類**: 決定の穴／確かめが要る。**場所**: §5-7 規則①・しきい値素子、§2-16 足すもの 1
- **何が起きるか**:
  - (a) 規則①は「RS6 の起動＋余裕の後」にトーンを書くが、±7 V の LDO のソフトスタート（CNR 10 nF なら 14 ms／9 ms〔仮定: ch の LDO と同じ値〕）と、NJW1194 が書き込みを受け付けるまでの時間（DS に無い）が数に入っていない。早すぎれば書き込みは黙って失われ、チップは MUTE のまま（次に全語を書くまで無音）
  - (b) 主電源スイッチのチャタリング・PD の瞬断で検知が揺れると、規則①が何度も走る
  - (c) ツェナー＋分圧の検知にはヒステリシスが無い。PD がしきい値の近くで垂れると、シュミットでない AND の出力が揺れ、`RAIL_OK` と MCP の RESET が揺れ続ける（音声リレーは最初の立ち下がりで開くので音には出ないが、単安定が撃ち続けてコイルに流れ続ける〔推論〕）。AND と Pico のしきい値がずれると、AND だけが反応した短い切れを Pico が見ない（C-06）
  - (d) 主電源を入れた瞬間は検知が Pico の 3V3 より数 ms 先に立つ。AND の入力に Ioff が無いと 3V3 を下から持ち上げ、MCP の POR の条件（VSS から立つ）を崩しうる〔推論〕
  - (e) AND の電源が無い・外れたときの `RAIL_OK` の線の既定（AND の後ろのプルダウン）が書かれていない。§5-3 の「外付けプルダウン」は Pico の直結のころの書き方

- **外れる条件**: 実物で ±7 V が立ってから書き込みを受け付けるまでが短いと測る。検知にヒステリシスつきの監視 IC を使う
- **直し方**: 規則①を「検知が 50 ms 以上続けて有り → さらに 100 ms 待つ → 制御 MCP の初期化（C-09）→ 全リセット → トーンの初期化」にし、最初の切替の S11 の前にもう一度全語を書く。検知はヒステリシスつき（監視 IC、またはシュミットの 1 ゲートを AND と Pico の手前に共通に置き、しきい値を 1 つにする）。AND は Ioff つきの石。`RAIL_OK` の線は AND の後ろにもプルダウン
- **ユーザー判断**: 小（検知の素子の選び方）

### C-10（無害／ふつう）§6-2 の手順に `CH_EN`・`RAIL_OK` の位置と間隔、レール良好の上限が無い

- **種類**: 決定の穴（記述）。**場所**: §6-2 切替の手順、§3-8・§3-13（コイルの同時通電の見積もり）、§3-14
- **何が起きるか**:
  - (a) 前回の案（切替の頭で `RAIL_OK`=0、[制] §2.1 S2）どおりに落とすと、全 4 枚の単安定が音声 RESET を撃ち（8 コイル、29〜40 ms）、§6-2 の例「ARST → 20 ms → PRST」では PRST が重なって 12 コイル（約 560 mA）。B7＝(B) なので毎回の切替で起きる。§3-13 は 12 コイル同時を「故障」の 1.3 A に数え、§3-8 はヒューズを「最悪の同時通電（約 560 mA・30 ms）で切れない」で選ぶと書くだけで、パルスの回数（切替ごと、10^5 回級〔仮定〕）を見ていない
  - (b) `CH_EN` を落とす位置が無い。ARST より前に落とすと、TMUX と LDO の切れる過渡が閉じた音声リレー越しにバスへ出る。PSET の間も `CH_EN`=1 なら新しい娘の同じ番号の ch がレールと一緒に立ち、§6-2「EN を上げる条件」と食い違う
  - (c) PSET の後にレール良好が来ないとき（娘が無い段・ジャンパ違い・22 Ω の開放・ソケット短絡）の上限と抜け方が無く、ファームが待ち続けうる
- **根拠**: 単安定の幅（rail_detect の案で 29〜40 ms）、コイル 46.7 mA〔DER §1.1: 5.25 V ÷ 112.5 Ω、AZ850P2-5 は 5 V・125 Ω ±10 %〔Zettler AZ850 p1〕〕、8×46.7＝373 mA・12×46.7＝560 mA〔計算〕。前回の要件 B8 #4・#6〔DER §3 B8〕が DECISIONS に入っていない
- **外れる条件**: 切替の中で `RAIL_OK` を落とさず `CH_EN` だけで切る（そのとき PRST と重なるのは前の娘の B2 の 2 コイルだけ）
- **直し方**: §6-2 を §1.2 の S1〜S11 の形で書く（`RAIL_OK`・`CH_EN` は ARST の後、PRST はその 40 ms 以上後、PSET の間は `CH_EN`=0、S7 に上限、S8 で読み返し）。L7805C の枝のヒューズは「毎回の切替のパルス」の回数で選ぶ（観点 ① へ渡す）
- **ユーザー判断**: 不要

### C-11（無害／ふつう）所要時間とトーンの応答: 段階の絞り・戻しの分が見積もりに無く、I²C は 100 kHz のまま

- **種類**: 記述の誤り（§6-2 の所要）／決定の穴。**場所**: §6-2（所要 0.25〜0.75 s）、§1-6 の 4（約 4 ms）、`firmware/board.py`（`I2C_FREQ_HZ = 100_000`、PT2314E のための値）
- **何が起きるか**: 1 語は 35 回の書き込み（ビットごとに DATA を置く・CLOCK を下げるの 2 回、最後に CLOCK・LATCH で 3 回）。値は §1.3。今の 100 kHz なら切替 1 回に +0.36〜0.4 s。トーンの 1 目盛りで 5 語全部を書くと 56〜62 ms で、速く回すと追いつかない。1 語の間（最大 12 ms）は UI の MCP の割り込みを読めず、INTCAP は最初の変化しか持たないので、クアドラチャの途中の変化を取りこぼす → BASS/TREBLE を回している最中に目盛りが飛ぶ・逆に進む。変えていないレジスタ（入力セレクタなど）をラッチし直したときに音が出るかは DS に無い
- **根拠**: 3 線の時間はすべて min で µs 級〔NJW1194 p11〕、I²C の 1 回の書き込みは約 29 クロック〔MCP Rev C p13 Figure 3-1〕、INTCAP は割り込みの時点の値を持ち読むまで変わらない〔p23 §3.5.9・p25 §3.6.4〕、`firmware/board.py`・`encoders.py`
- **外れる条件**: C のファームで 1 回の転送で 1 語を送る（0.84 ms／語、C-01 の制約つき）
- **直し方**: I2C0 を 400 kHz に（PT2314E が居なくなったので縛りは無い）。聴取中は変えた 1 語だけを書き、5 語全部は切替の S11・規則①・C-03 のきっかけで書く。目盛りは最新の目標値にまとめる。語の書き込みの合間にも INT を見る。§6-2 の所要を直す
- **ユーザー判断**: 任意（絞り・戻しの長さの好み）

### C-12（無害／ふつう）DIRECT を倒す操作子・表示・状態の保存が決まっていない

- **種類**: 決定の穴。**場所**: §1-6、V21-継-01（ENC×3 押し付き）、NOW「UI」
- **何が起きるか**: DIRECT をどの操作で倒すか（BASS/TREBLE の押し・長押しなど）が無い。DIRECT の間の Bass/Treble の表示（効いていない）も無い。Pico だけの再起動でも規則①が全語を書くので、保存が無ければ Bass/Treble/DIRECT・選んだ ch はファームの既定に戻る。USB だけのときは LCD が点かない（LCD の電源は主電源スイッチの後ろの `+5V_D` からの負荷スイッチ）ので、前回の要件「電源待ちを表示」（[制] F13）は出せない
- **根拠**: `+5V_D` → 負荷スイッチ → `LCD_VCC`〔SF nets +5V_D・LCD_VCC〕、Pico の VSYS から `+5V_D` へは逆流しない向き〔[制] §1.1〕
- **外れる条件**: —
- **直し方**: DIRECT の操作子を決める（例 TREBLE の長押し）。LCD に DIRECT を出し、Bass/Treble を「効いていない」と示す。選んだ ch とトーンの状態をフラッシュに保存し、規則①で戻す（書くのは聴取中を避け、切替の後に。フラッシュの書き込みの間は監視も止まる〔推論〕）。USB だけの表示は要件から外すか、LCD の電源を USB からも取る
- **ユーザー判断**: 要（操作子と、保存するか）

### C-13（無害／まれ）異常のときの振る舞いが書かれていない

- **種類**: 決定の穴。**場所**: §5-7 規則③（止まる）、§6-2（迷惑トリップは未決（推奨））、§5-2（張り付き・`PG_N` との矛盾）
- **何が起きるか・直し方**（5 点）:
  1. 「止まる」の状態が無い → `RAIL_OK`=0・`CH_EN`=0・コイルの線 0・トーン MUTE・LCD に故障、解除は電源の入れ直し、と書く
  2. `PG_N`（B1 の「おおむねある」約 ±7 V）と `MON`（約 10.5／12 V）はしきい値が違い、立ち上がり・立ち下がりの途中はふつうに食い違う → 矛盾の判定は整定の後だけ（例 S9 の間と聴取中）
  3. WDT の餌は、監視と手順の流れが生きているときだけやる（UI の流れだけ生きて監視が止まった形を WDT で拾う）
  4. ADC のピン（`MON_P`・`MON_N`・LM4040）の入力の有効を落とす。E9 の DS の注で、前回の B8 #8。DECISIONS に無い
  5. 再試行は 1 回（§6-2 の未決（推奨）を決める）
- **根拠**: E9 "if ADC channels are being used on a pin, clear the relevant GPIO input enable"〔RP2350 p1369〕、WDT はデバッグ停止で止まる〔p1197〕
- **ユーザー判断**: 要（小: 再試行の回数と解除のしかた）

### C-14（確かめが要る）実物の NJW1194 で測る項目に足すもの

- **場所**: §1-6「実物で測る」（本物か・スルーの切替の段・雑音と THD・電源断の入力電流）
- **足すもの**:
  1. 音量を書いてから効くまでの時間（ゼロクロス検出。DS は機能の名前だけで、待ちの上限・効く範囲・切る手段が無い〔p1、日本語版 p1〕）。低い周波数と無音の入力で。MUTE の後の待ち（C-02）と段階の間隔（C-11）をここから決める
  2. TSW を倒したときの出口の段と雑音を、チップの MUTE だけの場合と音声リレーを開いた場合で比べる（C-02）
  3. ±7 V が立ってから書き込みを受け付けるまで（C-08）。V+ と V− の立ち上がりの差（1.4 と 0.9 ms/nF）で変わらないか
  4. 変えていないレジスタを書き直したときに音が出るか（C-11）
  5. 3.3 V 直結での VIH の余裕（計画済み）に、LATCH・CLOCK のプルをつけた形で起動・Pico の再起動を繰り返して設定が乱れないか（C-05）
  6. 入力に信号を入れたまま電源を入れ、全語の書き直しで正常に戻るか（日本語版 p11 は乱れるものを「コントロールデータ初期値」と書くので戻る見込み。1 回だけ）

## 3. 撤回した疑い

- **Pico のピンが足りない** — 数え直した。タッチあり・MIRROR ありで空き 1 本（[A1R] §1.3 を支持）。NJW1194 の 3 線は UI の MCP の空き（GPB3〜7）から出るので Pico のピンは増えない。C-07 の付け替えも UI の MCP の中で閉じる
- **Pico の再起動で語の途中がラッチされて聴こえる** — `RAIL_OK` の立ち下がりで全娘の単安定が音声リレーを戻し、規則①（起動時にすでに有り）が全語を書き直すので聴こえない（C-05 の (b)(c) は聴取中に Pico が止まらない場合として残した）
- **p11 の「電源 ON の前の入力信号で初期状態が乱れる」は書き直しでは直らない何かかもしれない** — 日本語版 p11 は「コントロールデータ初期値に異常をきたす恐れ」と書き、乱れるのは設定値。§1-6 の 4 の書き直しで受ける決めは DS と合う（C-14 の 6 で 1 回確かめるだけ）
- **EN を先に切ってから PRST にすれば LDO の OUT>IN が消える** — `review/ch_ldo_reverse.md` §3.1 がシミュレーションで効かないことを示している
- **I²C の High が ±15 V の無いとき下がる（[制] #8）** — PT2314E とその 9 V 側のプルアップが外れれば原因が無い。図で BSS138 の組を外すのを忘れないこと
- **E9 で `RAIL_OK`・MCP の RESET が 2.2 V に居座る** — どちらも Pico の出力で、≤ 8.2 kΩ のプルダウンが決まっている（§2-16 基本の形）
- **電源断で `RAIL_OK` が落ちると、崩れていく `+5V_COIL` のもとで誤った SET が出る** — SET は ASET ∧ `RAIL_OK` が要り、どちらも 0。出るのは RESET の半端なパルスだけで、次の投入の全リセットで揃う
- **PD の 5 V の窓で約 3 V の `+5V_COIL` の論理が誤って SET を出す** — 同じ理由（制御 MCP は RESET、`RAIL_OK`=0）
- **検知が揺れて制御 MCP の RESET が揺れると出力が暴れる** — RESET のたびに POR の状態（全ピン入力）に戻るだけ。`RAIL_OK` の揺れは C-08 に残した
- **電源の無い NJW1194 の論理入力に High を入れると V+ を逆給電する** — 等価回路に V+ へのダイオードが無い〔p7〕。形式の定格の話だけ C-05 に残した
- **§1-6 の 7 の 2.4 s を毎回の切替で待つ** — 待つのは NJW1194 の電源が立った後と、TSW を全リセットの中で書くときだけ（[njw1194_io_review] 18 行）
- **デバッガの停止・ハングでパルスが残るとコイルや L7805C が壊れる** — AZ850P2-5 の最大連続は 10 V〔p1〕、ARST が固まっても 373 mA で L7805C は熱保護、両コイル同時は §5-8 のゲートが止める（§2-16 の既知の穴のまま）

**文書の小さな点（観点 ④ へ）**: §6-1 の行「Pico が止まったら全段の音声リセット」はリセット・ブラウンアウトのときの話で、ハング・デバッガの停止では成り立たない（§5-3 前提には書いてある）。§1-6 の 4 の「約 4 ms」は 400 kHz・1 回 1 レジスタの値で、今のファームは 100 kHz。
