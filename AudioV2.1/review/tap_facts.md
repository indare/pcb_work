## 1. v2.1 の現行タップ回路

### 1.1 どこで取っているか

- **タップ点はネット `AMP_SEL_L` / `AMP_SEL_R`** [SF pin U1611: `U1611.3 → AMP_SEL_L`、`U1611.5 → AMP_SEL_R`]。L・R の**両方**を取っている
- MeasureControl 側の名前 `AUDIO_L_IN`/`AUDIO_R_IN` は `AMP_SEL_L`/`AMP_SEL_R` の別名 [SF all「1本のネットに複数の名前」]
- `AMP_SEL_L` に載るピン（18本）[SF nets --net AMP_SEL_L]:
  `J1601.2`, `J_ANA101.7`, `J_ANA301.7`, `J_ANA302.7`, `J_PNL_A1601_1.1`, `J_PNL_A1602_1.1`, `J_RAIL501.1`,
  `K301.7`〜`K304.7`, `R1659.1`, `SW501.2`, `U1611.3`, `U311.7/.10`, `U312.7/.10`（R も同形 [SF nets --net AMP_SEL_R]）
- `AMP_SEL` を駆動するのは TMUX7612 の D ピン（`U311.7 → AMP_SEL_L`、S 側 `U311.6 → CH1_OUT_L`）とリレー `K30x` [SF pin U311]。
  各 ch の出力は `AMP601` → `R602` 47R → `C601` 2.2uF film → `CH1_OUT_L`、そこに `R603` 220k → `A_GND` [SF pin C601/R602/R603]

**出力端子との位置関係**（すべて [SF pin]）:

| 端子 | ネット | タップとの関係 |
|---|---|---|
| `J_RAIL501`（Value「AMP_SEL OUT」） | 1=`AMP_SEL_L` / 2=`A_GND` / 3=`AMP_SEL_R` | **タップと同一ノード** |
| `SW501`（DEST DPDT、FrontPanel） | 共通 `.2`=`AMP_SEL_L` → `.1`=`PHONE_PRE_L` / `.3`=`LINE_PRE_L` | タップは**スイッチの手前** |
| `RV501`（A50k Dual HP）/ `RV502`（A50k Dual LINE） | 上端 `PHONE_PRE_L`/`LINE_PRE_L`、下端 `A_GND`、ワイパ `PHONE_BUF_L`/`LINE_L` | タップは**ポットの手前** |
| `U501`（HP バッファ、Value OPA1652） | `.3`=`PHONE_BUF_L` → `.1`=`HP_OUT_L` → `R501` 10R → `C501` 470uF NP → `PHONE_L` | タップは HP バッファの手前 |
| `J_HP501` | 1=`PHONE_L` / 2=`A_GND` / 3=`PHONE_R` | タップとは別ノード（SW501・RV501・U501 の先） |
| `J_LINE501` | 1=`LINE_L` / 2=`A_GND` / 3=`LINE_R` | タップとは別ノード（SW501・RV502 ワイパの先） |

→ **回路図上のタップは「出力ジャックの直前」ではなく、DEST スイッチ・音量ポット・HP バッファより前の `AMP_SEL` バス**。
`J_HP501`/`J_LINE501` の信号（音量後）は ADC に入っていない [SF]。記録も同じことを言っている:
「計測 ADC のタップは `AMP_SEL_L/R`（**ポットの前**）」[DEC:1198]、「測定タップは母板側で `AMP_SEL` から取るので娘を経由しない」[DEC:4524]。

記録の食い違い（参考）: `J_RAIL501` の Description は「DEST スイッチ(SW501/SW502)の手前…A_GND 極を持つ唯一の音声取り出し口」[ROOT:53642] だが、
回路図に `SW502` は無く（BOM の SW は `SW402`/`SW501` のみ [SF bom]）、`J_HP501`/`J_LINE501` も 2026-09-08 から `A_GND` 極を持つ [ROOT:50540, 49167]。

### 1.2 信号経路（L。R は括弧内の参照）

すべて [SF pin]。値は [SF bom]。

1. **「+」側バッファ `U1611`（OPA1656）ユニティフォロワ**: `.3`(+IN)=`AMP_SEL_L`、`.1`=`.2`=`ADC_BUF_L`（R: `.5`=`AMP_SEL_R`、`.6`=`.7`=`ADC_BUF_R`）。
   出力抵抗なし。入力バイアス `R1659`（`R1660`）100k → `A_GND`
   - 2026-09-07 に復元（v1 の AdcBuffer 相当）。Description: 「バス負荷 1.87k→約30k…v1 の出力 47Ω は対称性のため付けない」[MC:51447]、[DEC:354–400]
2. **位相反転 `U1602`（OPA1656）**: 入力 `R1612`（`R1601`）4.7k 0.1% を `ADC_BUF_L` から反転入力 `.6`（`.2`）へ、帰還 `R1615`（`R1606`）4.7k 0.1%、
   **非反転入力 `.5`/`.3` = `A_GND`**。出力 `.7`（`.1`）
3. **AC 結合** `C1628`（`C1613`）10uF 25V NP: `ADC_BUF_L` → 「+」脚、`C1626`（`C1602`）10uF 25V NP: `U1602` 出力 → 「−」脚
4. **VCOM 基準の反転 LPF ドライバ `U1608`（R: `U1601`）OPA1656**: 入力抵抗 `R1618`/`R1614`（`R1609`/`R1603`）**6.19k 0.1%**、
   帰還 `R1619`/`R1616`（`R1610`/`R1607`）1k 0.1% ∥ `C1632`/`C1627`（`C1620`/`C1609`）1.8nF C0G、
   **非反転入力 `.3`/`.5` = `VCOML`（R: `VCOMR`）**
5. **直列 47Ω** `R1617`（`R1608`）→ `VINL+`（`VINR+`）、`R1613`（`R1602`）→ `VINL−`（`VINR−`）
6. **ADC `A1601`（ADC1804_F / PCM1804 モジュール）**: `.1`=`VINL+` `.2`=`VCOML` `.3`=`VINL−` `.4`=`VINR−` `.5`=`VCOMR` `.6`=`VINR+`、
   `.12`=`+5V_A` `.13`=`+3V3_A` `.14`=`ADC_GND`
   - `VCOML`/`VCOMR` の載るピンは各4本のみ: `A1601.2`, `C1607.2`（100nF → `ADC_GND`）, `U1608.3`, `U1608.5`（R: `A1601.5`, `C1615`, `U1601.3/.5`）[SF nets]
   - PCM1804 DS: VCOML/VCOMR = 「analog common-mode voltage (2.5 V)」、フルスケール「differential input 5 Vp-p」（`AudioV2.1/datasheets/TI_PCM1804.pdf`、pdftotext で確認）

図上の注記: 「チャンネルあたりの公式リファレンス構成: 入力インバータ + ADC VCOM 基準の反転 LPF ドライバ×2」[MC:44297]、
「6.19k/4.7k 網（前段入力抵抗は 2026-09-07 に 3.3k→6.19k）」[MC:44308]。記録では Figure 44「Application Circuit for Single-Ended Input」の逐語コピー（抵抗値のみ変更）[DEC:300–301, 404–425]。

**定数から出る量**（[計算]。記録の値と一致するものは併記）:
- 枝ゲイン 1k/6.19k = 0.1616、差動ゲイン 0.323 [DEC:424–425 と一致]
- ADC FS のバス換算 = 1.768 Vrms ÷ 0.323 = 5.47 Vrms [DEC:426 と一致]
- LPF 極 1/(2π·1k·1.8nF) = 88.4 kHz、HPF 1/(2π·6.19k·10µF) = 2.57 Hz [DEC:420 と一致]

### 1.3 シングルエンドか差動か／GND の運び方

- **タップはシングルエンド。** MeasureControl シートの界面は `AUDIO_L_IN`・`AUDIO_R_IN`・`A_GND`（1本、bidirectional）で、
  音声専用の帰り・センス線は無い [ROOT:54259, 54269, 54279 のシートピン／MC:50046, 50145, 50189 の階層ラベル／SF iface 不一致 0]
- 差動化は MeasureControl 内で行う: 「−」脚は `U1602` が作り、その基準は **`U1602` の +IN に繋がった `A_GND`**（`U1602.3`/`.5` → `A_GND`）[SF pin U1602]。
  `A_GND` は 156 ピンの単一ネット（ジャックの `J_HP501.2`・`J_LINE501.2`・`J_RAIL501.2`・`J_IN401.2`、DC-DC の `U201.5` などと同じ）[SF nets --net A_GND]
- ADC 側の基準は `ADC_GND`（`A1601.14`）と VCOM。`ADC_GND` と `A_GND` を結ぶのは **`NT1601` の1点だけ**（`NT1601.1`=`ADC_GND`、`.2`=`A_GND`）[SF pin NT1601]。
  `ADC_GND` の26ピンに `A_GND` 側の部品は無い [SF nets --net ADC_GND]
- 記録の読み: 「`U1602`（位相反転）の `+IN` が `A_GND` なので、Vg は両ブランチに係数 1 で乗り、原理的に純コモンモードになる」[DEC:301–302]。
  除去比は「+」「−」両脚の源インピーダンス対称で決まり、バッファ後 20 Hz〜20 kHz で約 43 dB（理想オペアンプ・集中定数、**確度: 中**）[DEC:304–316, 368–370]
- `J1601`（Value「AUDIO」、Phoenix MKDS 2P）は `.1`=`AMP_SEL_R`、`.2`=`AMP_SEL_L` で **GND 極が無い** [SF pin J1601、MC:55180 付近の FP]。
  v1 モジュールの外部端子の名残（`R1659` Description「J1601 を抜いても入力が浮かない」[MC:53519]）

## 2. タップが本線に掛ける負荷

**タップ単体**（[計算]、定数は [SF bom]、DS は `AudioV2.1/datasheets/opamps/TI_OPA1656.pdf` Electrical Characteristics「Common-mode 6 || 1.9 (10^12 Ω || pF)」を pdftotext で確認）:
- `R1659` 100k ∥ OPA1656 同相入力 6×10^12 Ω ∥ 1.9 pF ≈ **100 kΩ**（容量は数 pF ＋配線）。L・R それぞれ

**`AMP_SEL` バス全体**（選択中の1 ch から見た負荷、[計算]）:

| 構成 | 並列要素 | 合成 |
|---|---|---|
| タップ無し | `RV501` または `RV502` 50k（SW501 で片方）∥ 選択 ch の `R603` 220k | 40.7 kΩ |
| **現行（タップあり）** | 上 ∥ `R1659` 100k | **28.9 kΩ** |
| 2026-09-07 以前（バッファ無し） | 記録値 | 1.87 kΩ [DEC:361] |

- 記録: 「バスから見た負荷 1.87 kΩ → **約 30 kΩ**（`RV501` 50k ∥ `R603` 220k ∥ `R1659` 100k）」[DEC:391]。SPICE は `--rload 30.4e3` で回した [DEC:393]
- 同じ負荷で `TMUX7612` の歪み（`spice/switch_thd.py` のシミュレーション値、実機測定ではない）: THD −90.6 → −111.0 dB、H3 −94.9 → −115.5 dB [DEC:395–400]
- 本線への影響についての記録:
  - 「DUT が見る負荷が 50 kΩ → 1.87 kΩ に変わっており、**全 DUT の動作点が変わる**変更が意図的な判断として記録されていない」（バッファ無し時代の指摘）[DEC:376–377]
  - 「**H3 −94.9 dB は実用律速 −106 dBc より 11 dB 上**…**測定系が測定対象の歪みを持ち上げている**」[DEC:374–375]
  - `AmpChannel` 出力の低域 −3 dB（`C601` 2.2µF と組む）: 39 Hz（バッファ無し）→ 17 Hz（4.7k のみ）／1.78 Hz（タップ無し）[DEC:372]
- **記録の数値の食い違い（[計算]）**: 現行の 28.9 kΩ と `C601` 2.2µF の −3 dB は約 2.5 Hz。`U1611` Description の「低域 39→17Hz」[MC:51447] は現行トポロジ（両脚ともバッファの後）の値と合わない。17 Hz は [DEC:372] の「4.7k のみ」の場合の値

## 3. v1（`Audio/`）のタップ

[SF --root Audio/AudioCase.kicad_sch]。v1 の BOM は 289 個。

- **タップ点**: `AdcBufferModule` の入力 `R804`（`R809`）0Ω が載るネット `L_OUT`（`R_OUT`）。このネットには `C409.2`（470µF、AmpModule 出力カップリング）、`J403.1`（Value「AMP_AUX_OUT」）、`SW101.3`（DEST の DP3T 共通）が載る [SF nets --net L_OUT]。
  README でも「3 | L 極 コモン | Amp L 出力（ADC への分岐と共通）」[`Audio/README.md`:57] → **v1 も DEST スイッチ・ポットより前で取っていた**
- **AdcBuffer `AMP801`（Value OPA1652）ユニティフォロワ**: +IN ← `R804` 0Ω、バイアス `R805`（`R810`）100k → `GND`、帰還 `R801`（`R806`）0Ω、− 入力に `R803`（`R808`）10k → `GND`、出力 `R802`（`R807`）**47Ω** → `AUDIO_L_IN`（`AUDIO_R_IN`）[SF pin]。「Rf=0Ω なのでゲインは 1」[`Audio/README.md`:71]
  - v1 の図では `AMP801.8`（V+）のネットは `AMP801.8` と `C801.1` の2ピンだけ（電源ネットに繋がっていない）[SF nets]。`AMP801.4` は `V-_IN`
- **ADC 前段**: v2.1 と同じ形（`U702` 反転 + `U708`/`U701` の VCOM 基準反転 LPF）。入力抵抗 `R703`/`R709`/`R714`/`R718` が **3.3k 0.1%**、4.7k/1k/1.8nF/47Ω/10uF NP は同値 [SF pin/bom]。v2.1 はここから 6.19k へ変えた [DEC:418]
- **VCOM の扱い**: `VCOML` = `A701.2`, `C707.2`（100nF → `ADC_GND`）, `U708.3`, `U708.5` の4ピン [SF nets --net VCOML]。`U702` の +IN は `GND`（=`A_GND` の別名）[SF pin U702]。
  → **VCOM は2段目 LPF ドライバの +IN とデカップだけに使い、タップ側の基準（`U702` +IN）は `A_GND`。v2.1 と同じ**。
  STATUS にも「VCOM: ADC → 2 段目 OPA の＋、デカップは `VCOM↔ADC_GND`」[`Audio/MeasurementADC_STATUS.md`:119]
  - v1 実機で OPA 未通電時に VCOM が 0.92 V（本来 2.5 V）へ引き下げられた実測 [BU:140–155]、±15V 投入でノイズフロア約 70 dB 低下 [BU:157–165]
- **GND の運び方**: 音声入力 `J701`（Value「AUDIO」）は2P（`.1`=`AUDIO_R_IN`、`.2`=`AUDIO_L_IN`）で **GND 極無し** [SF pin J701]。
  計測モジュールの `GND`（=`A_GND`）に載る外部端子は `J703.2`（±15V 入口の中央）[SF nets --net GND]。
  → 図上、音声の帰りは ±15V 電源線の GND を経由する。`NT701` = `ADC_GND`–`GND`、`NT702` = `ADC_GND_IN`–`D_GND` [SF pin]
  - 実測記録の表現: 「音声接続はシングルエンドで `A_GND` 基準」[BU:438–439]
  - 図上注記は「NT702=A_GND─ADC_GND…NT701=ADC_GND_IN─D_GND」で**番号が回路図と逆**、また「計測経路は PD 基準（非絶縁完成）」[`Audio/MeasurementADC1804_Module.kicad_sch`:5819]
- **v1 の ADC 電源**: `U704` MBC2596-01（IN `ADC_V_IN`、`.2`=`ADC_GND_IN`、`.4`=`ADC_GND`）→ `U703` LT1763-3.3 / `U706` LT1763-5 [SF pin]。
  つまり v1 は PD 12 V から非絶縁バック経由で LDO を給電していた（注記 [`Audio/MeasurementADC1804_Module.kicad_sch`:5730]）

## 4. 実測結果と要求

**⚠ リポジトリ内の実測はすべて v1 実機のもの**（AudioV2/AudioV2.1 に BRINGUP 系ファイルは無い。`ls AudioV2*/BRINGUP*` は該当なし）。
**⚠ 「以下の測定はすべて仮配線・ケーシング未了の状態で行った。…この数字で部品を選ばないこと」**[BU:291–295]。
HANDOFF も「❌ 使ってはいけない（仮組み固有の絶対値）— ベースライン −76 dBc、分解能 −106 dBc といった**絶対値**」[HO:245–248]。

### 4.1 −106 dBc の一次記録（ユーザー決定: ADC 経路の目標＝この値）

**出典は [BU:379–414]「抜き差し対照（2026-09-03）」。** 二次引用は [DEC:344, 349–350, 374, 400, 1110, 4407, 4478]、[HO:1345, 1552, 1603, 1782] で、全部 BU を指している。

条件（記録にあるもの）:
- 日付 2026-09-03、v1 実機（AdcBuffer → MeasurementADC1804、仮配線）
- 試験音: 専用 WAV（`make_tone.py`）1320 Hz、**ADC-L −3.4 dBFS**、連続再生 [BU:297–300]
- DUT: `OPA2134PA`。「**一度抜いて**他の石を通し、再び戻して測り直した」[BU:381–382]
- 1条件あたりのキャプチャ数: 「何も触らず8回」[BU:300]。抜き差し対照の節自体に回数の明記は無い。「測定雑音のみ（8回平均）」[BU:409]
- 解析: 高調波の**複素ベクトル**比較（`Audio/measurement_fw/analyze_thd.py --vs`）[BU:367–369]

結果の記録（逐語）:

```
[BU:384–387]
| 次数 | 同じ石を抜き差し | 判定 |
| **H2** | −101.37 dBc / **4.5σ** | **再現しない。H2 による石の判定は無効** |
| **H3** | −111.99 dBc / 1.9σ | **再現する。使える** |
| H5 | −126.51 dBc / 0.7σ | 再現する。使える |

[BU:405–414]
#### 実用的な検出限界
| 条件 | 3σ 検出限界 |
| 測定雑音のみ（8回平均） | 約 −111 dBc |
| **抜き差し込み（実力）** | **約 −106 dBc** |
| H2 は抜き差しで −101 dBc 動く | **石の判定に使えない** |
**限界を決めているのは測定雑音ではなくソケットの再現性。**
ここを改善する（ソケット交換、接点清掃、ZIF 化など）と直接効く。
```

**何の dBc か:**
- `analyze_thd.py` の定義は `dbc = 20*log10(ah / a1)`（`a1` = 同じキャプチャの基本波振幅）[`Audio/measurement_fw/analyze_thd.py`:161]。
  → **基本波（ADC-L で約 −3.4 dBFS、1320 Hz）に対する H3 の差ベクトルの大きさ**。THD 全体ではなく**高調波ごと**の値で、−106 は **H3** の値（H2 は −101 dBc で動く）
- [計算] 絶対値に直すと −106 dBc ≈ −109.4 dBFS（基本波 −3.4 dBFS）。v1 前段（3.3k、差動ゲイン 0.606）のバス換算 FS 2.92 Vrms [DEC:408] を使うと基本波は約 1.97 Vrms。
  ただし BU は「−16.3 dBFS は AdcBuffer 出力で約 0.27 Vrms」と前段ゲインを入れずに換算している [BU:224–226] ので、Vrms 換算は記録どうしで一致しない
- 意味: 「DUT の寄与が基線に複素加算されるとき、3σ で検出できる差ベクトルの大きさ」（[BU:311–331] の枠組み、関数は [analyze_thd.py:179–211]）。**DUT 自身の歪みの絶対値ではない**（符号・どちらが低歪かは未決 [BU:416–422]）

**導出の記録が無い:**
- −106 がどの式で出たかは BU に書かれていない。関数の 3σ 限界式 `lim = |d| − 20log10(σ/3)` [analyze_thd.py:206] を H3 の対照（−111.99 dBc / 1.9σ）に当てると **−108.0 dBc**、
  雑音の 3σ 限界 −111 dBc と対照の差ベクトル −112 dBc を振幅で線形加算すると **−105.5 dBc**、二乗和なら −108.5 dBc（いずれも [計算]）。記録の「約 −106」に一番近いのは線形加算だが、そう計算したとは書かれていない
- 紛らわしい同値: [BU:354] の表の「−106.1 dBc」は OPA2134 vs NJM5532 の **H2** の 3σ 検出限界で、抜き差しの値とは別物

**n と再現:**
- **抜き差しは1回（同じ石を1回戻しただけ）で、2回目の抜き差しの記録は無い → n=1・未再現**
- 同日の生データはリポジトリに無い（`Audio/measurement_fw/captures/` は `2026-09-07/` のみ）
- 別表現: 「分解能を縛っていたのは機械的再現性（ソケット抜き差しで −112 dBc）」[DEC:3288–3289]（−112 は対照の差ベクトルそのもの）

**−106 / −111 / −117 の並び**（逐語）:

```
[BU:525–530]
−76 dBc    いまのベースライン H3（仮配線由来）        ← 実際に効いているのはこれ
−106 dBc   抜き差し再現性（ソケットの機械的ばらつき）  ← 実用上の分解能
−111 dBc   測定雑音（スパー込み、8回複素平均）
−117 dBc   スパーを消せた場合の測定雑音              ← ここを直しても上3つは動かない
```

- −117 の根拠: 「差の検出限界を約 6 dB 押し上げている（中央値床 −123.9 に対し H2/H3/H5 位置は −117〜−119）」[BU:534]、[BU:190–191]。**推定であり、スパーを消した実測ではない**
- DEC の解釈: 「−106 dBc は機械要因なので、基板を作り直しても同じソケットを使う限り改善しない」[DEC:350]

### 4.4 ADC の用途・目標の記述

- 「**計測器ではない。** 測定系が載っているのは『切替素子が音を悪くしないか』を確かめるためで、その問いには既に答えが出ている（切替素子の歪みは −166 dBc…）」[HO:24–27]、同旨 [DEC:4136–4141]
- 表示: 「スペアナ = Waveshare 29318 LCD」[DEC:29, 61]。実機の Pico の既定は LCD スペアナ版 [HO:1776]
- ヘッドルームと床のトレードオフの判断: 「6.19k で確定（2026-09-08、ユーザー判断）…切替素子の H3 を −115 dB 級で見る用途では床側に効く」[DEC:440–443]
- 比較器としての用途: 「感度は 5.4 dB 落ちるが、比較器としての用途（相対比較）には影響しない」[DEC:429–430]
- 閾値の置き方の記録: 「閾値を −120 dBc（実測ビン床 −117.7 dBFS の 2 dB 下）」[DEC:1275]、「床 −117.7 dBFS・実用律速 −106 dBc に対して各経路が何 dB 下か、で判定する」[DEC:1515–1516]
- **今回のユーザー決定（コーディネータ経由、2026-09-25）: ADC 経路の目標は「ソケット抜き差し再現性の限界＝記録上の −106 dBc」**。上 4.1 のとおり、この値は v1 仮配線・n=1・H3・基本波 −3.4 dBFS 基準

## 5. この経路の絶縁についての記録

- **ISO7741 級デジタルアイソレータ＋絶縁電源で ADC を島にする案は【却下】（2026-09-07）** [DEC:290–352]。理由（逐語の要旨）:
  1. 「`A_GND`↔`ADC_GND` 差（Vg）の除去を律速しているのは絶縁ではない。源インピーダンスの非対称」[DEC:298–320]（後に `U1611` で解消 [DEC:354–400]）
  2. 「島の絶縁性能は DC-DC の絶縁容量が単独で決め、それは今より悪い」— `ISO7741` 級 ≈1 pF、`REC20K-2415DZ` 2000 pF typ、「比は 2000 倍」「ほぼ 0 Ω の意図した1点結合（`NT1601`）を、531 Ω の分布結合に置き換える」[DEC:322–332]
  3. 「動機だったスパーの発生源が未特定」[DEC:334–336]
  - 費用対効果: 「島が最良で触れるのは −111 → −117 dBc で、実用律速より 5〜11 dB 下」[DEC:349]
- 「絶縁を本物にするのは `ISO7741` ＋ ADC 電源の二次側移設とセットで B5。単独で入れてはいけない」[DEC:1340]。理由は I2S 4本が境界をまたぎ、切ると帰路が信号線だけになる [DEC:1326–1338]、Ciso でスイッチング帯は既に結合 [DEC:1342–1351]
- 「絶縁を本物にするなら `ISO7741`（¥448）が要る」「素直なのは逆方向 —— 全部を二次側に寄せ…`ISO7741` も要らない」[DEC:2111–2119]
- WIRING.md との食い違いの表で「方針に合わせる | `ISO7741`（¥448）＋ ADC 側電源を二次側へ。次号 PCB（B5）でまとめてやる」[DEC:3496–3500]
- USB アイソレータ `ADUM3160`: 「買わない」[HO:1397]。ただし A1 の根拠は 2026-09-07 に再現せず「却下の根拠は要再検討」[BU:504–506, 514]、DEC は「却下そのものは維持…理由が入れ替わるだけ」[DEC:2046–2049]
- 絶縁 I²C `ADuM1250` 級: [DEC:2476]（PT2314E 境界の話で、タップ経路ではない）
- **アナログのタップ信号そのものを絶縁する案（絶縁アンプ・信号トランス）は、DECISIONS / HANDOFF / NOW / `Audio/*.md` / `AudioV2.1/review/*.md` を grep した範囲で記述が見つからない**
  （検索語: ISO124, AMC13, AMC3, 絶縁アンプ, アイソレーションアンプ, isolation amp, 信号トランス, ライントランス, 音声トランス。DEC の「トランス」は DC-DC のフライバックの1件 [DEC:674] のみ）
- 関連する別の記述: 測定系の方向性の枝として「b. 差動／計装アンプ入力にする | 同相ノイズの除去 | A1 が指した方向そのもの」[DEC:4135]（2026-09-04、採否の記録は同節に無い）。
  スタック化の検討時の対策候補に「`AdcBuffer` までをアナログ側に置き、`MeasurementADC` へは差動で送る」[DEC:3222]
- v2.1 向けのエージェント査読（一次ではない）: `AudioV2.1/review/rejected_review.md`:27–29, 71–130 が上の却下を v2.1 条件で再評価している。
  そこに「絶縁しても測定タップ（アナログ）は `A_GND` から島へ渡るので、島の境界の Vg はフロントエンドの同相除去で落とすしかない」[rejected_review.md:85]、
  「決めるのに足りないデータ: ADC のデジタル帰り電流（`ADC_GND`→`NT1601`→`A_GND`）が音声側に出ているかどうか。これまでの測定はすべて ADC 自身の床の話で、音声への漏れは測っていない」[rejected_review.md:86]
