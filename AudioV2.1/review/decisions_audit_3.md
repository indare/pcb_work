### いちばん効く「無効」

- **2861 §11.1「電源は常時給電」** — D1 と矛盾する。
- **4660「なぜ電源を切らないか」** — 理由 2 つがどちらも成立しない。LDO で切るので接点を通らない。
- **3601 B0「入力ブロードキャスト＋出力のみ MUX」** — D4 と矛盾する。
- **4076「この構成が要るのは 16ch 以上のときだけ」**と、**3955「6ch×2 は IC 追加ゼロ・電源カットなしで入る」** — D4 で入力の TMUX が要る。12ch の 275 mA は RS6 の ±200 mA を超える。

- **4345「+9V 三端子を使わなくなる理由」** — D3/D5 で理由が消えた。

### いちばん効く「前提変更」

- **電流の上限の数字が ±333 mA（REC10K）のまま**（3815 / 3913 / 3926 / 4029 / 4664）。v2.1 では RS6-1215D の **±200 mA**（ds_facts p1）になり、(a)/D1 で常時負荷は 1ch 分になる。ADC の負荷は D5 で PD 12 V 側へ移る。**ADC1804_F/PCM1804 の負荷は多めに見積もってよい（ユーザー）**。「AK05/LC5 を 1ch だけ挿すと 150 mA」は **TPS7A49 の IOUT max 150 mA** とちょうど同じ値になるので、別途確かめる必要がある。
- **MCP23017 の GPIO の上限**（3052 / 3926）。ch ごとに EN が加わるので、1 個の MCP で扱える ch 数が下がる。
  - スイッチ版: 1 SEL＋1 EN で 8ch まで
  - リレー版: 2 コイル＋1 EN で 5ch まで（EN を正負別々にすると 4ch）
  - v2 の 4ch 娘ならどちらの版も収まる（リレー版は 8＋4＝12 ≦ 16）
- **コネクタのピン数は増えない。** EN・入力 SEL・並列コイルは、どれも娘の MCP と娘の上で完結する（3040 / 3704 / 4509）。J_PWR は v2 ですでに 2×8 で、pin 11..16 の 6 本が N.C.（`build_motherboard.py` 87–96 行）。±15 V のピンの電流は (a) で 1 石分＋TMUX の Iq＋LDO の GND 電流まで下がる。+5V_COIL は D4 のコイル並列で 1ch に 80 mA（125 Ω×2、ds_facts）。
- **B1 の「220k プルダウン撤去」（3569）と、入力スイッチの置き場所（4714）。** 撤去の主な理由「スイッチが無いので不要」は D4 で崩れる。一方、4714 が挙げていた「1 kΩ の負荷で −70 dB」「バイアス抵抗は上げられない」の前提は、B1 の Rb 100k とすでに食い違っている。
- **TONE バスの負荷（4439 / 3829）。** 10ch 並列で 10.0 kΩ だったものが、生きている ch だけになる。PT2314E 出力の 2.2 µF の議論は計算し直しになる。
- **v2 のアースの申し送り（3415）の結合の鎖。** U1604 は v2 で削除済みで、NT1603 が加わっている。D5 で ADC の LDO の帰路が PD 12 V から NetTie の鎖を通る。

### 「却下の再検討」（ユーザーが追加した前提 (a)(b) による）

特に重要なのは次の 5 件。

- **3492 `ISO7741`＋ADC の電源を二次側へ（「方針に合わせる」案）** — 却下された理由は「B5 へ先送り」だけで、**(b) で最有力の復活候補**になる。ただし D5 は ADC の LDO を PD（一次）側に置くので「二次側へ」とは逆向きで、アイソレータの位置は一から決め直す。
- **4827 §7 GND ／ 3433・3449 A6「NetTie を足さない、2 箇所目は閉路になる」** — 却下の理由は、全ドメインが 1 つの電源とグランドを共有していることが前提。(b) でドメインを絶縁すれば「系で 1 点」はドメインごとの規則になり、判定不能。
- **3884 接続方式 B（縦積み）** — 却下の理由（番地の衝突）は、v2 で娘の A0–A2 ジャンパになってすでに成立しない。C（ケーブル）は接点が 2 組になる理由が今も成立し、面積の理由は D9 しだい。
- **3404 Pico を制御側へ移す**、**3363 MeasurePower を別ドメインに切り出す 3 分割**、**4134 枝 a（より良い ADC）** — (b) と D5 でグランドの評価軸が変わるので、どれも判定不能。
- **4630 TMUX4821 の却下理由「OFF 漏れ」** — (a)＋D4 で成立しなくなる（実装の QFN の理由は成立する）。4631/4657 の DG412 は、入力側の候補としてだけ判定不能。

### 道具・手順の注意（v2.1 にも持っていくもの）

- **2×NN ヘッダのピン番号は標準フットプリントの並び**（奇数＝1 列目、偶数＝2 列目）。シンボル `Conn_02x0N_Odd_Even` は縦向きに描かれるが、ピンの隣り合い方は同じ（3760–3763）。
- **ピン割当のテーブルの二重化。** v2.1 の `build_daughter.py` 33 行は `build_motherboard.py` からテーブルを import しているので、スクリプトどうしの二重化はなくなった。ただしルートは手編集所有なので、**手で描いた母板の図とスクリプトのテーブルが食い違っても、ERC でもネットリストでも見つからない**（階層ピン経由でつながってしまう。4535–4541）。別 PCB にすると `hier_label_mismatch` も効かなくなる。
- **⚠ 古い手順。**「シートピンを足したら `build_motherboard.py` の `CHILD_SHEETS` にも足す」（3357）は、今は当てはまらない。ルートのシートシンボルへは KiCad で足す（CLAUDE.md）。
- **新旧どちらの構成も「4 枚」。** 枚数ではなくシート名で見分ける（2996）。WIRING.md は旧 4 枚のまま（3000）。
- **流通品の情報は代理店の掲載による。** 発注前にメーカーの DS で、テール長と嵌合の深さを確かめる（4185 / 4194）。部品の高さは発注前に実測する（3702）。
- **挿抜の注意。** 四隅の M3 を外してから垂直に抜く。指かけを設けるかは PCB で考える（4208）。
- **`digikey_search.py` はキーワード検索しかできない。** パラメトリックに絞るには `FilterOptionsRequest` の対応が要る。API の入手性フィールドは信用せず、`ProductUrl` を開いて確かめる（4308–4310）。
- **TMUX の DS は表を取り違えやすい。** §5.7 が ±15 V、§5.9 が ±20 V で、平坦度の表の条件は VS ±10 V だけ（4700–4705）。OPA1612 の値は typical グラフのベクタ抽出なので、小数点 1 桁の絶対値として扱わない（4599）。
- **28 ピン DIP を 0.600" と決めつけない**（4226）。
- **「買ったこと」を採用の根拠にしない**（4335 / 4356 / 4372）。
- **ERC の期待値の表（CLAUDE.md）は v2 のもの。** v2.1 はパスを明示して回す（4888、NOW.md）。
