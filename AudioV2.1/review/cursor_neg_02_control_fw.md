## 1. 指摘詳細

### 1.1 〔穴／損傷〕娘またぎ「1 枚だけ」は §6-1 に無い

**何が** — §1-2・§1-3・§6-2 は「電源 SET は 1 本」をファーム責務にする。§6-1 の表は B1・B2・デコーダ・排他ゲート・MCP RESET∧検知までで、**PSETk 同士の相互排他は無い**。§5-8 は `PSETk ∧ ¬PRST` のみ。  
**なぜ効くか** — 化けた OLAT／バグで PSET が 2 本立つ、または衝撃で別娘の電源リレーが SET → 最悪 4 枚×1 ch＝+15 V 110 %（§1-3・bulk）。OLP 150 % は働かない。音声は B1 でバスに出なくても、RS6・22 Ω の熱は続く。  
**確度** — 一次（DECISIONS 本文の表の有無）＋二次（design_eval / a1 が同じ穴を「ファームだけ」と書いた）。  
**外れる条件** — 親で PSET を 1-hot ハード符号化する、または衝撃耐性を実測で無視できる、を別途決めたとき。  
**判定** — 穴。§6-1 の「ハードが保証」と §1-3 の語りが噛み合っていない。

### 1.2 〔修正／損傷〕「2 段目が関門」は娘またぎでは成り立たない

**何が** — §1-3: 1 段目故障でも「ch の EN が 2 つ目の関門」。§2-5: `CH_SEL0/1`・`CH_EN` は全段共通。  
**なぜ効くか** — 電源だけ入った 2 枚目は、選んだ ch 番号のデコーダが同じ線を見るので **同じ番号の LDO が 2 系統立つ**（§2-6 前提欄が既に 89 % と書いている）。関門は「娘内 1 ch」だけで「箱全体 1 ch」ではない。  
**確度** — 一次（ネットの共通性は決定文）。  
**外れる条件** — ch 選択線を段ごとにする／電源の無い娘でデコーダ出力を強制 OFF にする別ハード。  
**判定** — 修正。理由文を「娘内の関門」に限定しないと過大。

### 1.3 〔修正〕§2-6「全リセットで弱点が消える」

**何が** — 共通音声 SET の弱点（衝撃で電源ラッチ→B1 通る）を「手順が必ず全リセットから」で消す、と書く。  
**なぜ効くか** — **次の切替**では消える。聴取中は 2 ch 給電が残りうる（バス非接続）。「消える」は時間軸を略している。  
**確度** — 推論（決定自身の前提欄と理由欄の緊張）。  
**外れる条件** — 聴取中の衝撃を要件外と明示したとき。  
**判定** — 修正（文言）。棄却はしない（バス接続の弱点は B1＋手順で閉じる向きは残る）。

### 1.4 〔穴／聴こえる〕電源投入：ラッチ残留 × 規則①の RS6 待ち

**何が** — ラッチは断後も最後の状態（design_eval §1.1・B6、§2-10）。規則①は「RS6 の起動＋余裕の**後**」に全リセット（§5-7）。Pico・`+5V_COIL` は `PD_12V_SW` 直後から動ける。  
**なぜ効くか** — 投入〜全リセット完了の間、前歴で SET の電源リレー経由に ±15 V が入り、音声リレーも SET なら **前 ch がバスに乗る**。無音はトーン音量の段階絞りに依存するが、規則①の「初期化」はその後。GND 落としは切替不使用・電源断は DNP（§2-10）。  
**確度** — 一次（順序の文言）＋二次（電源断で B2 が撃てない計算、design_eval §1.1）。  
**外れる条件** — 検知立ち上がり／起動直後に **ARST→PRST を RS6 より先**に置く、または電源断で音声を戻す保持を実装したとき。  
**判定** — 穴。B6「次投入の全リセットで消す」は残留の**後始末**であり、投入直後の窓を消していない。

### 1.5 〔支持〕切替無音＝全リセット／GND 落とし不使用

**何が** — B7=(B)、§2-10。  
**なぜ効くか** — 境目を動かさない (A) は生きたバスに過渡が出る、というユーザー判断と一致。切替経路のポップは構造で閉じ込められる。  
**確度** — 決定＋design_eval の対立記録。  
**外れる条件** — 所要 0.25〜0.75 s・クリック増が運用不能と実測されたとき。  
**判定** — 支持（切替手順として）。電源断ポップは別穴（1.4・1.5 の裏）。

### 1.6 〔修正〕§2-16「安全は同等」

**何が** — Pico1＋制御 MCP（M）。a1 査読は安全同等・封じ込めは P1 優勢。DEC は M＋足すもの 1〜4。  
**なぜ効くか** — リセットで放す→プルダウンは同等（支持）。残差: (a) UI と制御が同一実行環境（専用 I²C は配線で断てない、§2-16 前提）、(b) パルス終端に I²C 書きが要り PIO ハード幅が取れない（a1 §2.4）、(c) MCP の浅い VDD 瞬断で POR 不定（a1 §2.2）。「同等」は (a)(b)(c) を安全から外した定義のときだけ。  
**確度** — 二次（a1、DS 引用は a1 が画像照合済みと記載）。  
**外れる条件** — 制御を別コア／別プロセスに隔離し、パルスを単安定で最大幅制限したとき。  
**判定** — 修正。「リセット安全は同等、誤操作・固着窓は M が厚い」に落とす。

### 1.7 〔支持＋穴〕§5-8 排他

**何が** — 音声 SET＝ASET∧`RAIL_OK`∧¬(ARST∨Q)、電源 SET＝PSETk∧¬PRST。COMMON＝常時 `+5V_COIL`。  
**なぜ効くか** — B2 単安定中の ASET 重なりと両コイル同時は消える（design_eval A3）。**消えない**: 複数 PSETk、ARST 固着（8 コイル≈373 mA）、ファームが ASET をパルスでなく張り付き。  
**確度** — 一次。  
**外れる条件** — 単安定で最大パルス幅、PSET 1-hot ハード。  
**判定** — 支持（狙い通り）／穴（固着・多 PSET）。

### 1.8 〔穴〕ハード最大パルス幅が無い

**何が** — §2-16 前提・a1 §2.4。WDT 前ハング、デバッガ停止（WDT も既定停止）、Ctrl-C、I²C 閉じ失敗。  
**なぜ効くか** — L7805C に数 W 級が続き熱保護頼み（a1 計算≈2.6 W）。壊れにくいがコイル電源が当てにならない間、規則③や次切替が空振りしうる。  
**確度** — 二次＋推論（熱保護の効きは ST L78 要確認）。  
**外れる条件** — 娘側で SET/RESET 入力を単安定クランプ。  
**判定** — 穴。§5-8 と独立。

### 1.9 〔穴〕MCP POR・読み返し

**何が** — POR は VDD＝0 起点（a1 MCP DS p4）。足すもの 4＝IODIR/OLAT 定期読み返し。  
**なぜ効くか** — 浅い 3V3 瞬断で出力不定のまま残りうる。読み返し失敗・周期より短い窓では未検出。E9 は MCP 出力には無く、Pico の `RAIL_OK`/RESET/検知だけ（B9）。  
**確度** — 二次（a1）。  
**外れる条件** — MCP を監督リセットする外部監視、または P1。  
**判定** — 穴（いったんの決め依存）。

### 1.10 〔穴〕§6-2 に「電源 SET 前に `CH_EN=0`」が無い

**何が** — 手順: 全リセット→PSETk→レール良→ch 選択→整定→音声 SET。`CH_EN` の Low 化が明示されない。  
**なぜ効くか** — 全リセットで娘レールは落ち EN は構造上 0。電源 SET でレール再上昇時、**スタックの `CH_EN` が前値 High のまま**なら、ch 選択の前にデコーダが FET を放す。過渡は音声リレー開中なのでバスには出にくいが、空ソケット禁止（§3-7）や LDO OUT–IN（§3-7）の時間窓を広げる。  
**確度** — 推論。  
**外れる条件** — 実装が全リセット直後に必ず `CH_EN=0`・OLAT 既知値を書くと仕様化したとき。  
**判定** — 穴（手順の抜け）。

### 1.11 〔修正〕B7=(B) と design_eval 推奨 (A)

**何が** — design_eval B7 推奨は (A)＋ミュート。ユーザーは (B)。  
**なぜ効くか** — (B) は §2-6 を構造化し他娘のラッチも毎回消す（理由は成立）。払うもの: 電源リレー往復、0.25〜0.75 s、クリック。電気寿命 2×10⁵（抵抗負荷 1 A）より軽い開閉〔推論〕なので損傷にはなりにくい。  
**確度** — 一次。  
**外れる条件** — 連打で寿命・音が問題になった実測。  
**判定** — 修正（「唯一の安全」ではなく「安全側のトレードオフ」）。棄却しない。

### 1.12 〔修正〕AZ850 に「衝撃でラッチ反転」を載せる

**何が** — §2-1 根拠は G6K/TQ の「リセット出荷・衝撃で変わりうる・初期化せよ」。`boundary`/`verify_boundary`: **AZ850 に同等文言は無い**（衝撃 50 g は動作耐性のみ）。  
**なぜ効くか** — 全リセット方針自体は保険として妥当。DS 制約として AZ850 に帰すと過大。  
**確度** — 一次（ds_facts）。  
**外れる条件** — AZ850 で衝撃反転を実測したとき。  
**判定** — 修正（根拠の帰属）。

### 1.13 〔支持〕`PD_12V_SW`・規則①②③・`RAIL_OK`∧検知

**何が** — §5-7・§2-16 足すもの 1。起動時すでに検知有りを足した訂正（履歴 2026-09-25）。  
**なぜ効くか** — Pico は主電源 SW 後ろ給電で、ふつうの投入では立ち上がりエッジを見ない。①の「すでに有り」が無いと全リセットが走らない。②は AND で配線でも守れる（USB 挿しでも）。③は溶着・コイル欠を `MON` で拾う。  
**確度** — 一次＋ design_eval A2。  
**外れる条件** — 予備 12 V 入口で SW 迂回給電（§5-7 前提）を常用し検知意味が変わる運用。  
**判定** — 支持。1.4 の窓は別問題。

### 1.14 〔支持〕EN≤IN・娘デコーダ既定 OFF

**何が** — §2-9。  
**なぜ効くか** — USB のみ／RS6 停止時の 3.3 V EN 破りを構造で潰す。ファーム規約だけでは足りない、という却下理由は妥当。  
**確度** — DS（TPS7A49 EN–IN）は pow 経由。LVC1G139 Ioff はリポジトリに DS 無し（§2-9 前提）。  
**外れる条件** — デコーダ品が Ioff 無し。  
**判定** — 支持（品 DS 未収集は §3）。

## 2. 見たが問題を見つけられなかったところ

- **音声 SET 共通 1 本＋B1**: レール無し娘は SET コイルに電源が来ない、の論理は閉じる（段ごと SET でも衝撃 SET 音声は消せない、という却下も一貫）。
- **ARST→PRST をファーム順**: バルク無しで壊れはしない、ハード順序は保険（§2-7）— 損傷経路は見当たらない。
- **聴取中に娘へクロックを流さない（§2-12）**: 制御を親静的線にした方針と矛盾しない。
- **§5-6 TBD62083A を 5 V 振幅**: 自動リセットを DS 保証内に戻す向きは妥当（AHCT DS 未収集は別）。
- **E9 を検知テブナン≤8.2 kΩ（B9）**: ゆっくり遷移する入力への適用は a1/design_eval と整合。出力駆動中の `RAIL_OK` に E9 を直結する誤解は既に訂正済み。
