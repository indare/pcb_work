## 1. C-02 — TSW を切り替えるときの MUTE はチップの外

- 言い直し: DIRECT（TSW）を「チップの音量を MUTE → TSW」で切り替えるのは DS の注の読み違いで、DS はチップの後ろでの MUTE を勧めている
- 原文: DS-J p8「注：TONE 設定の ON/OFF 切換時は、IC 後段で MUTE をかけて使用されますことを推奨いたします。」〔DS-J p8、テキスト層〕／"Note.) When switching TSW(Tone Control By-pass Switch), use MUTE on the set."〔DS p8、画像〕
- 根拠:
  1. 語の使い分け: チップ自身の MUTE を DS は「MUTE 設定」「MUTE データを送信して MUTE 設定に」〔DS-J p11〕、"MUTE setting"・"setting MUTE"〔DS p11〕と書く。p8 だけが「IC 後段で」"on the set"（セット＝機器の側）
  2. 構造: 入力セレクタ（MUTE の位置あり）→ 音量の減衰器のワイパ → 2 接点の TSW（上＝ワイパ直、下＝TONE の戻り。TONE の入口も同じワイパの節）→ 出力アンプの＋入力、の順〔DS p1・p8、画像〕。チップの MUTE はどれも TSW より前で、TSW が動いたときの段（2 つの節の DC の差、スイッチの電荷）は覆えない〔推論、図から〕。出力アンプより後ろに MUTE は描かれていない
  3. DECISIONS §1-6 の前提の欄（「切替点そのものの DC の段は残りうる。確実に消すのは全リセットの中」）と `ds_facts/njw1194.md` §3（「セット側で MUTE」）は正しい。[TCBR] と `tone_options_compare_review.md` M1 も「セット側で」と読み、TSW は全リセットの始めに書く案を出していた。ずれたのは §1-6 の状態の欄の「DS の…（p8）に従い、チップの音量を MUTE にしてから TSW を書く」だけ
- 元の指摘との差: 「DS と逆」は言い過ぎで、「チップの MUTE は TSW の上流なので DS の勧める MUTE に当たらない」が正確。段の大きさは DS に無く、聞こえるとまでは言えない
- 直し方の評価:
  - (i) 全リセットの中（ARST の直後）で TSW を書く（C-02 の推し）: DS に合う（開いた音声リレーが「IC 後段の MUTE」）。**C-02 に無い代償**: 今の規則では DIRECT を倒すたびに §6-2 の手順を全部回し、電源リレーも戻すので、選んだ石の電源が切れ冷えた状態から聴き直す（V21-実測-09。DIRECT とトーンを比べるたびに起きる）。リレーの往復と音も毎回。電源リレーを戻さない形（ARST → TSW → ASET）は §2-6 の規則（音声 SET は全リセットから始まる手順の中だけ）を破り、衝撃でラッチした別の娘を共通の SET がつなぐ弱点が戻るので取れない。`TONE` の残りは τ 0.47 s（4.7 µF × 100 kΩ）。ARST の直後に書けば手順の残り約 0.75 s（§8 の整定込み）で 1.6τ は稼げ、段 ΔV を `AMP_SEL` で 0.5 mV（`TONE` で 0.25 mV）以下にする追加の待ちは、ΔV 1 mV なら 0、10 mV なら約 +1 s（47 kΩ なら約 +0.1 s）〔計算: τ·ln(ΔV/0.25 mV)〕
  - (ii) ポットの前の GND 落とし（§2-10 の足場）を DIRECT の切替だけに使う: DS に合い、石は冷えない。代償は足場の実装（ラッチング 1 個・制御 MCP の線 1 本）と、直列 R が聴く経路に入ること（§9）
  - (iii) 今の形: DS の外の近道。実物で段が聞こえなければいちばん安い
  - (iv) DIRECT をトーン 0 dB にして TSW を使わない: 段は消えるが、ユーザーは 2026-09-26 にスルーを選んだ。トーン 0 dB は 100 Hz・10 kHz で ±2 dB max〔DS p5〕
  - 推し: 理由の文の訂正は必須（文書）。既定は C-14 の 2（チップの MUTE だけ／音声リレーを開いた場合の出口の段）を測るまで決めなくても手戻りは小さい。石を冷やしたくないなら (ii)
- ユーザー判断: **要**（いったんの決めの中身が変わる）

## 2. C-07 — MCP23017 Rev D の GPA7・GPB7

- 言い直し: 今の版の DS では GPA7・GPB7 は出力専用で、UI の MCP の GPA7 に入力（TREBLE のエンコーダの B 相）がつながっている
- DS: Rev D p1 "Pins GPA7, GPB7 are output only for MCP23017"、p11 Table 2-1 の GPB7（SPDIP 8 番）・GPA7（28 番）"Output only (MCP23017)"、p18 §3.5.1 の注 "For MCP23017, IO7 must be set via I2C interface to "0" (output)."、p37 改版履歴 Rev D（June 2022）に Features・Table 2-1・§3.5.1 の更新〔すべて画像〕。Rev C（July 2016）の Table 2-1 は GPA7/GPB7 も "Bidirectional I/O pin" だけで注は無い。IODIR の POR 値は Rev D でも 1111 1111（IO7 も入力で立つ）〔Rev D p18〕。理由は DS に無い
- 図: UI の MCP の 28 番（シンボルのピン名 GPA7）＝`ENC3_B`＝TREBLE のエンコーダの B 相〔SF pin U1610.28・ENC1603〕。4〜8 番（GPB3〜GPB7）は空き
- 判定: 支持。「読み出しの誤りが UI の I²C バスで起き、同じバスで 3 線を打つ」は DS に根拠が無い〔確かめられず〕
- 直し方の評価: 安い。FrontPanel（手で直してよいシート）で B 相を GPB3〜6 のどれかへ移し、GPA7・GPB7 は出力（3 線・LED）だけに。両 MCP の初期化で IODIR の bit7＝0。制御 MCP の `PG_N`、§6 の任意の ±7 V の検知は GPx0〜6。付け替え後の空きは I/O 3 本＋出力専用 2 本で、3 線と ±7 V の検知が入る〔計算〕。LATCH を CLOCK・DATA と別のポート（例 GPA7）に置けば、1 回 1 レジスタの書き方（§3）のもとで OLATB の書き損じが LATCH に端を作らない〔推論〕。Rev D はもう `datasheets/Microchip_MCP23017_RevD.pdf` にある
- ユーザー判断: 不要

## 3. C-01 — 番地の自動加算

- 言い直し: UI の MCP に 3 線のビット列を 1 回の転送で流すと、既定の自動加算で番地が 15h から 00h へ回り、IODIR・IOCON まで書き換わる
- DS: SEQOP=0（既定）は ACK ごとに番地を進め、最後の番地の次は 00h〔Rev D p13 §3.2.1、p14 §3.2.2.3〕。SEQOP=1 は番地を進めないが、BANK=0 では A/B の組を往復する（例 12h↔13h）〔p13〕。BANK=0 の表は 00h（IODIRA）〜15h（OLATB）で IOCON は 0Ah・0Bh〔p17 Table 3-5〕、**BANK=1 の表では 15h が IOCON**〔p17 Table 3-4〕。POR で IOCON＝00h、IODIR＝FFh、OLAT・GPPU＝00h〔同〕。出力の絶対最大 25 mA／ピン〔p3〕、短絡電流は DS に無い
- 図: エンコーダの A/B/SW は MCP に直結、共通は `D_GND`、直列 R も外付けのプルアップも無い〔SF nets ENC1_A・ENC3_B・ENC3_SW、pin ENC1601〜1603〕
- 判定: 支持。機構は DS のとおり。損傷は「恐れ」まで〔確かめられず〕
- 元の指摘との差（直し方）: (1) SEQOP=1 だけでは足りない。BANK=0 のまま流すと語は OLATB と OLATA に交互に入る（Rev D で GPA7 を出力にするので OLATA には必ず出力がある）。浅い瞬断は POR を保証しない（VPOR＝VSS〔p4 D002〕）ので、化けて SEQOP＝0 に戻っていれば次の流しは表を一周する。(2) BANK=1 は勧めない。POR で 0 に戻ると番地の意味が変わり、化けて 1 になると「OLATB のつもり」の 15h への書き込みが IOCON に入る
- 直し方の推し: UI の MCP も「BANK=0 のまま、1 回の転送で 1 レジスタ」（§2-16 の足すもの 2 を UI の MCP にも広げる）。1 レジスタの転送は SEQOP に依らず、POR の後も番地が変わらない。400 kHz で 1 語 3.6〜4.6 ms〔計算: 1 回 29 クロック＋ソフトの手間、C-11 を再現〕、段階の絞り 16 語で約 70 ms で足り、流す理由が無い。安い保険にエンコーダの A/B/SW へ直列 330 Ω〜1 kΩ（3.3 V の短絡を 3.3〜10 mA に抑える〔計算〕）
- ユーザー判断: 不要

## 4. C-04／A-02 — 音量の符号と 1 ビットの誤り

- 言い直し: 音量の MUTE は 00h と FFh の 2 つで、00h の隣が +31.5 dB。加減の誤りや語の化けで +16〜+31.5 dB へ跳ぶ
- DS: 00h＝Mute、01h＝+31.5 dB、0.5 dB 刻みで 40h＝0 dB、FEh＝−95 dB、FFh＝Mute（初期値）〔DS p12・p13・p16〕。符号 c（01h〜FEh）は 32 − 0.5c dB〔計算、表と一致〕。番地 D7〜D4 は音量 1＝0000・音量 2＝0001・セレクタ＝0010・Treble＝0011・Bass＝0100〔p11 画像〕。読み返しは無い〔ds_facts §2〕
- 再現〔計算〕: 00h の 1 ビットの誤り 8 通りのうち 6 通りが +16〜+31.5 dB。FFh と 40h の 1 ビットは 8 通りとも 0 dB 以下（40h→00h は MUTE）。番地の 1 ビット（D5 か D6）でセレクタ→音量 1、Treble→音量 2、Bass→音量 1。データはセレクタ Input1＝04h → +30 dB、Treble Cut −3 dB・TSW＝1＝1Ch → +18 dB、Bass Cut −3 dB＝18h → +20 dB。0.2 Vrms の源に +31.5 dB は 7.5 Vrms 相当で、4.2 Vrms typ〔p3〕で頭打ち、ふだんより約 26 dB 大きい
- 判定: 支持
- 補足: 3 線に誤りの検出は無い。入り口は (a) MCP への書き込みの失敗（ACK で見える）と (b) 線の上のひげ（見えない）。(a) は ACK を見て語の頭から送り直せば消える
- 直し方の評価（A-02 の 5 項目）: ①〜④ は部品なしで効く。④ は「DATA を変える書き込みで CLOCK を下げない」で足りる（データは CLOCK の立ち下がりで取る〔p11 時間図、300 dpi の画像〕、t5・t6 は 1.6 µs min）。CLOCK を上げる書き込みで次の DATA を置くのは構わない〔推論〕ので 1 ビット 2 回で済む。⑤ 聴取中の定期の書き直しは、変えていない語を書き直して音が出ないか（C-14 の 4、DS に無い）を実物で確かめてから
- 追加の安い手〔推論〕: セレクタの語の don't care（D15〜D13・D9・D8）を 1 で送ると、番地が化けて音量の語に入っても E7h（−83.5 dB）。Bass/Treble の 0 dB を Boost 0 dB（D15＝1）で送ると化けても −32 dB 以下。Cut の設定だけは守れない
- ユーザー判断: 不要（§6-2 にファームの規則として）

## 5. C-05・N-2・P-12 — 3 線の待機のレベル、プル、バッファの電源

- 言い直し: (C-05) 3 線の待機の電位・プル・LATCH の扱いが決まっていない。UI の MCP の RESET は 3V3 直結で Pico のリセットに追従しない。(N-2) DS は待機中の CLOCK を High にと書くのに、前の推奨は 3 本ともプルダウン。(P-12) バッファを載せたときの電源の領域が決まっていない
- DS（NJW1194）:
  - 注 "Set CLOCK in High to prevent incorrect operation during a standby period."〔p11 画像〕／「誤動作を防止するため、CLOCKは必ずHighで待機するように設定してください。」〔DS-J p11〕
  - 時間図〔p11、300 dpi〕: CLOCK は前後とも High。データは CLOCK の立ち下がりで取る。LATCH は語の前に落ち（t7 ≥ 1.6 µs で最初の立ち下がり）、語の間 Low、最後の立ち下がりから t4 ≥ 4 µs で上がってラッチし、t8 ≥ 1.6 µs の後 **Low へ戻って終わる**。実装例 2 つ（DS ではない）は LATCH を High で待たせている。どちらの待機でもラッチは立ち上がり
  - ロジック入力の等価回路〔p7 画像〕: パッドから V−(sub) へダイオード、パッドと V−(sub) の間にベースを 8 kΩ で落としたトランジスタ（ESD のクランプと読める〔推論〕）、4 kΩ を通って V+ の電流源で動く差動対のゲート。V+ へのダイオードとプルは無い〔ds_facts §2〕。電源が無いときに 3.3〜5 V の High が来ても、描かれた経路は逆向きのダイオードとクランプとゲートだけで、V+ を押し上げる経路は見えない〔推論〕。形式の上では VIH max＝V+〔p5〕を外れ、VIM（V+/V−）がロジック入力に掛かるかは DS に無い〔verify_njw1194 §7〕
- DS（MCP23017）: POR で IODIR＝FFh（全ピン入力）・OLAT＝00h・GPPU＝00h〔Rev D p17〕。POR が保証されるのは VDD が VSS から 0.05 V/ms 以上で立つときだけ〔p4 D002・D003〕。RESET の Low から 1 µs 以内に Hi-Z〔p5 TIOZ〕
- 図: UI の MCP の RESET（18 番）＝`3V3`〔SF pin U1610.18〕
- 判定: C-05 支持、ただし (b)「聴取中に MCP が状態を失ってずれた語がラッチされる」は弱める。LATCH をプルダウンにすれば、入力に戻った MCP では LATCH に立ち上がりが来ない。残るのは、化けた出力で同じ瞬間に CLOCK が落ち LATCH が上がる形と、語の途中（1 語 4 ms 級）で化ける形だけで、どちらもまれ。N-2 支持（[TCBR] 44 行の「3 本に外付けのプルダウン」は CLOCK だけ DS の待機と逆。同 156 行は検知で使い分ける案だが、MCP が Hi-Z の間は使い分けられない）。P-12 支持
- 推し（部品）: CLOCK を 3V3 へプルアップ、LATCH と DATA を GND へプルダウン（10 kΩ 級）。LATCH を Low 待機にするのは、MCP の POR（OLAT＝0）と向きが同じで初期化のときに LATCH に端が出ないため。チップの近くに 3 本とも直列 R の置き場（例 1 kΩ、ピンの容量との τ は数十 ns 級で t5/t6 より 2 桁小さい〔推論、容量は仮定〕）。電源の無いチップへの電流とひげを抑える
- 推し（ファーム）: 規則②に「検知が無い間は 3 線を Low」（P-12）。検知と ±7 V の整定の後に CLOCK を High。LATCH は ACK の取れた 16 ビットの直後にだけ上げ、途中で誤れば上げずに語の頭から。書き手は 1 つ（OLATB の影を持つ）。語の前に IOCON・IODIR を読み返す
- バッファ（P-12）: 既定は 0 Ω の素通し（§1-6 の 2）。載せるなら電源は `+5V_D`（主電源スイッチの後ろ）。USB だけのときはバッファに電源が無く MCP とプルが入力を駆動するので、入力が VCC＝0 で受けられる品（Ioff か過電圧に耐える入力）を選ぶ。AHCT の DS はリポジトリに無い〔確かめられず〕。RS6 の保護で ±7 V だけ無い間は 5 V の High が電源の無いチップへ入る（形式の逸脱。上の読みでは電流の経路なし）→ 直列 R で受ける
- 取らない方がよい案: C-05 の任意の「UI の MCP の RESET を制御 MCP と同じ AND へ」。UI の MCP を戻すたびに制御 MCP も戻って `CH_EN`＝0 になり、聴取中の ch の電源が音声リレーを閉じたまま切れる（§2-10 が避けたい過渡）〔推論〕。USB だけのときも Hi-Z＋プルアップで CLOCK は High のままで P-12 にも効かない。RESET は 3V3 直結のまま、プルと読み返しで受ける
- ユーザー判断: 不要（部品の置き場とファームの規則）

## 6. 状態の追跡 — C-03・C-09・Cursor 1.4・1.10

### C-03（支持、条件つき）
- 言い直し: ±15 V だけが落ちて戻ると NJW1194 は黙って初期値（MUTE）へ戻るのに、規則①は走らない
- 根拠: 上の表の 3 行目。ファームに見えるのは選んだ娘の `MON` だけで、切替の窓（どの娘もつながっていない間）の崩れは見えない。電源 SET の突入 0.68 A（§2-4）が OLP を撃つかも OLP の形しだい〔推論〕
- 元の指摘との差: 「ファームは知らない」は半分。娘がつながっていれば異常は `MON` に見え、足りないのは「そのときトーンも状態不明にする」規則だけ。C-13 の「止まって電源を入れ直す」を取るなら規則①で書き直されて自然に戻る。再試行（§6-2 の未決（推奨））を許すなら要る
- 直し方の評価: ファームの規則で直る。「レールの異常の後と毎回の切替で、音量を戻す前にセレクタ・Treble（TSW）・Bass を書き、音量は MUTE から段階で、整定待ち（§1-6 の 7）も頭から」。任意のハード（±7 V の有無を UI の MCP の空きの入力へ、抵抗 2 本、GPx0〜6）は切替の窓の崩れも拾い、P-12 の「電源の無いチップに CLOCK High」も避けられる
- ユーザー判断: 小（任意のハード 1 本）

### C-09（支持）
- 言い直し: 規則①に制御 MCP の初期化が無いので、USB を先に挿した起動と PD の瞬断の後、全リセットが届かず規則③が「リレーが戻らない」で誤って止まる
- 根拠: 上の表の 2 行目。§2-16 の基本の形は「起動は OLAT＝0 を書いてから IODIR を出力に」で、きっかけが「起動」だけ。RESET 中の I²C の応答は DS に無い〔確かめられず〕が、応答しても RESET を放せば POR の状態〔Rev D p5・p17〕
- 元の指摘との差: 無い。止まる向きで音は出ないが、USB で分析しながら使うふつうの形で毎回起きうる〔推論〕
- 直し方の評価: 規則①を「制御 MCP の RESET を放す → OLAT＝0 → IODIR（bit7＝0、§2）→ 読み返し → 全リセット → 規則③ → トーンの初期化」と書き、§2-16 の「起動は」を「検知が立つたびに」へ。文書とファームだけ
- ユーザー判断: 不要

### Cursor 1.4（棄却、条件つき）
- 言い直し: 電源投入の直後、規則①の全リセットまでの間に、前回のラッチのまま前の ch がバスに乗る
- 根拠: 上の表の 1 行目。バスにつながるのは前の娘の節（TMUX は全 OFF）で ch ではない。石の EN は `RAIL_OK`＝0 と `CH_EN`＝0 の二重で切れ、どちらもファームに依らないハードの既定。NJW1194 も MUTE で立つので `TONE` に音楽は無い。源が鳴ったまま投入して初期値が乱れても〔DS p11〕、入力と出力の TMUX の 2 段が OFF
- 条件: TMUX の SELx もデコーダの出力（`CH_EN` で全 OFF、できれば `RAIL_OK` も AND）から取ること。§2-9 はデコーダを EN の FET について書くだけで、TMUX の選択線の出どころは DECISIONS に無い。ここが `CH_SEL` 直のデコードなら、`CH_SEL`＝00（プルダウン）で ch 1 の TMUX が ON になり、電源の無い石の入出力がバスにつながる（V21-継-14・-15 の形）
- 直し方: 1.4 の案（RS6 より先に ARST）は要らないし、Pico の起動（0.3〜1 s〔仮定〕）では RS6 の起動 2 ms〔[pow]〕に先回りできない。§2-9 に TMUX の選択線の出どころを 1 行足す
- ユーザー判断: 不要

### Cursor 1.10（支持、影響は小さい）
- 言い直し: §6-2 の手順に `CH_EN`＝0 が無く、電源 SET の後に前の `CH_EN` のまま ch の LDO が先に立ちうる
- 根拠: 上の表の 4 行目。§6-2 の「EN を上げる条件（電源 SET の後に両レールを `MON` で確かめてから）」と食い違う。影響: 音声リレーは開いていてバスには出ない。新しい娘の前の番号の石が一瞬通電する（熱の前歴、V21-実測-09）。そこが空のソケットなら出力の容量が帰還の分圧だけで抜け（§3-7 の 4、1〜10 s）、次の PRST が早いと OUT＞IN の窓に入る〔推論〕
- 直し方の評価: ファームの規則で直る。「ARST の後（PRST の前）に `CH_EN`＝0、PSET の間も 0、`CH_SEL` は `CH_EN`＝0 の間に目標へ、`MON` を確かめ `RAIL_OK`＝1 の後で `CH_EN`＝1」。C-10 の S3・S8 と同じ形。`RAIL_OK` を切替の頭で落とすかは C-10 (a)（全娘の単安定が同時に撃つ）と一緒に決める
- ユーザー判断: 不要

## 9. A-04 — `AMP_SEL OUT` と LINE の外の負荷

- 言い直し: `AMP_SEL OUT` の外の機器と LINE の能動スピーカが聴く節に直に載る。電源の切れた機器は入力保護で波形を削り、線形の負荷でも出力結合の低域の極が上がる
- 図: `AMP_SEL_L` の負荷は 100 kΩ で `A_GND`、タップのバッファ（OPA1656 のフォロア）、DEST（DPDT）の共通、`AMP_SEL OUT` の端子、計測側の予備の 2P 端子（§4-12 で外す）〔SF nets AMP_SEL_L、pin R1659・U1611・SW501・J_RAIL501・J1601〕。DEST は HP か LINE のポット（A50k）のどちらか 1 本を選ぶ〔SF nets PHONE_PRE_L・LINE_PRE_L〕
- 計算（再現）: ふつうは 100 k ∥ 220 k ∥ 50 k＝28.9 kΩ、2.2 µF の極 2.5 Hz（20 Hz −0.07 dB）。LINE 上げ切り＋10 kΩ（または HP＋`AMP_SEL OUT` 10 kΩ）で 7.4 kΩ・9.7 Hz・20 Hz −0.9 dB、両方で 4.3 kΩ・17 Hz・−2.4 dB。後者では 2.2 µF の ±5 % が 20 Hz で 0.36 dB の ch の差。GND 落としの R を 1 kΩ にすると、外の 10 kΩ の抜き挿しで聴く音量が −0.17 → −0.99 dB。電源の切れた機器（入力 10 kΩ の先で ±0.6 V のクランプ〔仮定〕）では源 49 Ω で 29 mV（6.5 Vpk の −47 dB）
- 判定: 支持。線形の負荷は図と計算で確か。電源の切れた機器は外の入力の形（結合 C・直列 R・保護の向き）しだいで〔仮定〕、結合 C があれば山を削り、無ければ ±0.6 V の不感帯の負荷で、どちらも −50 dB 前後の桁
- 補足: LINE の能動スピーカ 10 kΩ・上げ切りの 20 Hz −0.9 dB は `AMP_SEL OUT` と関係なく今の形（V21-継-03）にある
- 直し方の評価: (1) 運用の約束（つなぐ機器は電源を入れる、使わないときは外す、10 kΩ 未満はつながない）は 0 円で効く。(2) GND 落としの R を実装するなら、端子に専用のフォロア（タップのバッファと同じ考え、V21-継-07）を R の後ろに置けば §4-14 の「ミュートの内側」と両立する。(3) V21-継-10 に「ポット 1 本の負荷のとき」と注記
- ユーザー判断: **要**（運用で受けるか、フォロアを置くか。§4-14 はユーザーの決定）
